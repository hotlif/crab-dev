# FlowDiagram 流程图

基于 `rc-canvas` 的流程图组件，使用 ELK.js 计算布局，并提供正交连线路由。
调用方传入节点和边数据，通过子渲染函数使用布局结果，自定义节点与连线的内容。

[打开组件工作台](/components/rc-flow-diagram/workbench/)

## 何时使用

- 展示有向流程图或架构图，并自动计算节点位置。
- 使用正交折线连接节点，或手动指定部分连线路径。
- 拖拽节点、缩放和平移画布，或通过 `fitView` 将内容适配到视口。

## 主要功能

- **ELK 自动布局**：内置 Web Worker + ELK.js，支持 `layered`（层次）、`mrtree`（树形）、`stress`（力导向）等算法。
- **正交边路由**：基于 A\* 的障碍物避让，自动分配端口、生成折线，支持虚线与箭头方向。
- **Render Prop 模式**：`<FlowDiagram>` 提供 `children({ nodeRects, routes, zoom, loading, controls })`，节点 / 边的渲染完全由消费方控制。
- **画布封装**：内部使用 `@crab-dev/rc-canvas`，常规接入无需直接操作 WebGL。
- **节点拖拽**：`FlowNode` 的 `draggable` + `onDrag(dx, dy)` 支持拖拽覆盖布局位置。
- **手动走线**：通过 `manualRoutes` 对单条边指定端口与途经点，其余边仍自动路由。
- **无限网格 + 视口控制**：内置 `InfiniteGrid` 背景网格，支持 `useFlowDiagramControls()` 程序化缩放 / 平移 / fitView。

默认节点、文字、连线和网格使用 L3 语义令牌，随主题变化。`palette` 的部分覆盖只替换指定角色；如需保留旧版固定蓝色配色，可以显式传入导出的 `DEFAULT_FLOW_DIAGRAM_PALETTE`。

## 窄屏查看

**现有示例：** 节点和连线保留二维布局，外层提供有名称、可聚焦的局部横向滚动区域。视口变窄时，可查看完整画布，不把整个文档页面撑宽。

**设计要求：** 局部滚动与图内平移是不同操作。滚动区域获得焦点后可用方向键查看；图内拖拽、缩放和节点编辑仍需各自的键盘替代及状态反馈，不能仅凭外层可聚焦就认定流程图满足全部无障碍要求。

## 设计风格与主题

FlowDiagram 组合 Canvas、视口、网格、节点与连线，按 Crab 的流程图扩展维护。Material Design 3 Expressive、Apple 和 shadcn/ui 的来源及固定基线见[三套设计体系](/guides/design-styles)；三体系为其承载表面、前景、边界和选中角色提供独立契约，不定义 ELK 布局或本库的编辑协议。

默认节点填充与标签使用品牌色及其配对前景，描边、连线和网格使用各自的语义角色，通过 FlowDiagram L3 色板传给绘制层。显式节点、标签和连线颜色仍表示业务覆盖；只替换节点填充时，需要同时核对标签前景。默认色板示例与显式业务配色示例应分别查看。

节点尺寸、字体大小、圆角、箭头、路由、拖动、平移和缩放属于领域参数，不由全局控件尺寸统一改写。`loading` / `error` 由渲染上下文提供，调用方应为当前场景呈现状态；局部滚动区可聚焦也不等于图元选择、拖拽和编辑已有完整键盘替代。

色板、布局与领域交互按三体系及浅深色分别验收，覆盖等级以[覆盖矩阵](/guides/design-coverage)及对应候选记录为准。


## 桌面三体系矩阵规格

核对日期：2026-10-29。流程图没有一一对应的 M3 Expressive、Apple 或 shadcn 原生组件；ELK、正交路由、手动端口、拖动及 world 坐标由本库领域协议定义。官方来源以[三套设计体系](/guides/design-styles)的固定基线为准；[Apple Charts](https://developer.apple.com/design/human-interface-guidelines/charts)提供图形和文字共同传递含义的原则，shadcn 的固定 New York V4 仅作为中性表面、边界和焦点的参考，不宣称其有等价流程图引擎。

| 项目 | 视觉合同 | 领域边界 |
| --- | --- | --- |
| 三体系与明暗 | 默认节点填充和前景成对，网格、节点描边和边各有 L3 角色 | 业务覆盖显式通过 palette 或节点/边 props 传入 |
| 尺寸与密度 | 外部容器及键盘入口使用语义间距与焦点 | 节点宽高、字阶、圆角、端口、箭头和路由保持 world 几何，不随控件 size/density 缩放 |
| 状态 | 真实选择、拖动、空图、手动路由、ELK 失败、键盘移动分别核对 | 选择与编辑权限由 render-prop 宿主拥有，组件没有伪造的 disabled/expanded 状态 |
| 动效 | 流动虚线使用实际 Canvas 帧，减少动画保持静态连线 | 不冻结相位建立像素基准；保留时间序列与视频并实际查看 |

“流程工作区状态矩阵”在同一真实 ELK/Canvas 树上通过公开 props 保存节点位置。图形旁的键盘节点入口用于选择与方向键移动，和图内指针拖动更新同一位置状态；这些是示例宿主提供的等价操作，不表示 FlowNode 已自动生成 DOM 无障碍树。配置切换保留同一个画布、选择与位置覆盖。长内容、320/768/桌面局部滚动、RTL、品牌、强制颜色、减少动画与触控命中区域独立验收。

ELK 的 loading 是真实异步计算窗口；失败使用无效算法触发真实错误，同时保留既有布局，不能延长计时或注入加载样式制造证据。核心轴与 FF/WebKit 子集维护在 docs/visual.json；不适用项须保留理由，实际候选和复审完成前覆盖状态仍为 partial。

实际画面准备还独立核对 Canvas 的真实 DPR、drawing buffer 与原生帧，并在初始视图读取已提交节点内部、匹配实际公共色板的标签像素。ELK ready、节点数和非零 DOM 边界分别只能证明各自前提。手动路由检查真实路径经过声明的 waypoint；选择、拖动和配置切换保留同一数据模型。

视图工具栏直接使用 render-prop 的 `fitView`、`zoomIn`、`zoomOut`、`exportPNG`。原生领域场景执行背景指针平移，确认模型/路由和倍率不被平移修改；实际导出的 PNG 在页面显示、校验原生解码尺寸并附入框架报告。这里的 domain zoom 与浏览器真实 200% 是两个分别记录的能力，不能互相替代。
