# Button 按钮

## 何时使用

用于保存、提交、取消等操作。一个操作区域应突出一个主要操作，其余按钮按重要程度选择外观。

`appearance` 提供六种外观：

| 值 | 用途 |
| --- | --- |
| `primary` | 强调主要操作 |
| `subtle`（默认） | 浅阴影表面的常规或次要操作，如取消、返回、刷新 |
| `dashed` | 添加等辅助操作 |
| `text` | 低强调度的文字操作 |
| `link` | 链接样式的操作 |
| `danger` | 删除、清空等危险操作 |

传入 `href` 才会渲染为链接元素；`appearance="link"` 只设置外观。

未设置 `appearance` 与显式设置 `appearance="subtle"` 是同一层级。常规按钮使用中性表面、正文色与浅阴影；悬停时文字和淡底色显现品牌色，阴影略微增强；按压时底色加深、阴影收回。保留紧凑尺寸、6px 圆角和间距，用克制的表面层次区分操作，主按钮继续使用醒目的实色填充。

## 无障碍

- 优先使用清晰的可见文字；只有图标的按钮必须传入描述操作目的的 `aria-label`。
- 普通按钮传入 `isSelected` 时会同步默认 `aria-pressed`；未传入时仍是普通动作。显式 `aria-pressed` 优先，适合混合状态等情形。链接和显式 tab 等其他角色应使用对应的 current / selected 语义。
- 异步操作使用 `loading` 提供 `aria-busy` 与防重复提交反馈；不要仅用颜色表示危险或选中状态。
- 保持原生按钮的键盘行为和可见焦点，不要用普通元素模拟按钮。

更多通用要求见[无障碍使用指南](/guides/accessibility)。

## 视觉状态与验证

常规按钮的默认底色来自抬升表面色，文字来自主文字色。悬停、按压分别加入 4%、8% 品牌色底色；交互文字使用 85% 品牌色与 15% 主文字色，保证明暗下的可读性。默认只使用一层短距离底部投影，不叠加内侧环线；暗黑主题主要通过抬升表面的明度区分按钮。OKLCh 混色保留品牌色相，由 L3 消费 L2 变量。设置 `brandColor` 后，常态保持中性，交互反馈、焦点及选中同步换色。

三态保留透明的 1px 边框占位和稳定尺寸，可见边界由浅阴影表达；原有边框变量仍可覆盖。悬停时投影略微增强，按压时收回，不缩放、不移动文字，使用 `motion.interaction` 过渡。禁用使用中性底色、主文字色与禁用透明度，移除阴影且不响应悬停和按压；加载保留正常配色、默认阴影与 spinner；`isSelected` 使用无阴影的强品牌填充。键盘焦点环独立显示；强制颜色模式移除阴影并使用系统轮廓，减少动态效果时关闭过渡。

加载时保留可读的背景与前景，默认 opacity 为 1；已有 `--button-opacity-loading` 覆盖继续有效。点击和捕获处理函数在 loading 时阻止激活及表单提交；仅使用 loading 时按钮保留焦点，同时设置 disabled 则遵循原生禁用行为并退出键盘顺序。业务仍需用 pending 状态管理整个请求周期，Promise 点击锁不能代替提交状态。禁用链接不应用悬停或按压外观，虚线和普通按钮保留边框占位以避免宽度跳动。

粗指针环境下，独立操作的命中区至少为 44×44 CSS px。按钮通过最小尺寸扩展操作区域。长标签采用正文行高；紧密组合需检查目标区域没有相互重叠。此规则不新增 density 属性，也不把全部组件改成同一视觉高度。

键盘焦点使用公共 L2 焦点角色，通过 L3 覆盖可调整；减少动态效果时移除非必要过渡。实际浏览器应逐项检查 Tab / Shift+Tab、原生激活方式、两种主题、强制颜色、长标签与粗指针布局。当前源码修复与自动检查状态见质量审查记录，不能把 CSS 中存在媒体查询等同于设备验收通过。

规则依据：[状态系统](/design/interaction)、[无障碍与键盘](/design/accessibility)、[布局与密度](/design/layout)。
