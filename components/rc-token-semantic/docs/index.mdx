# Semantic Tokens 语义令牌

语义设计令牌（L2）将全局基础值映射为品牌色、表面色、文字色、间距、焦点环和动效等界面语义。组件令牌优先引用这一层，主题通过覆盖语义变量改变外观。

[打开组件工作台](/components/rc-token-semantic/workbench/)

## 角色与默认主题

业务样式消费角色，例如 `token.color.text.primary`、`token.color.brand.primary` 与 `token.color.selection.background`。默认 MD3 Expressive 将 L1 的 Purple 40 / 80 配对为浅色 / 深色品牌；shadcn/ui 使用零色度 Neutral 黑白灰，Apple 使用蓝色强调与分层灰色表面。三套设计体系使用相同的 L2 角色，独立定义颜色、排版、动效与组件规格。`TokenVars` 与 `vars` 均导出 `token.toml` 生成的正式变量映射。

| 意图 | 背景或主色 | 配套前景 | 使用边界 |
| --- | --- | --- | --- |
| 主要操作 | color.brand.primary | color.text.on-brand | 同时检查 hover / active 背景 |
| 当前选择 | color.selection.background | color.selection.foreground | 同时提供选择标记或 ARIA |
| 阅读容器 | color.background.surface | color.text.primary / secondary | 必要边界用 border.default，装饰分隔用 border.subtle |
| 反馈 | color.feedback 中对应意图的 background / solid | text / on-solid | 不混用容器文字和实心按钮前景 |
| 键盘位置 | color.focus.ring | 与所在表面比较 | 焦点独立于选中和错误 |

```tsx
import { css } from "@crab-dev/css";
import token from "@crab-dev/rc-token-semantic";

const panel = css`
    background: ${token.color.background.surface};
    color: ${token.color.text.primary};
    padding: ${token.space["card-padding"]};
`;
```

## 同一份配对数据与 CSS 主题

`designSystemRegistry` 集中维护 `md3` / `apple` / `shadcn` 的展示名与来源，`defaultDesignSystem` 为 `md3`，`DesignSystem` 从注册表推导。`designColorContract` 按相同 ID 索引 `md3ColorContract`、`appleColorContract` 与 `shadcnColorContract`，每套含完整的 `light`、`dark` 配对。成员是 CSS 引用字符串，读取它们不会注入样式。

```ts
import { designColorContract } from "@crab-dev/rc-token-semantic";
import type { ThemeColors, DesignSystem } from "@crab-dev/rc-token-semantic";

const design: DesignSystem = "shadcn";
const light: ThemeColors = designColorContract[design].light;
const brand = light.brand.primary; // L1 Neutral 900 的 CSS 引用
const onBrand = light.text.onBrand;
```

运行时加载 `@crab-dev/rc-theme/css/index.css`，通过 `data-crab-design` 与解析为明暗的 `data-theme` 选择映射。React 应用通过 `ConfigProvider designSystem="apple" colorMode="light"` 配置。TOML 保持无主题样式时的 MD3 Expressive Light 回退值；业务组件只消费默认 `token`，不按设计体系或颜色模式分支。

## 覆盖、迁移与验收

### 使用正式变量

每个令牌只有一个正式 CSS 变量入口。组件默认值通过 `$ref()` 引用 L2；历史名称不再进入回退链，例如 `--switch-transition` 应迁移为 `--switch-root-transition`。代码中优先通过组件的 `TokenVars['root.transition']` 获取名称。

旧反馈总色变量（例如 `--token-semantic-color-feedback-error`）已移除。请按用途分别覆盖 `color.feedback.error.text`、`icon`、`border` 和 `solid` 对应的变量，并保留背景与前景配对。旧 `vars` 键也应更新为正式路径，例如 `size.large.border.radius` 改为 `size.large.border-radius`。

### 从一个颜色生成配对

`createBrandTheme('#1677ff')` 返回 `{ seed, light, dark }`，其中 seed 为标准化六位颜色，light / dark 为品牌相关的 L2 变量映射。颜色统一输出为经过 sRGB 色域收敛的 OKLCh，并检查主色上的文字可读性；secondary / tertiary 与品牌种子联动；中性表面和业务反馈保持独立。

输入仅支持不透明 `#RGB` / `#RRGGBB`，非法值抛出 RangeError。`normalizeBrandColor(value)` 可独立校验并标准化输入。该函数本身不访问 DOM，也不会插入样式；React 应用通常直接使用 [ConfigProvider 的 brandColor](/components/rc-config-provider)，由 Provider 管理继承和作用域。

### 统一视觉尺度

- small 控件横向内边距为 `space.control-padding-x-small`（8px），medium / large 为 `space.control-padding-x`（12px）。
- 通用尺寸为 small / medium / large；输入、选择控件、开关、分段按钮和页签使用各自规格，不能用通用高度推断所有组件。MD3 带标签输入为 56px，复选框和单选框交互区为 48px；触控目标保持独立。
- 密度档位为 compact / standard / comfortable，对应 `density.<档位>.navigation / item / gap / padding / cell-padding`。当前生效角色为 `density.navigation / item / gap / padding / cell-padding`，默认引用 standard。密度不改写 `sizing.small / medium / large`，也不缩放字体。
- 数据行与表头使用 `density.<档位>.row / header`。公开的 `densityGeometry` 从同一份 TOML 的 row / header / navigation / item 引用生成数值，供虚拟滚动测量使用；修改密度定义后必须运行 `generate:token`，不得手改生成的 `density-geometry.ts`。
- MD3 Expressive 保留 4px 控件圆角、胶囊按钮、28px 弹层圆角和默认层级卡片；shadcn 使用 8px 控件圆角、方形按钮、12px 弹层圆角和默认描边卡片。风格切换统一覆盖共享形状角色。
- Apple 通过共享形状与阴影角色提供 6px 控件和按钮圆角、12px 卡片与 16px 弹层圆角，输入采用外置标签和外圈蓝色焦点；这些是桌面风格扩展，不改变组件的无障碍语义与键盘操作。
- 卡片和内容分隔使用 `color.border.subtle`；可输入控件保留 `color.border.default` 的辨识度。
- 即时颜色、边框和阴影反馈使用 `motion.interaction`；大范围展开使用独立的 `motion.expand`。

### 排版与字体

`typography.display / headline / title / body / label` 各有 large、medium、small，另提供相应 emphasized 角色。MD3 Expressive 使用 Roboto 的标准与强调字阶；Apple 使用系统字体和独立桌面字阶；shadcn/ui 使用 Inter 优先的 Web 字阶。三套体系同时重置字体、字号、行高和字重，避免嵌套边界继承另一体系。字体加载由应用负责。

动效区分 effects 与 spatial 的 fast / default / slow，以及交互、淡入、展开、面板与布局角色。MD3 使用 Expressive 的 Web 时长与 easing 近似，带边界的 sheet 保留无过冲过渡；Apple 与 shadcn/ui 使用各自的时长和 easing。减少动态效果由组件保留最终状态并移除非必要运动，不能只取消某个主题的动画。

### 组件类别角色

`selection`、`toggle` 与 `range` 控制选择类形状和状态；`field` 与 `picker` 控制标签、输入反馈和选择面板；`navigation` 控制分段轨道、页签和选中项；`overlay`、`feedback` 与 `status` 控制表面、消息与加载形态；`data` 控制表格、图表与分隔柄。L3 引用这些 L2 角色，三套风格在公共主题中成组覆盖，组件不按风格分支。实际对照见[三套风格](/guides/design-styles)。

### 验收范围

公共默认风格仍为 Material Design 3：品牌采用 Material Purple，表面采用 Material Neutral / Neutral Variant。shadcn 风格独立采用零色度 Neutral：浅色白底、深色近黑底，品牌操作、选中容器、文字、边框和焦点均为黑白灰。Apple 风格使用蓝色操作与选中角色，浅色银灰和深色灰阶分别定义表面层级。三套风格共用 lowest、low、container、high、highest、dim 和 bright 等角色，保留错误、成功、警告与信息的语义反馈色；自定义品牌不会改变基础表面。

L2 颜色变量名保持稳定；公开设计体系接口统一为新 ID 与新导出，不保留旧类型或主题导出别名。切换体系应复测已有业务覆盖：主色前景、悬停、按压、链接、选中与焦点必须成组评审。细描边不能成为控件唯一的可访问性标记；焦点与选择状态仍使用独立角色。Apple 属于 HIG 灵感的自主 Web 设计，不代表苹果原生控件。

- L1 修改会影响所有上层引用；业务品牌定制优先覆盖 L2。
- L3 覆盖继续优先于 L2；应检查旧组件覆盖是否遮住新的公共默认。
- Portal 不会继承另一个 DOM 分支的局部变量。浮层根需置于相同主题边界或显式同步 data-theme 与业务覆盖。
- 在 Light、Dark、按压背景、选中底色和反馈容器上检查最终前景；数值测试不能替代键盘与真实浏览器验收。

原始值见[全局令牌](/components/rc-token-global)，主题入口见[Theme](/components/rc-theme)，设计规则见[色彩与主题](https://material-web.dev/theming/color/)与[令牌与实施](/components/rc-token-semantic)。

## 语义配对验收

包内角色样张实际消费品牌、反馈、表面、前景、边界与焦点令牌；三体系来源与参考提交沿用[设计体系](/guides/design-styles)。样张不复制色值表，也不将 L1 原始尺度当作通用组件高度。L2 没有独立的组件尺寸或密度状态，数字几何与 CSS 映射由相同契约派生，具体消费者另做尺寸、密度、禁用和选中矩阵。

`docs/visual.json` 声明角色样张、三体系明暗及键盘焦点，环境前提和截图策略复用原生 Playwright 夹具。自动检查、候选截图、人工复审及基准比较分别保留结果。
