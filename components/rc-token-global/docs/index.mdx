# TokenGlobal 全局令牌

全局令牌是 Crab 的基础材料库。它记录颜色、距离、字体与时间等原始值，让设计与代码共享同一把标尺。**先理解角色，再选择尺度，最后通过语义层应用到界面。**

`L1 原始基元 → L2 设计角色 → L3 组件部位 → 业务界面`

例如：`space.5（20px）→ space.card-padding → 卡片内边距`。数值说明“多大”，角色说明“为什么用在这里”。

## 定位与使用边界

本页展示公共基元的**当前原始值**。先确定用途，再对照尺度；参数与源码同步，具体组件默认规格请查看对应组件文档。

| 你的任务 | 使用哪一层 | 具体决定 |
| --- | --- | --- |
| 维护基础色阶、字体或尺度 | L1 全局令牌 | 修改原始定义前评估所有引用方；为变化安排迁移 |
| 定义正文、卡片留白、焦点或反馈角色 | L2 语义令牌 | 从 L1 选值，用用途命名，检查主题下的组合 |
| 实现按钮、输入框、浮层 | L3 组件令牌 | 优先引用 L2，表达控件部位和状态 |
| 编写项目台账等业务页面 | 语义令牌与现有组件 | 使用角色和组件属性，避免在每个页面分别选色阶 |
| 展示设计基元、制作尺度比较 | 可直接引用 L1 | 本页样本属于此场景；框架与说明文字仍使用 L2 |

**现有实现**：公共色板包含 Zinc、Blue、Red、Green、Amber、Purple 以及黑白。Purple 新增七档现有站点品牌基元；原有 137 项键值保持不变。公共 L2 将 Purple 映射为默认品牌、焦点和选中角色，站点与公共主题共享这些映射。L1 本身仍不承担“品牌”或“错误”等语义。

**设计要求**：基元名称不携带业务语义。`red.600` 是颜色，不能替代“删除”“失败”等可感知名称；状态必须结合文字、图标与行为表达。色阶的用途建议不构成已经通过对比度验证的前景背景组合。

## 基础示例

需要了解 TypeScript 导入与 CSS 声明；不需要为令牌建立 React 状态。项目应已接入 Crab CSS 的构建处理。下面两步分别观察返回值与静态样式，完整代码可在示例中展开。

{/* token-tutorial */}

### 三种写法分别是什么

```tsx
import globalToken, { vars } from "@crab-dev/rc-token-global";

globalToken.blue[600];
// var(--token-global-blue-600, oklch(0.546 0.245 262))

vars["blue.600"];
// --token-global-blue-600

globalToken.space["0-5"];
// var(--token-global-space-0-5, 2px)
```

| 形式 | 返回内容 | 使用边界 |
| --- | --- | --- |
| 默认导出的 `globalToken` | 带回退值的 CSS `var(...)` 引用 | 插入 CSS 属性值；不是可直接算术运算的 JavaScript 数字 |
| 具名导出的 `vars` | 扁平键对应的 CSS 自定义属性名称 | 需要声明变量名或检查覆盖关系时使用；值不是颜色本身 |
| 本页“原始值” | TOML 中的基础字符串 | 用于核对，不建议复制字面量到业务样式中 |

CSS 变量未声明时使用回退值；存在覆盖时使用覆盖值。切换主题是否影响它，取决于对应变量及其作用域是否发生变化。不要把“返回 CSS 引用”解释为“会自动适配所有主题”。

数字键可用 `[600]`，带连字符的键必须使用括号，如 `space["0-5"]`、`globalToken["z-index"][10]`。`vars` 使用完整点分路径，如 `vars["font.size.md"]`。

本包入口不提供组件 Props，也没有公开的 `css/index.css` 子路径。不要套用普通 UI 组件的样式导入说明。后文的简短样式片段沿用此处的 `globalToken`，以及基础示例中的 `css` 和语义 `token` 导入。

## 颜色

颜色负责提供可重复引用的原料。Zinc、Blue、Red、Green、Amber 各有 11 档（50–950）；Purple 有七档（10、20、30、40、80、90、100），另有黑白，共 64 项。每组以连续色带展示。选择色阶后，在下方查看原始 OKLCh 值、公共引用和变量名；选中标记与文字位于色块之外。

### 如何读取与选择

`oklch(L C H)` 中，L 表示明度，C 表示彩度，H 表示色相角度。本页 L 用 0–1 数值，H 用角度数字；黑白的彩度为 0。五组 50–950 色阶数字越大越暗；**Purple 调阶数字越大越亮**，沿用其 [Material Web v0.192 来源](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-ref-palette.scss)的编号。不同家族不能按同一个数字互换，也不能访问不存在的 `purple[600]`。这七档只公开现有值，未插值补齐完整调阶。

| 场景 | 选用方法 | 需要确认 |
| --- | --- | --- |
| 页面、文字与边界 | 由 L2 中性角色映射 Zinc 或黑白 | 文字、边框在相邻表面上的可辨认性 |
| 信息、成功、警告、危险 | 检查现有 L2 反馈角色，不直接给业务对象绑定色阶 | 文字、图标、背景与状态叠加后的配对 |
| 浅色底上的强调标记 | 从合适色阶建立语义角色，再验证实际配对 | 不根据“600 常用于主色”推断一定达标 |
| 图表分类 | 在图表规范中定义稳定类别映射 | 多系列区分、图例、线型以及反馈色冲突 |
| 深色界面 | 使用深色语义映射，重新验收配对 | 不把所有 L 值机械取反，也不自动交换 50 与 950 |

{/* token-reference:colors */}

```tsx
import { css } from "@crab-dev/css";
import globalToken from "@crab-dev/rc-token-global";
import token from "@crab-dev/rc-token-semantic";

// 色板样本可以展示原色；业务文字使用语义角色。
const swatch = css`background: ${globalToken.blue[600]};`;
const label = css`color: ${token.color.text.primary};`;
```

**正例**：项目失败状态使用反馈角色，并显示“同步失败”和重试入口。**反例**：把整行文字设为 `red[400]`，仅用红色表示失败；应补齐状态名称，并按实际前景背景验证对比度。

色块存在不等于文字可用。透明、悬停、选中和禁用会改变最终组合；配对与验收方法统一见[色彩与主题](/design/color)，图表职责见[数据展示](/design/data-display)。

## 间距

间距表达归属、节奏和操作空间。`space` 以 4px 为主要节奏，包含 1px、2px、6px、10px、14px 等微调档。键名是刻度标识：`space.4` 为 16px，`space.px` 为 1px，不能把所有键当作像素值。

长度条按真实 CSS 像素显示，零值没有可见长度。页面缩放会同时放大标尺和界面；本图不代表设备物理尺寸。

| 关系 | 当前 L2 示例 | 原始来源 | 选择规则 |
| --- | --- | --- | --- |
| 图标与短标签等行内关联 | `space.inline-gap` | `space.1`，4px | 紧密关联；不得压缩可点击命中区 |
| 相邻控件 | `space.component-gap` | `space.2`，8px | 同一任务中的操作，窄屏可换行 |
| 垂直内容项 | `space.stack-gap` | `space.3`，12px | 保持同组节奏，错误文案加入后仍有归属 |
| 内容分段 | `space.section-gap` | `space.4`，16px | 区分段落或区块 |
| 卡片内部 | `space.card-padding` | `space.5`，20px | 四边留白表达容器范围 |
| 组间与页面内边距 | `space.group-gap` / `space.page-padding` | `space.6`，24px | 大关系应比组内更疏，不用空元素撑开 |

{/* token-reference:space */}

```tsx
const group = css`
    display: grid;
    gap: ${token.space["component-gap"]};
    padding: ${token.space["card-padding"]};
`;
```

**正例**：成员表单字段组内统一间隔，组标题与下一组使用更大间隔。**反例**：以连续空格或空白 div 排版；应改用 `gap` 与容器留白。

原始尺度不是密度 API；`space.8` 也不代表全库控件高度。36/28px 控件与 44/36px 数据行属于设计语言样板范围，见[布局与密度](/design/layout)。

## 圆角

圆角描述边缘形状，不单独表达层级。比较时保持样本宽高一致，避免把“大卡片看起来更方”误判成数值不同。`full` 为 9999px，实际曲线还受盒子尺寸限制。

| 当前 L2 名称 | 对应 L1 | 适用判断 |
| --- | --- | --- |
| `radius.sm` | `radius.1`，2px | 轻微修饰的小边缘 |
| `radius.md` | `radius.3`，6px | 常规控件候选尺度，仍核对组件 L3 |
| `radius.lg` | `radius.4`，8px | 容器形状参考 |
| `radius.xl` | `radius.6`，12px | 较大容器与浮层形状参考 |
| `radius.pill` | `radius.full`，9999px | 胶囊；圆形还要求等宽等高 |

{/* token-reference:radius */}

```tsx
const panel = css`border-radius: ${token.radius.lg};`;
```

**正例**：卡片使用一个连续外轮廓，内部列表用分隔表达关系。**反例**：每层嵌套容器都增加圆角、边框、阴影；应去掉没有职责的包围层。焦点与错误状态不得通过改变圆角或边框宽度引发布局跳动。

圆角不会自动裁切溢出的子元素。是否裁切需要结合内容、焦点环和阴影决定，不能为了圆角统一设置 `overflow: hidden`。详见[形状与层次](/design/shape)。

## 字体与排版

字体族、字号、字重与行高是独立基元。先选内容角色，再组合这些参数；不能把 `font.size.md` 的 16px 解读为全部业务界面的正文字号。当前 L2 的 `font.size.body` 引用 `font.size.sm`，即 14px。

每个样本仅改变该项属性，其他属性继承展示区。中文、英文与数字可能由不同回退字体绘制；样张用于发现组合差异，不保证所有设备字形完全一致。

### 字体、字号与字重

| 决策 | 规则 | 边界 |
| --- | --- | --- |
| 普通界面文字 | 优先使用 `font.family.body` 等语义角色 | L1 sans 声明 Inter 等回退，不负责下载字体 |
| 代码、令牌键、机器标识 | 使用 mono 基元或项目对应语义角色 | 当前 mono 列表包含 Geist Mono 等；未安装时继续回退 |
| 中文混排 | 检查系统回退后的字面大小、标点与基线 | 不能根据拉丁字体名称声称已包含中文 |
| 标题与标签 | 用层级与字重共同区分，避免所有内容加粗 | 缺少真实字重时浏览器可能合成；需在目标设备验收 |
| 数字列与金额 | 结合等宽数字特性和一致的单位、对齐规则 | mono 字体不是唯一方案；不得靠空格对齐金额 |

### 行高与组合

行高为无单位倍数，`normal` 在本库是明确的 **1.5**，不是 CSS 关键字 `normal`。当字号为 16px 时，1.5 的计算行高是 24px；这只是计算示例，不代表站点文章正文统一规格。

{/* token-reference:typography */}

```tsx
const paragraph = css`
    font-family: ${token.font.family.body};
    font-size: ${token.font.size.body};
    font-weight: ${token.font.weight.body};
    line-height: ${token.font["line-height"].body};
`;
```

**正例**：长项目名允许换行，编号可选择复制；摘要截断时保留全文入口。**反例**：为压缩表格把所有正文改为 xs 并设置一倍行高，导致中文多行难读；应先减少低价值列或采用适当密度。

`line.height.none` 适合需要精确盒模型的短内容试验，不应直接用于多行正文。检验中文标点、上下标、两行错误提示和 200% 缩放，避免固定高度裁切。正文与业务界面排版的完整规则见[字体与排版](/design/typography)。

## 阴影

阴影帮助辨认表面相对抬升，不能替代边框、遮罩或正确的层叠顺序。样本统一使用同一语义底板与表面；深色下某些黑色阴影较弱，这是原始值的真实表现，不为展示而擅自加强。

| 任务 | 选择依据 | 当前来源与边界 |
| --- | --- | --- |
| 普通信息分组 | 优先留白、分隔或边框 | 无需默认给每个区块加阴影 |
| 浮动表面 | 使用语义阴影并检查宿主背景 | `shadow.float` 引用 `shadow.md` |
| 更高层的覆盖表面 | 结合遮挡范围、焦点和关闭行为判断 | `shadow.overlay` 引用 `shadow.lg`，不等于所有 Dialog 的实际阴影 |
| 取消装饰阴影 | `shadow.none` | 去掉阴影后仍要能看清操作边界 |

{/* token-reference:shadow */}

```tsx
const floatingSurface = css`box-shadow: ${token.shadow.float};`;
```

每个阴影可能由多层逗号分隔的声明构成，应整体引用。选择样本可查看完整声明及引用代码。

**正例**：下拉浮层具有足够空间展示阴影，并保留与背景的边界。**反例**：通过增大阴影修复被上层元素挡住的菜单；应检查 portal、堆叠上下文和层级，而非加深投影。关联[浮层规范](/design/overlays)。

## 动效

时长回答“多久”，缓动回答“如何变化”。同一距离下比较时长，同一时长下比较缓动，才能看清区别。样本由用户主动播放，不循环；连续点击会从当前位置反向，减少动态效果时取消过渡。

| 当前语义动效 | 组合来源 | 用途与边界 |
| --- | --- | --- |
| `motion.interaction` | fast 与 normal 的平均值，加 easing.out | 150ms，用于即时状态反馈；不是 L1 `duration.normal` |
| `motion.fade` | duration.normal + easing.out | 200ms 的淡入淡出组合 |
| `motion.expand` | duration.slow + easing.out | 300ms 的展开组合；不能据此推断所有组件动画参数 |

{/* token-reference:motion */}

```tsx
const feedback = css`
    transition: background-color ${token.motion.interaction};
    @media (prefers-reduced-motion: reduce) {
        transition: none;
    }
`;
```

此例只演示过渡声明；需要变化的状态样式仍应拆为静态块。不要写 `transition: all`，避免尺寸、定位等非预期属性也被动画化。

**正例**：点击后立即反馈状态，动画只帮助理解变化。**反例**：等待动画结束才允许继续操作或才移动焦点；应把交互结果与装饰动画分离。删除内容、恢复焦点和退出卸载由组件行为控制，不能仅靠一个 duration 值完成。

缓动 in/out 表示速度变化趋势，不是进入、退出操作的自动绑定。加载反馈还需说明任务状态；本页动效参数不是接口超时时间。见[动效](/design/motion)与[状态系统](/design/interaction)。

## 透明度

透明度为 0–1 的无单位数值，键 `50` 对应 0.5。预览对整块样本及其文字应用 `opacity`，使用同一底板，以显示内容会一起变淡。0 表示完全透明，元素仍占据布局空间。

| 目标 | 应如何处理 | 误用后果 |
| --- | --- | --- |
| 整体降低控件强调 | 优先使用组件既有禁用状态与语义透明度 | 仅降低 opacity 并不会禁止点击或键盘操作 |
| 半透明背景而文字清晰 | 使用独立的背景颜色或语义填充角色 | 父容器 opacity 会连文字与子元素一起变淡 |
| 隐藏内容 | 依据可访问性和布局意图选择真正的显示策略 | opacity 为 0 的元素仍可能接收焦点与指针 |
| 多层叠加 | 在最终背景上检查实际组合 | 父子透明度叠加会进一步降低可见性 |

{/* token-reference:opacity */}

```tsx
// 这是原始透明度样本；业务禁用状态请交给组件。
const opacitySample = css`opacity: ${globalToken.opacity[50]};`;
```

**正例**：成员保存中由组件显示忙碌状态、限制重复提交，同时给出进度反馈。**反例**：将表单整体设为 0.3，却让提交按钮继续可用；应补齐真实行为限制，而不是把视觉减弱等同禁用。

只读与禁用也不能靠同一个透明度区分：只读内容通常仍需可读、可选和可复制。具体状态组合归[状态系统](/design/interaction)。

## 层级

层级基元是相对排序的数值工具。键 `10` 的原始值为 **1000**，不是 10；后续刻度也不应通过键名计算。本页把九档刻度放在同一层叠场景中，下面的列表提供完整键值。整个示意场景独立于页面层级，演示元素不会覆盖导航。

| 当前 L2 角色 | L1 键 | 数值 | 语义意图 |
| --- | --- | --- | --- |
| 无映射 | z-index.0 | 0 | 基础零值，不等于 CSS auto |
| base | z-index.1 | 1 | 普通内容层 |
| sticky | z-index.10 | 1000 | 页面内吸顶 |
| float | z-index.20 | 1100 | 浮动内容 |
| mask | z-index.30 | 1200 | 遮罩 |
| block | z-index.40 | 1300 | 阻塞性表面 |
| elevated | z-index.50 | 1400 | 更高提示层 |
| alert | z-index.60 | 1500 | 警报 |
| top | z-index.70 | 1600 | 语义兜底层 |

{/* token-reference:z-index */}

```tsx
const stickyToolbar = css`
    position: sticky;
    top: ${globalToken.space[0]};
    z-index: ${token["z-index"].sticky};
`;
```

数值只在相关堆叠上下文内比较。父容器的 `transform`、`opacity` 等可能创建新的上下文，子元素的巨大 z-index 不能突破父层；祖先裁切也不能靠加大 z-index 解决。相同层级还与绘制顺序相关，本图不模拟所有定位规则。

**正例**：先检查遮挡元素与浮层的挂载位置，再选语义层级。**反例**：遇到遮挡就写 999999，导致菜单盖住确认窗口；应修复上下文和挂载关系。

原生 top layer 与普通 z-index 是不同机制。当前语义源码特别说明 Dialog、Drawer、Message、Notification 使用原生顶层机制，不消费此刻度；本表不是这些组件的实现层级表。详见[浮层](/design/overlays)、[Dialog](/components/rc-dialog)与[Drawer](/components/rc-drawer)。

## 三层令牌与主题

### 从原始值到组件

下面摘录当前源码中真实存在的引用关系。每段分别属于相应包的 `token.toml`，不是将三个层级写在同一个文件。

```toml
# L1 · rc-token-global 的 [token] 内容
space.5 = "20px"

# L2 · rc-token-semantic 的 [token] 内容
space.card-padding = "$ref(space.5)"

# L3 · rc-card 的 [token] 内容
size.middle.padding = "$ref(space.card-padding)"
```

这条链路始终描述同一个值：L1 的 20px 被 L2 命名为卡片内边距，再被 L3 的中等尺寸 Card 引用。Card 源码把 `size.middle.padding` 连接到容器的 CSS padding，最终形成内容与卡片边缘之间的留白。其他尺寸可以选择不同映射。

L2 的构建 imports 指向全局令牌包，L3 指向语义令牌包，`$ref()` 因而能引用上层。修改 L1 的这档尺度会影响多个消费者；只想调整某个组件时，先检查其 L3 角色。

### 主题应该覆盖哪里

1. 为同一角色建立明暗映射，例如正文始终消费 `color.text.primary`。
2. 在主题边界覆盖 L2 变量，使内部组件继续消费同一个角色。
3. 检查浮层挂载后是否仍继承边界；不同挂载根不会凭空继承祖先变量。
4. 在真实表面上验证状态叠加、文本对比与只读、禁用表现。

修改 L1 会影响所有引用它的语义角色，适合受评审的基元变更；单个主题调整应优先发生在 L2。不得为了某页品牌色重写 `blue.600` 的含义，也不得在组件内分支复制两套颜色。

站点参考样本通过 L1 引用绘制。当前站点导入公共主题的 L2 覆盖，还额外覆盖了 L1 sans 字体以补充中文回退。为准确展示公共基元，每个样本仅将被展示的那一个 L1 变量局部设为 `initial`，让 `var()` 使用公共回退值；周围阅读表面仍继承站点主题。本目录展示源码原始值，不是应用覆盖后的运行时值检视器。

详见[语义令牌](/components/rc-token-semantic)、[Theme](/components/rc-theme)和[令牌与实施](/design/tokens)。

## 维护、误用与验收

### 维护附注

参数来自 `components/rc-token-global/token.toml`，访问方式经包入口与生成源码核对。当前 `shadow.md` 包含 0.1 透明度的黑色阴影；源码旧注释中的 0.03–0.08 概述不覆盖全部值，维护时以实际声明为准。

### 修改与生成

公共值的唯一来源是 `token.toml`，`src/token.ts` 由工具生成。修改原始值前先查找上层引用和最终组件消费者，记录主题与尺寸影响；不能只看本页色块是否好看。

```powershell
# 在 components/rc-token-global 中：修改公共定义后刷新令牌
yarn generate:token

# 在 .website 中：同步本页参考数据与页面
yarn generate:docs
yarn check:docs
yarn test:generator
yarn build
```

这些命令分别在注释所述工作目录执行。公共令牌变更还须按仓库约定完成受影响组件验证；文档生成通过不能代替组件验收。

| 常见问题 | 原因 | 修正 |
| --- | --- | --- |
| 把 CSS 引用与数字相加，得到意外字符串 | token 返回的是 CSS 表达式 | 使用静态 CSS `calc()` 或使用组件需要的独立数字参数 |
| 切换主题后样本色块没有反转 | L1 与 L2 的职责不同 | 检查角色是否消费了主题覆盖，不机械修改原始色阶 |
| 修改源码后页面仍显示旧值 | 未生成令牌或文档数据 | 按顺序生成、检查漂移并重建生产页面 |
| 在业务样式里直接写 purple[40] 当作按钮主色 | 原始色不随 L2 主题映射变化 | 使用 color.brand.primary 和 color.text.on-brand 配对 |
| 深色下阴影不明显 | 黑色投影与背景接近 | 在 L2 评审表面和边界配对，不篡改参考样本 |
| 复制按钮失败 | 浏览器未提供剪贴板写入能力或拒绝操作 | 保留就近失败说明，手动选择可见表达式复制 |

### 可观察的验收步骤

- 从任意分类选择一项，对照 TOML 的键、值、单位与生成变量名；代码可从公共入口访问。
- 比较全部颜色与尺度，确认没有遗漏项；零间距、透明度 0、none 阴影和 0ms 也必须保留。
- 在明暗主题下分别阅读样本标签和原始值，确认没有用样本颜色承载唯一文字说明。
- 用方向键切换色阶，确认每组只有当前项进入 Tab 顺序，详情区切换不推动后续内容。列表中的代码可展开与收起，复制后有就近结果提示；拒绝复制后仍能选择文本。
- 播放动效并中途反向，检查没有累积队列；减少动态效果下保持静态可理解。
- 在 320、768、1440px 检查全文与 200% 缩放，确认代码、长字体列表和阴影不会撑宽或被固定高度裁切。
- 对照相关组件实际类型与 L3 源码，确认没有把本页原始刻度写成组件统一默认值。

### 当前差异与后续工作

公共 Purple 基元与明暗品牌映射已经落入源码，所有组件的最终组合仍需逐批验收。统一密度角色以及设计语言中的部分业务参数仍处于候选或待迁移阶段。本页准确记录现有值，不以文档重写宣称这些能力已经实现。无障碍共性基线见[无障碍](/design/accessibility)，样板与公共契约差异见[令牌与实施](/design/tokens)。
