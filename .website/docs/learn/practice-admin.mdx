# 实战：后台管理页面

## 开始之前

先完成资料表单和数据列表实战，再学习 AppMainLayout、Menu、Tabs 与 Drawer。

## 跟着做

将后台布局、菜单、标签页、成员列表和编辑抽屉组合为一个可以操作的管理页面。

**建立后台框架**

把页面放进统一的后台布局。 公共页头、导航与内容边界先确定，业务页面就能专注自己的任务。 识别侧栏、页头、标签与正文区域。 工作区先显示概览卡片。

**连接导航与标签**

从菜单打开成员管理页。 菜单项与标签使用相同业务 key，重复打开时可以复用现有标签。 打开成员管理，再切回概览，重复点击成员菜单。 页面可以切换，同一个成员标签不会无限重复创建。

**组合列表和编辑**

在列表旁完成资料编辑并回写。 抽屉保留当前列表上下文，保存回调只更新目标成员。 打开林晓的编辑抽屉，改名后保存。 抽屉关闭，对应成员卡片显示新名字。

**适配窄屏**

让后台页面在手机宽度下仍能操作。 侧栏与内容要保留明确入口，卡片单列排列，编辑字段不能溢出容器。 缩窄浏览器窗口，从侧栏或概览页的打开成员管理按钮进入，再编辑并保存。 列表变为单列；导航与编辑仍可通过键盘和触控完成。

## 常见问题

### 列表为何使用 Card 而不是再写一份表格？

### 真实应用如何保持页面状态？

以业务主键区分标签，并按应用要求把数据状态提升到共享层或服务缓存。教程状态只在当前示例内存中保存，重置会恢复初值。
