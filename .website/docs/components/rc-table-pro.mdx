#### 基础与数据

##### 基础用法 — 通过 fetchData 与 fetchColumns 异步加载数据和列定义，TablePro 会自动适应容器宽高。

##### 可重放的数据状态 — 切换真实请求的加载、空结果、数据错误、列错误和成功状态。加载请求持续等待至切换场景时取消；请求计数来自传输函数的实际调用，可核对错误场景的重复重试，切换“显示数据”后恢复成功。

##### 自定义类型渲染 — 通过 typeLoaders 为不同 dataType 注入自定义渲染器，实现状态标签、金额格式化和日期格式化等效果。

##### 自动刷新 — autoRefreshInterval 指定轮询间隔（ms），侧边栏同时出现「立即刷新」按钮。此示例每 3 秒自动重新拉取一次数据，模拟实时监控场景。

#### 工作区能力

##### 全局关键字搜索 — showSearchBar=true 在表格顶部显示内置搜索栏，输入关键字后所有可见列匹配到的文字会高亮显示，并支持上一个 / 下一个导航。DataTypeLoader.getSearchText 可为枚举等类型自定义匹配文本。

##### 侧边栏（列 / 过滤器） — sideBar 在右侧展示工具栏：点击「列」图标可切换列的显隐、拖拽改变顺序、固定到左/右侧、开关排序；点击「过滤器」图标进入过滤条件面板。

##### 服务端分页 — 设置 pagination 属性后，fetchData 会接收 page 与 pageSize 参数，由服务端完成数据切片并返回 （ rows, total ），组件根据 total 渲染分页器。分页栏末尾始终显示刷新按钮；若设置 autoRefreshInterval，还会按指定间隔自动重拉当前页数据。

#### 导出与状态

##### CSV 导出 — 设置 exportFileName 后侧边栏出现导出按钮，点击后将当前可见列导出为 UTF-8 CSV 文件。DataTypeLoader.exportValue 可自定义每种数据类型的导出文本——例如将枚举值转换为中文标签，或对数值格式化。

##### 状态持久化 — initialState 在首次加载时恢复列顺序、显隐、宽度、固定等属性；onStateChange 在任何列属性或过滤条件变更时触发，可将快照写入 localStorage。刷新页面后所有调整会被还原。

## 使用说明

基于 `@crab-dev/rc-table` 的业务表格。将 `ProtocolColumnType` 列定义转换为 Table 使用的 `ColumnType`，并通过 `dataType` 配置对应的渲染器、筛选器和编辑器。


### 主要功能

- 通过 `fetchColumns` 和 `request` 异步加载列定义与数据，兼容旧 `fetchData`。
- 通过 `typeLoaders` 为不同 `dataType` 配置 `render`、`filterEditor` 和 `editRender`。
- 复用 AutoSizer 与 Table，提供自适应容器和虚拟滚动。
- 集成分页、查询、列管理与导出；数据请求和业务筛选逻辑由调用方实现。

### 何时使用

- 后端以列协议（metadata）下发列定义，需要前端根据协议渲染表格；
- 需要为多种数据类型（金额、日期、富文本、状态）提供可插拔渲染器；
- 需要将筛选/排序逻辑放到服务端，前端只负责展示与收集条件。

三个场景分别处理 960 笔订单、720 条库存组合和 840 张发票。订单场景的 `request` 只返回当前页，因此底部汇总和 CSV 只覆盖**当前页**；另外两个场景一次返回全部筛选结果，汇总和 CSV 覆盖**全部筛选结果**。内置搜索栏用于定位已加载的行，不能代替跨页服务端搜索。示例中的「生成」按钮只在页面内展示操作反馈，不会创建真实单据。

这三个示例共用的演示框架、筛选输入、状态标签和可取消模拟请求位于包内 `docs/demos/scenario-shared.tsx`；复制场景源码到自己的项目时，也要将这些辅助函数替换为项目组件和真实接口。

“可重放的数据状态”将请求保持在加载状态，或返回空结果、数据错误、列错误及成功数据。错误场景可重复使用内置重试按钮，仍会返回同一模拟错误；切换“显示数据”恢复成功。切换场景会取消未完成请求，适合观察各状态的内容和操作布局。

加载与请求错误优先于空态：请求未成功返回空结果时，不显示默认或自定义 `empty` 内容。已有行在刷新和刷新失败时保留，加载或错误反馈覆盖其上；成功返回零行后才显示 `empty`。重试期间同样遵守此顺序，不同时报告“加载中”和“暂无数据”。




推荐使用 `request({ page, pageSize, filters, sort, signal })`，返回 `{ rows, total }`。新查询和卸载会取消旧请求；将 signal 传给 fetch 可中止底层网络请求。过期结果与过期错误均不会覆盖当前状态。

从零开始接入时，先定义 `Row` 的 `dataRef` 形状，再让 `fetchColumns` 返回列协议（`name` 通常写成 `$.字段名`），最后实现 `request`。`filters` 的 key 是列名，value 是编辑器提交的字符串；服务端需自行解释条件并计算筛选后的 `total`。`sort` 包含列名与方向，服务端负责实际排序；`signal` 应传给网络请求。`rowSelection` 用受控 `selectedRowIds` 时，在 `onSelectedRowIdsChange(ids, { rows, reason })` 中保存新集合，并根据业务状态设置 `getDisabled`。仅在已加载数据范围内使用 `showSummary` 与导出；需要全库聚合或全库导出时应另接后端接口。

`sortMode` 默认为 client，仅对已加载数据排序。服务端分页配合 `sortMode="server"` 和 request 使用，组件通过 query.sort 传递排序条件，保留返回顺序，排序变化时回到第一页。旧 fetchData 仅支持 client 模式。

为类型加载器标注 `DataTypeLoader<MyRow>[]`，渲染、编辑、搜索、汇总和导出回调便可保留业务行类型。`TableProProps`、`ProtocolTableState`、`TableQuery` 等类型均从包入口导出。

`size` 只设置内置控件尺寸，`density` 独立控制 Table 行高与列面板 Tree 的默认几何；显式行高优先。分页配置的变化通知为 `onValueChange(page, { pageSize, reason })`，reason 为 `page` / `page-size` / `jump`；每页条数另通过 `onPageSizeChange(size, { page })` 通知。原有 `pagination.onChange(page, pageSize)` 已移除。内部请求仍采用既有的 `page/pageSize/filters/sort` 数据协议。

工具栏、搜索、列操作、筛选、错误与无障碍名称跟随 `ConfigProvider locale`。业务列标题、数据内容、自定义编辑器和服务端错误消息由调用方负责。

窄容器中，列面板覆盖表格并保留侧边工具栏；固定列阴影、表格焦点框和滚动条留在表格层内，不遮盖面板的搜索、勾选和重置操作。

排序、分组展开、树展开、详情展开与行编辑复用 Table 的 `TableStateProps` 约束；受控属性与对应初值或默认展开策略互斥。TablePro 先解析自己的排序状态，再以受控排序传给 Table，初始排序只由一层状态机制消费。



### 设计风格与主题

TablePro 在 Table 上组合查询、列配置和分页等能力。内部表格及列面板 Tree、工具栏字段、Checkbox、Button、DropdownContainer、Pagination 和 Spin 分别复用对应组件的视觉与交互契约；外围工作区使用工具栏、表面、表格边界、选中和错误等 L2 角色，不另造一套表格主题。

Material Design 3 Expressive、Apple 和 shadcn/ui 的来源与固定 New York V4 基线见[三套设计体系](/guides/design-styles)。表格增强、列协议和请求编排按本库的专业扩展规则维护；基础控件的来源不能替代排序、列操作、虚拟行、编辑、加载与错误状态的逐项验收。

`size` 设置内置控件尺寸，`density` 控制默认数据行和列面板节点几何，显式行高等配置优先。列定义、`request` 查询、持久化状态、业务编辑器和数据格式属于领域接口，切换设计体系不会重新解释它们。列加载错误、数据加载错误、空态和加载反馈应分别可识别。

三体系、浅深色及适用数据状态的覆盖等级以[覆盖矩阵](/guides/design-coverage)和对应候选记录为准。

### 适用场景

页面需要围绕一个数据源提供完整查询和管理工具。 多个项目要复用一致的分页、列配置、导出和刷新流程。

只展示本地小数据集时直接使用 Table；页面交互特殊到无法共享协议时先拆分需求。

### 使用要点

- loader 的输入、返回总数和取消/竞态行为必须明确。
- 搜索、分页和列状态使用单一来源，持久化只保存可恢复的用户偏好。
- 导出、自动刷新和侧栏都要展示独立的进行中、成功和失败结果。

### 无障碍

- 工具栏有名称和逻辑顺序，刷新后不重置用户焦点或朗读整个表格。
- 查询错误、空结果和导出状态提供文字反馈，列管理可完全使用键盘。
