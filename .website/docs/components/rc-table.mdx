## 使用说明

按行列展示结构化数据，支持排序、筛选、选择和编辑。


### 何时使用

- 比较多个记录在相同字段上的数据。
- 对结构化数据进行排序、筛选、行选择或编辑。
- 使用自定义单元格展示状态和操作入口。

需要同时管理数据请求、分页、列配置和导出时，可使用 TablePro。

### 无障碍

- 为每个 Table 提供描述数据用途的 `aria-label`，例如“本月订单”；不要只写“表格”。
- 列标题应是简短的纯文本；自定义单元格中的按钮、复选框和输入框必须分别拥有上下文名称。
- 排序、展开、选中和编辑状态不能只靠颜色表达，并应保留组件提供的键盘操作。
- 虚拟滚动场景仍需传入准确的数据总数；空、加载和错误状态要有可读文本和稳定焦点位置。

更多通用要求见[无障碍使用指南](/guides/accessibility)。


示例采用固定日期的虚构业务数据：采购订单 3,000 行、24 列；员工资料 2,000 行、22 列；库存台账 2,000 行、23 列；项目预算 1,200 行、23 列。编辑和审核操作保存在当前页面，刷新后恢复初始数据。

各表格根据容器宽度调整视口，横向滚动查看完整字段；大规模示例为 1,000 家门店、1,000 列，共 100 万单元格。

### 适用场景

需要比较多条记录在相同字段上的值。 用户要排序、筛选、选择、编辑或批量处理结构化数据。

内容主要是叙述或卡片媒体时使用 List/Card；字段很少且只读时简单语义表格可能更合适。

### 使用要点

- 每行提供稳定唯一 ID，列 key 和数据路径不能随渲染变化。
- 容器必须有明确宽高，虚拟化只渲染视口附近内容。
- 排序和筛选要明确由本地还是服务端负责，不能同时重复处理。

### 无障碍

- 表格提供描述用途的 aria-label，列标题简短可读，排序状态用 aria-sort。
- 单元格内控件拥有带行上下文的名称；键盘选择、编辑和滚动后保持可见焦点。
