## 使用说明

切换页码、调整每页条数，并展示数据总量。


### 何时使用

- 列表 / 表格 / 卡片墙需要按页加载大量数据
- 后端分页或前端切片分页，向用户暴露页码导航
- 需要在不同密度场景（表格内联 / 独立页面 / 抽屉底部）切换尺寸

### 设计要点

- 根据页面密度选择尺寸，分页控件应靠近对应的数据区域。
- 页数较少时显示完整页码，较多时通过省略号和跳转控件缩短导航。
- 保留悬停、聚焦、按下和禁用反馈，并遵循减少动态效果的系统偏好。
- 整组禁用时，当前页仍以中性容器和边界保留位置标记；所有页码继续使用原生禁用语义，不能点击或键盘切页。强制颜色模式通过当前页轮廓保留区别。

### 三套风格

Apple 当前页使用强调色背景和配对前景色、6px 圆角；MD3 使用胶囊形次要色容器；shadcn 当前页使用表面色、细描边和 8px 圆角。三套风格保留上一页、下一页、省略跳转、页容量、快速跳转、禁用和键盘焦点行为。当前页通过 `aria-current="page"` 暴露，不靠颜色单独传达位置。

M3 与 Material Web 没有独立分页组件，本组件根据 [M3 按钮](https://m3.material.io/components/buttons/overview)和 [Material Web 按钮](https://material-web.dev/components/button/)的状态反馈扩展。shadcn 参考 [Pagination](https://ui.shadcn.com/docs/components/radix/pagination)及其 [New York v4 实现](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/pagination.tsx)的 active outline / inactive ghost 模式。Apple 是与同主题按钮和导航一致的 Web 扩展。参考核对日期：2026-10-22。

### 三体系验收规格

分页没有直接对应的官方 M3 组件。本项目将 [M3 Buttons](https://m3.material.io/components/buttons/guidelines)的动作反馈、明确当前位置与数据导航组合为桌面扩展；保留 Expressive 动作与分页几何的职责边界。Apple 依据 [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)的可识别动作与内容优先原则自主实现。shadcn 对照产品清单锁定修订的 [New York V4 Pagination](https://github.com/shadcn-ui/ui/blob/3d98900e9b73c45f035f8109e9d41ba6a51685e7/apps/v4/registry/new-york-v4/ui/pagination.tsx)，页大小与快速跳转属于项目扩展。资料核对：2026-10-29。

| 设计 | 页面位置、表面与层级 |
| --- | --- |
| MD3 Expressive | 当前位置采用强调色容器，其余页码为低强调动作；不把五档 Button 大尺寸传播到分页器。 |
| Apple | 轻量路径动作与精确对齐，选中页有清晰位置标记；数字使用 tabular-nums 减少变化跳动。 |
| shadcn | 中性 ghost 页码与当前位置描边，辅助总量使用次级文字；前后页保留独立名称。 |

三档尺寸来自 `sizing.*.control`，三档密度通过组间距独立变化；L3 `item` 映射 L2 `navigation.pagination`，并经 Button 的公开 `TokenVars` 保留选中背景与状态反馈。视觉边界和粗指针命中区域分别核对。默认、hover、焦点、按下、禁用、空数据、切页、跳转和页大小菜单均在 `docs/visual.json` 登记。禁用仍保留当前位置；跳页不改变页码窗口的稳态规则。错误/加载由数据视图管理，没有新增分页数据状态协议。

`pagination.visual.spec.mjs` 通过真实按钮、Enter 和下拉菜单进入状态，并把 Portal 纳入截图。环境矩阵覆盖窄屏折行、RTL、语言、品牌、强制颜色及减少动画；切换配置保留当前页和页大小。候选截图、像素比较和人工复审分别记录，未完成的范围不视为通过。



页码使用 `value/defaultValue/onValueChange(page, details)`，从 1 开始；`details` 包含当前 `pageSize` 和 `reason: 'page' | 'page-size' | 'jump'`。每页条数使用独立的 `pageSize/defaultPageSize/onPageSizeChange(size, { page })`。每组受控与默认属性互斥，外部更新不触发回调。

改变每页条数时保留原首条数据所在页，先通知条数变化，再通知页码及完整详情；应用据此更新数据请求。两类详情通过可选的 `event` 保留真实操作事件：页码点击、跳转的 Enter 或失焦、页容量选择；页容量变化的两个回调共享同一事件，不伪造原生事件。`total=0` 时保留不可前后移动的第一页。组件管理导航状态，数据加载由使用方负责。

页码按钮和快速跳转保持原生键盘操作；内置名称、页容量与总数格式跟随语言，可通过现有格式化属性覆盖。`size` 决定分页控件尺寸，数据区域的 `density` 独立配置；窄屏允许辅助区域换行。

### 适用场景

用户需要在较大的结果集中稳定定位页码。 服务器分页或业务要求明确的页数和每页条数。

连续浏览内容可使用加载更多或虚拟滚动；结果很少时不要增加分页控制。

### 使用要点

- current、pageSize 与 total 共同决定合法页码。
- 改变 pageSize 后要重新计算 current，避免落到不存在的页。
- 请求中的页码状态、加载和错误由业务层管理。

### 无障碍

- 分页区域使用有名称的导航语义，当前页标记 aria-current。
- 上一页、下一页、页码和跳转输入都有明确名称，禁用状态不能只变淡。
