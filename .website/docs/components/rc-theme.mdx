## 使用说明

`@crab-dev/rc-theme` 是 CSS-only 主题包，通过 L2 变量提供 Material 与 Shadcn 两种风格，以及各自的浅色、深色和强制颜色配对：


```sh
yarn add @crab-dev/rc-theme
```

普通组件随模块引用自动加载 CSS；仅声明本包依赖不会触发加载。本仓库在 Wake Docs 中配置主题入口，由 Wake 加载，无需手写 CSS 副作用导入：

```toml
# .website/wake.config.toml；路径相对于文档项目根目录。
[docs]
theme_css = "docs/theme.css"
```

`theme_css` 文件必须位于文档项目内。本仓库的 `.website/docs/theme.css` 通过 CSS 引用公共主题：

```css
@import "../../components/rc-theme/css/index.css";
```

其他构建器需要自行加载本包公开的 `css/index.css`；自动加载是 Wake 的构建能力。

默认风格为 Material，默认颜色模式为 Light。风格与颜色模式相互独立，可通过 `ConfigProvider` 设置，也可以在非 React 页面同时设置两个属性：

```tsx
<main data-crab-design="shadcn" data-theme="dark">...</main>
```

`data-crab-design` 接受 `material` / `shadcn`，`data-theme` 接受 `light` / `dark`。原有只设置 `data-theme` 的页面继续使用 Material 配色；手写局部风格边界时，应同时声明两个属性。React 项目推荐使用 [ConfigProvider](/components/rc-config-provider)，由它继承并同步风格、颜色模式与品牌色。

### 避免首屏主题闪烁

主题包不会监听 `prefers-color-scheme`，也不会读写持久化状态。应用应自行决定主题，并在应用脚本执行和
首屏渲染之前尽早把 `data-theme="light"` 或 `data-theme="dark"` 写到 `document.documentElement`。
例如，可把下面的短脚本放在文档 `<head>` 中、主 bundle 之前：

```js
const savedTheme = localStorage.getItem("theme");
document.documentElement.dataset.theme = savedTheme === "dark" ? "dark" : "light";
```

如果应用选择跟随系统，也应由应用读取 `matchMedia("(prefers-color-scheme: dark)")`、持久化用户选择并
设置 `data-theme`；`@crab-dev/rc-theme` 只负责 CSS 变量映射。运行时切换只需更新同一属性。

主题包仅覆写 `--token-semantic-*`，所以组件级变量仍拥有最高优先级。`forced-colors: active`
会自动切换到 `Canvas`、`CanvasText`、`Highlight` 等系统颜色。

### 风格、默认品牌与来源

Material 保留已有紫色品牌与带色调的表面配对。Light 的品牌默认 / 悬停 / 按压为 Purple 40 / 30 / 20，其上文字为 White；Dark 从 Purple 80 过渡到 Purple 90，其上文字为 Purple 20。

Shadcn 采用黑白灰结构表面、文字、边框、选中与焦点角色。Light 的近黑主色配白色文字，悬停和按压时逐步提亮；Dark 的近白主色配深色文字，悬停和按压时逐步加深。两种风格都保留 Red、Green、Amber、Blue 功能反馈，切换时只改变 L2 映射。

风格还会切换默认形状和阴影：Material 的通用控件 / 卡片 / 弹层圆角为 4 / 12 / 28px，默认按钮保留胶囊形状；Shadcn 分别为 8 / 12 / 12px，默认按钮采用 8px 圆角，默认卡片使用细描边与较轻的层级。显式指定的按钮 `shape`、卡片 `variant` 仍优先。桌面 `small` / `middle` / `large` 三档 32 / 36 / 40px 控件高度由[尺寸配置](/guides/component-sizing)独立控制。

需要从一个颜色快速换肤时，使用 [ConfigProvider 的 brandColor](/components/rc-config-provider)。它会成对生成明暗模式的品牌角色并覆盖当前边界的 L2 变量，支持嵌套继承；传入 `null` 恢复当前风格的默认品牌。该可选能力由 ConfigProvider 提供，本包保持 CSS-only。

配对数据位于 `@crab-dev/rc-token-semantic`：`themeColorContract` 保留 Material 合约，`shadcnColorContract` 提供中性配对，`designColorContract` 按风格统一索引。本包将它们编译为 CSS。文档站与独立工作台使用同一来源；站点的字体和阅读布局仍属于站点自身，不是公共组件默认尺寸。

### 局部主题与浮层

风格与颜色模式可以嵌套，例如 Shadcn Dark 内放置 Material Light。每个显式双属性边界重新声明配色、形状与阴影，使内层能恢复所选风格；只在外层祖先定义的业务覆盖不一定穿过内层主题边界。

浮层若通过 Portal 挂载到 body，已经离开局部主题祖先。应在浮层的已有根或挂载容器上同步主题和业务覆盖；不能只观察触发按钮的颜色。当前页面主题切换时，已打开浮层也要更新。主题包只提供选择器和变量，不管理应用状态或 Portal 生命周期。

### 保留业务品牌覆盖

通过 `TokenVars` 中的正式 L2 和 L3 变量覆盖品牌色；历史别名需要先迁移，参见[正式变量迁移](/components/rc-token-semantic)。把业务覆盖放在公共主题样式之后，并使用应用自有类与主题属性共同限定范围。例如下列片段只展示 Light 的自定义紫色主按钮配对；完整业务主题还要分别评审链接、焦点、选中和 Dark 配对。

```tsx
import { css } from "@crab-dev/css";
import global from "@crab-dev/rc-token-global";

const existingBrand = css`
    &[data-theme="light"] {
        --token-semantic-color-brand-primary: ${global.purple[40]};
        --token-semantic-color-brand-primary-hover: ${global.purple[30]};
        --token-semantic-color-brand-primary-active: ${global.purple[20]};
        --token-semantic-color-text-on-brand: ${global.white};
    }
`;
// 将 existingBrand 与 data-theme="light" 同时放到应用主题根。
```

### 迁移检查

1. 将旧变量名和旧 `vars` 键迁移到 `TokenVars` 中的正式名称，再比较默认、悬停、按压三种主按钮与前景。
2. 检查链接、焦点、当前导航与选中数据的明暗配对；Material、Shadcn 与自定义品牌色都需要覆盖这些状态。
3. 打开 Dialog、Drawer、Select 和 Tooltip 后切换主题，再关闭并检查焦点恢复。
4. 检查局部深色、浅色岛和已有 L3 覆盖。强制颜色下必须保留系统颜色，业务覆盖也须提供该模式的等价处理。
5. 运行令牌生成、契约测试和受影响包测试；在浏览器记录完整状态。公共映射测试通过不代表整个应用已符合 WCAG。

本项目的双风格主题参考 [M3 颜色系统](https://m3.material.io/styles/color/system/overview)、[形状系统](https://m3.material.io/styles/shape/overview)、[Material Web 色彩配对](https://material-web.dev/theming/color/)与[形状主题](https://material-web.dev/theming/shape/)，实现对照 [Material Web v0.192 形状令牌](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-sys-shape.scss)及 [shadcn/ui 主题变量](https://ui.shadcn.com/docs/theming)。Shadcn 风格和共享桌面密度是本项目的定制，不代表 M3 默认视觉规格。另见[无障碍](/guides/accessibility)与[令牌实施](/components/rc-token-semantic)。

### 适用场景

应用根节点需要加载 Crab UI 的基础主题。 某个局部区域需要在明确边界内覆盖浅色、深色或品牌语义变量。

单个组件微调优先修改其 props 或 L3 token；不要在业务节点随意重写原始色阶。

### 使用要点

- 主题覆盖发生在 L2 语义角色，组件继续消费相同 token 名称。
- Theme 边界决定 CSS 变量继承，Portal 到边界外的浮层要单独检查。
- 浅色和深色是两套角色映射，不是把颜色机械反相。

### 无障碍

- 每个主题分别验证文字、图标、边框、焦点与状态层对比度。
- 遵循系统偏好时仍提供可理解的用户选择，并避免切换造成闪烁或焦点丢失。

## 常见问题

### 主题为什么没有变化？

检查主题 CSS 是否加载、data-theme 是否正确，以及自定义样式是否使用了语义令牌。
