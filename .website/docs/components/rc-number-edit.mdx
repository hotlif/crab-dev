## 使用说明

输入数值，支持步进、范围限制、千分位和科学计数法显示。


### 何时使用

用于数量、金额、阈值等数值录入。支持加减按钮、方向键、长按步进和大步长调整；失焦时按范围限制修正数值。

显示时可使用千分位或自定义格式。极大、极小数值可显示为 `1.23×10²¹` 等科学计数法，聚焦后转为便于编辑的 `e` 记法。

### 编辑、步进与范围

**现有实现**：键入文本先保留为编辑草稿；失焦、步进或清除时提交数值。键盘 ↑ / ↓、PageUp / PageDown、Shift + ↑ / ↓、滚轮和步进按钮使用同一数值计算路径。`aria-valuenow` 随当前可解析的编辑文本更新。

| 场景 | 结果与规则 |
| --- | --- |
| 原值 3，键入 20 后按 ↑ | 得到 21，不能从旧值 3 得到 4 |
| 键入 20.5，step 为 1，未指定 precision | 得到 21.5，保留输入的小数精度 |
| 清空编辑文本后按 ↑ | 从 0 开始步进，再应用 min / max |
| 文本尚不能解析，例如单独的负号 | 步进从上次已提交值开始；尚无数值时从 0 开始 |
| 当前编辑值达到 min / max | 对应方向按钮禁用；键盘步进同样不得越界 |
| 显式指定 precision | 按该精度规范提交值，不能用于无限精度金额运算 |

`parser` 应是无副作用的解析函数，并返回有限数或 `null`；组件会在编辑期间读取它以同步步进和无障碍数值。旧调用方若假定 parser 只在失焦时执行，应移出其中的请求或其他副作用。`stringMode` 当前仍为预留能力，不能据此宣称支持任意精度。

**正例**：通过可见标签说明“预警阈值（万元）”，就近说明范围；编辑 20.5 后步进得到 21.5。**反例**：仅用 placeholder 作为名称，或步进时恢复旧值，导致用户误以为刚才的输入已经保存。

验收：分别用键盘和鼠标测试草稿步进、空值、边界、带小数的 step、只读与禁用。格式化显示不改变真实数值；长数值在聚焦后可完整编辑。当前小步进按钮的触控尺寸、科学计数法覆盖层和文字缩放仍需独立复核。通用规则见[输入与选择](/design/inputs)和[无障碍](/design/accessibility)。
