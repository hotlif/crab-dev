## 使用说明

为应用或局部区域提供可嵌套的默认配置。




### 使用

```tsx
import ConfigProvider from '@crab-dev/rc-config-provider';

<ConfigProvider theme="dark" locale="en-US" size="large">
    <App />
</ConfigProvider>
```

主题切换需要加载 `@crab-dev/rc-theme` 的样式，仅安装包还不够。Wake Docs 中通过 `theme_css` 配置入口；其他构建器需接入公开样式入口，详见 [Theme 主题样式](/components/rc-theme)。

Provider 会渲染一个普通 `div`，可通过 `className` 设置这层容器的布局。它本身不绘制背景，Card 等子组件使用对应主题的颜色。

### 配置与继承

| 属性 | 值 | 根级默认值 |
| --- | --- | --- |
| theme | light / dark | light |
| brandColor | #RGB / #RRGGBB / null | null（默认紫色） |
| locale | zh-CN / en-US | zh-CN |
| size | small / middle / large | middle |

嵌套 Provider 按字段继承父级，只覆盖显式传入的属性；传入 `undefined` 恢复继承。没有 Provider 时，`useConfig()` 返回表中的默认值。

配置继承发生在 ConfigProvider 之间。仅给 `html` 设置 `data-theme="dark"` 不会改变 React 配置：如果应用已有主题状态，应把该状态传给根级 Provider，避免只设置 `size` 的根级 Provider 使用默认浅色。

`locale` 会设置容器的 `lang` 并切换 Empty 的预置文案，不会自动翻译业务文字。原生 div 属性与 React 19 `ref` 可直接传入；自定义组件可用 `useConfig()` 读取当前配置。

### 一个颜色生成品牌主题

```tsx
<ConfigProvider brandColor="#1677ff" theme="dark">
    <App />
</ConfigProvider>
```

`brandColor` 接受不透明十六进制颜色（忽略首尾空格、大小写），自动生成浅色与暗黑的 OKLCh 配对。
默认、悬停、按下、链接、焦点和选中背景一起联动；中性背景及成功、警告、错误色保持独立。
算法保留色相并调整亮度和色度，以维持文字对比度和 sRGB 色域，因此按钮背景不一定与输入值完全相同。
不支持带透明度的颜色、CSS 变量或任意 CSS 表达式；无效值会抛出 RangeError，颜色编辑器应先校验再传入。

不传 `brandColor` 继承父级；传入 `null` 恢复默认紫色。`useConfig().brandColor` 返回标准化的六位颜色或 null。
嵌套 Provider 切换 light / dark 时会保留品牌色，并使用对应模式的配色。

设置品牌色时，Provider 在自己的边界内渲染一张仅声明 L2 变量的 style 标签；更新或卸载时由 React 同步处理。
没有品牌色时仅使用预编译主题 CSS。若应用使用 CSP，可通过原生 `nonce` 属性为该标签提供 nonce。
品牌规则只在 `forced-colors: none` 下生效，强制颜色模式继续使用系统颜色。
非 React 场景可从 `@crab-dev/rc-token-semantic` 导入纯函数 `createBrandTheme(color)`，读取 `light` / `dark` 变量映射。

### 统一尺寸

`small` 适合紧凑工作区，`middle` 是默认档位，`large` 提供更宽松的操作空间。组件显式的 `size` 优先于分组配置，分组优先于最近 Provider。

尺寸配置不会按屏幕分辨率自动切换，也不会等比缩放页面。适用组件、具体数值和局部覆盖示例统一维护在[尺寸指南](/guides/component-sizing)。

自定义组件可通过 `useComponentSize(size)` 解析显式尺寸与继承值。虚拟列表可用 `componentSizeMetrics` 获取对应的默认行高；需要在已有 DOM 上建立密度范围时，可使用 `componentSizeStyles` 提供的静态类名。

### 嵌套与浮层

允许 dark 内嵌 light，或并列多个独立主题。CSS 同时保留强制颜色支持；主题切换不添加动画。
Provider 不访问 document、存储或系统主题，也不修改 html / body；如需持久化或跟随系统，请由应用传入结果。

React Portal 保留 Context，但不会继承原 DOM 祖先的 CSS 变量。
将浮层挂载在主题容器内，或在 Portal 内容外再包一层不带配置属性的 ConfigProvider，
即可从 Context 继承配置并重新建立 CSS 边界。DropdownContainer 已在自己的浮层节点重建尺寸边界；其他自定义 Portal 应按此方式处理。

```tsx
createPortal(<ConfigProvider><Overlay /></ConfigProvider>, container)
```

局部主题边界会重新声明 L2 变量；业务变量覆盖应施加到目标边界或其后代。

### 适用场景

整个应用需要统一默认配置。 某个局部区域要临时切换语言、密度或主题，而不影响页面其他部分。

只影响一个组件的一次性属性直接传 prop；不要用全局配置隐藏业务状态。

### 使用要点

- 最外层放应用默认值，局部覆盖只写确实不同的字段。
- Provider 边界决定配置作用域，弹层挂载到边界外时要检查是否仍能继承。
- 配置是默认策略，不应覆盖组件显式传入的值。

### 无障碍

- 语言切换要同步文档语言、读屏文本与格式化规则。
- 主题和尺寸覆盖后仍需检查对比度、焦点可见性和 200% 缩放。

## 常见问题

### 哪些组件会跟随配置？

主题作用于消费语义颜色的后代；按钮、输入框、选择器、表格和树等已接入尺寸配置，详细范围见“统一尺寸与密度”指南。locale 自动切换 Empty 的预置文案，业务文案仍由应用提供。

### Portal 浮层如何继承主题？

将浮层放在主题容器内，或在 Portal 内再包一层无配置属性的 ConfigProvider，从 React Context 继承配置并重建 CSS 边界。
