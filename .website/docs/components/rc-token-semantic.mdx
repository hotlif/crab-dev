## 使用说明

语义设计令牌（L2）将全局基础值映射为品牌色、表面色、文字色、间距、焦点环和动效等界面语义。组件令牌优先引用这一层，主题通过覆盖语义变量改变外观。


### 角色与默认主题

业务样式应消费角色，例如 `token.color.text.primary`、`token.color.brand.primary` 与 `token.color.selection.background`。默认 Material Design 3 风格将 L1 的 Purple 40 / 80 配对为浅色 / 深色品牌；可选 shadcn 风格使用零色度 Neutral 黑白灰，macOS 风格使用蓝色强调与银灰、深灰表面。三套风格使用相同的 L2 角色，明暗模式独立切换。`TokenVars` 与 `vars` 均导出 `token.toml` 生成的正式变量映射，不再包含历史别名。

| 意图 | 背景或主色 | 配套前景 | 使用边界 |
| --- | --- | --- | --- |
| 主要操作 | color.brand.primary | color.text.on-brand | 同时检查 hover / active 背景 |
| 当前选择 | color.selection.background | color.selection.foreground | 同时提供选择标记或 ARIA |
| 阅读容器 | color.background.surface | color.text.primary / secondary | 必要边界用 border.default，装饰分隔用 border.subtle |
| 反馈 | color.feedback 中对应意图的 background / solid | text / on-solid | 不混用容器文字和实心按钮前景 |
| 键盘位置 | color.focus.ring | 与所在表面比较 | 焦点独立于选中和错误 |

```tsx
import { css } from "@crab-dev/css";
import token from "@crab-dev/rc-token-semantic";

const panel = css`
    background: ${token.color.background.surface};
    color: ${token.color.text.primary};
    padding: ${token.space["card-padding"]};
`;
```

### 同一份配对数据与 CSS 主题

`themeColorContract` 保持默认 Material 的 `light`、`dark` 配对；`shadcnColorContract` 提供独立的黑白灰配对，`macosColorContract` 提供蓝色强调与分层灰色表面的配对。`designColorContract` 用 `material` / `shadcn` / `macos` 索引三套数据，`ThemeDesign` 类型声明这三个风格名称。它们供主题编译、设计参考和契约测试使用，成员是 CSS 引用字符串，读取它们不会切换主题或注入样式。

```ts
import { designColorContract } from "@crab-dev/rc-token-semantic";
import type { ThemeColors, ThemeDesign } from "@crab-dev/rc-token-semantic";

const design: ThemeDesign = "shadcn";
const light: ThemeColors = designColorContract[design].light;
const brand = light.brand.primary; // L1 Neutral 900 的 CSS 引用
const onBrand = light.text.onBrand;
```

运行时主题使用 `@crab-dev/rc-theme/css/index.css`、`data-crab-design` 与 `data-theme`；React 应用通过 ConfigProvider 的 `design` 统一选择风格，例如 `design="macos"`。TOML 保持无主题样式时的 Material Light 回退值，`src/theme.ts`、`src/shadcn-theme.ts` 与 `src/macos-theme.ts` 分别维护三套完整明暗配对。业务代码通常只需要默认 `token`，不用在每个组件里读取风格或明暗模式再分支。

### 覆盖、迁移与验收

### 使用正式变量

每个令牌只有一个正式 CSS 变量入口。组件默认值通过 `$ref()` 引用 L2；历史名称不再进入回退链，例如 `--switch-transition` 应迁移为 `--switch-root-transition`。代码中优先通过组件的 `TokenVars['root.transition']` 获取名称。

旧反馈总色变量（例如 `--token-semantic-color-feedback-error`）已移除。请按用途分别覆盖 `color.feedback.error.text`、`icon`、`border` 和 `solid` 对应的变量，并保留背景与前景配对。旧 `vars` 键也应更新为正式路径，例如 `size.large.border.radius` 改为 `size.large.border-radius`。

### 从一个颜色生成配对

`createBrandTheme('#1677ff')` 返回 `{ seed, light, dark }`，其中 seed 为标准化六位颜色，light / dark 为品牌相关的 L2 变量映射。颜色统一输出为经过 sRGB 色域收敛的 OKLCh，并检查主色上的文字可读性；secondary / tertiary 与品牌种子联动；中性表面和业务反馈保持独立。

输入仅支持不透明 `#RGB` / `#RRGGBB`，非法值抛出 RangeError。`normalizeBrandColor(value)` 可独立校验并标准化输入。该函数本身不访问 DOM，也不会插入样式；React 应用通常直接使用 [ConfigProvider 的 brandColor](/components/rc-config-provider)，由 Provider 管理继承和作用域。

### 统一视觉尺度

- small 控件横向内边距为 `space.control-padding-x-small`（8px），middle / large 为 `space.control-padding-x`（12px）。
- 通用桌面尺寸为 small / middle / large 的 32 / 36 / 40px；输入、选择控件、开关、分段按钮和页签使用各自的规格角色，不能用通用高度推断所有组件。Material 带标签输入为 56px，复选框和单选框交互区为 48px；触控目标保留独立角色。
- Material 保留 4px 控件圆角、胶囊按钮、28px 弹层圆角和默认层级卡片；shadcn 使用 8px 控件圆角、方形按钮、12px 弹层圆角和默认描边卡片。风格切换统一覆盖共享形状角色。
- macOS 通过共享形状与阴影角色提供 6px 控件和按钮圆角、12px 卡片与 16px 弹层圆角，输入采用外置标签和外圈蓝色焦点；这些是桌面风格扩展，不改变组件的无障碍语义与键盘操作。
- 卡片和内容分隔使用 `color.border.subtle`；可输入控件保留 `color.border.default` 的辨识度。
- 即时颜色、边框和阴影反馈使用 `motion.interaction`；大范围展开使用独立的 `motion.expand`。

### 排版与字体

`typography.display / headline / title / body / label` 各有 large、medium、small，共 15 组字体、字号、行高和字重角色。Material 使用 Roboto，macOS 使用系统界面字体，shadcn 使用 Inter 优先的 sans 回退；所有字体角色在嵌套风格边界一起恢复。文档和工作台随产物加载 Roboto，其他字体是否可用取决于设备；消费方可自行加载字体或覆盖公共字体角色。

### 组件类别角色

`selection`、`toggle` 与 `range` 控制选择类形状和状态；`field` 与 `picker` 控制标签、输入反馈和选择面板；`navigation` 控制分段轨道、页签和选中项；`overlay`、`feedback` 与 `status` 控制表面、消息与加载形态；`data` 控制表格、图表与分隔柄。L3 引用这些 L2 角色，三套风格在公共主题中成组覆盖，组件不按风格分支。实际对照见[三套风格](/guides/design-styles)。

### 验收范围

公共默认风格仍为 Material Design 3：品牌采用 Material Purple，表面采用 Material Neutral / Neutral Variant。shadcn 风格独立采用零色度 Neutral：浅色白底、深色近黑底，品牌操作、选中容器、文字、边框和焦点均为黑白灰。macOS 风格使用蓝色操作与选中角色，浅色银灰和深色灰阶分别定义表面层级。三套风格共用 lowest、low、container、high、highest、dim 和 bright 等角色，保留错误、成功、警告与信息的语义反馈色；自定义品牌不会改变基础表面。

颜色 API 名称保持不变，切换风格应复测已有业务主题。仅覆盖主色不等于完成主题：主色前景、悬停、按压、链接、选中与焦点必须成组评审。shadcn 与 macOS 的细描边是各自风格的视觉定制，不能将其当作所有控件唯一的可访问性标记；焦点与选择状态仍有独立的高对比角色。macOS 是受苹果桌面界面启发的项目主题，不代表苹果原生控件或 M3 默认视觉规格。

- L1 修改会影响所有上层引用；业务品牌定制优先覆盖 L2。
- L3 覆盖继续优先于 L2；应检查旧组件覆盖是否遮住新的公共默认。
- Portal 不会继承另一个 DOM 分支的局部变量。浮层根需置于相同主题边界或显式同步 data-theme 与业务覆盖。
- 在 Light、Dark、按压背景、选中底色和反馈容器上检查最终前景；数值测试不能替代键盘与真实浏览器验收。

原始值见[全局令牌](/components/rc-token-global)，主题入口见[Theme](/components/rc-theme)，设计规则见[色彩与主题](https://material-web.dev/theming/color/)与[令牌与实施](/components/rc-token-semantic)。

### 适用场景

应用需要统一浅色、深色和品牌主题。 多个组件共享同一种内容、表面、焦点或反馈含义。

组件独有视觉进入 L3；不要在 L2 中加入某一个页面或业务对象的名字。

### 使用要点

- 颜色角色按 container/on-container 等前景背景成对使用。
- 主题只覆盖角色值，不在组件里根据主题名称写分支。
- 新增角色前先确认现有语义是否已经覆盖，避免同义 token 分裂。

### 无障碍

- 所有主题分别验证角色配对、状态叠加和焦点环，不只检查静态色值。
- 错误、禁用和选中含义不能只由透明度或颜色承担。

## 常见问题

### 旧 CSS 变量如何迁移？

历史别名已移除。请使用组件 TokenVars 中的正式名称，例如 --switch-transition 改为 --switch-root-transition；TokenVars 和 vars 均只包含正式键。旧反馈总色变量应拆为 text、icon、border、solid 等角色分别覆盖。

### 修改令牌定义后怎么办？

修改 token.toml 后运行 generate:token，生成的 token.ts 必须由命令刷新。
