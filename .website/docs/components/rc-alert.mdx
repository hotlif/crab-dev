## 使用说明

在页面内展示信息、成功、警告或错误提示。


### 何时使用

需要在页面内持续展示说明、操作结果或异常信息时使用。Alert 不会自动消失；启用 `closable` 后可由用户关闭。

根据内容选择 `info`、`success`、`warning` 或 `error`，并用标题和说明表达具体含义。

### 主要功能

- 支持四种类型：`success`、`info`、`warning`、`error`。
- 支持 `title` 标题与 `children` 描述内容组合展示。
- 默认展示类型对应图标，可通过 `showIcon` 控制显隐。
- 支持 `icon` 自定义图标。
- 支持 `closable` 关闭交互与 `onClose` 回调。
- 支持 `closeIcon` 自定义关闭按钮。
- 支持 `action` 操作区域。



### 三套设计风格

Material 保留语义反馈容器色；Apple 使用较淡的状态底色、10px 圆角和紧凑标题；shadcn 使用中性表面、细描边与 8px 圆角。success / warning / error / info 的图标和文字语义不随主题改变。内联 Alert 为项目消息模式扩展，不等同于阻塞式系统 alert dialog。

切换文档站设计风格后，本页演示同步使用该设计；浅色和深色模式分别使用配对语义颜色。

### 适用场景

保存结果、权限限制或风险说明需要一直留在当前上下文中。 一段内容需要 success、info、warning 或 error 语义，并可能允许用户关闭。

只需短暂确认一次操作结果时使用 Message；必须打断流程并要求决策时使用 Dialog。

### 使用要点

- 先选 type，再写能独立成立的 title，children 只补充原因和行动。
- closable 只表示可以移除提示，业务状态仍应由外部状态管理。
- 提示离相关内容越近，用户越容易理解它影响的是哪一部分。

### 无障碍

- 不要只靠颜色区分状态，标题或正文应直接写出成功、警告或错误含义。
- 动态出现的重要错误需要合适的状态通告；可关闭提示必须提供可访问名称清楚的关闭按钮。

## 常见问题

### 什么时候用 Message？

需要短暂、简短的操作反馈时用 Message；需要持续阅读的页面提示用 Alert。
