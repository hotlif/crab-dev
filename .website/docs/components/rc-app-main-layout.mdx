## 使用说明

为管理后台提供侧边导航、顶部操作区和标签页内容区。


### 何时使用

- 管理后台需要统一的侧边导航、顶部操作区和内容区。
- 多个业务页面需要通过标签页切换，并共享应用布局。
- 窄屏下需要将侧边导航收起到抽屉中。

使用时需包裹在 `AppMainLayoutProvider` 中，由 Provider 管理标签页状态。

独立应用的内容区默认使用 `main`。嵌入文档或已有主内容区的页面时，设置 `contentLandmark={{ role: "region", "aria-label": "后台工作区示例" }}`，将示例内容标记为有名称的区域，避免嵌套主内容地标。`region` 的名称在类型上必填。

### 适用场景

企业后台需要长期存在的主导航、顶栏和可切换工作页。 不同页面必须共享一致的响应式框架、焦点顺序和内容边界。

单页落地页或只有一条简单流程时，不要为了形式套入复杂后台骨架。

### 使用要点

- 先确定导航目的地，再把路由状态映射到选中项和当前页签。
- Header、Sidebar、TabBar 与 Content 各有职责，业务内容只放进内容区。
- 窄屏不是把桌面布局等比缩小，而是按可用空间收起或转换导航。

### 无障碍

- 为导航、页签和主内容提供清楚的 landmark 与名称，并保留唯一主内容入口。
- 打开、关闭侧栏或页签后要把焦点放到可预测位置，键盘顺序应与视觉顺序一致。

## 常见问题

### 页面内容放在哪里？

页面内容放在 TabItem.children 中，由 Provider 管理。AppMainLayout 本身不通过 children 接收页面。
