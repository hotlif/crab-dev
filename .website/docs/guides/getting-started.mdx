# 开始使用

Crab UI 按包提供 React 19 组件。先从[组件目录](/learn/components)选择所需能力，安装对应包，不需要引入整个组件库。

应用提供满足包声明范围的 React 宿主；实际使用 ReactDOM 的包也声明对应 peer。库包保留自身开发依赖供构建和测试，严格 PnP 消费不会依赖它们替应用提供 React。

```sh
yarn add @crab-dev/rc-button @crab-dev/rc-config-provider @crab-dev/rc-theme
```

## 创建第一个界面

```tsx
import Button from "@crab-dev/rc-button";
import ConfigProvider from "@crab-dev/rc-config-provider";

export default function App() {
    return <ConfigProvider designSystem="md3" colorMode="light" size="medium" density="standard">
        <Button appearance="primary">保存修改</Button>
    </ConfigProvider>;
}
```

主组件默认导出，类型、Hook 和工具具名导出；CSS-only 与基础支撑包以各自公开导出为准。

## 加载静态样式

Wake 按组件模块引用加载对应静态 CSS；其他构建器需要显式加载所用组件及其依赖包公开的 `css/index.css`。使用包公开入口，不导入 `src`、`esm`、`cjs` 或 `declarations` 内部文件。

`@crab-dev/rc-theme` 是 CSS-only 包，安装或渲染 ConfigProvider 不会自动加载它。普通构建器应在全局 CSS 入口加载主题：

```css
@import "@crab-dev/rc-theme/css/index.css";
```

Wake Docs 通过项目内的 `theme_css` 文件加载主题；本仓库配置为 `docs/theme.css`，其中引用 `../../components/rc-theme/css/index.css`。具体入口与局部主题规则见 [Theme 主题样式](/components/rc-theme)。

## 选择外观与密度

公共配置的四个独立轴为 designSystem、colorMode、size、density。设计体系是 MD3 Expressive（md3，默认）、Apple（apple）与 shadcn/ui（shadcn）；明暗是 light、dark；跟随系统属于应用偏好，解析后再传入；通用尺寸是 small、medium、large，密度是 compact、standard、comfortable。

```tsx
<ConfigProvider designSystem="apple" colorMode="dark" density="compact">
    <Profile />
</ConfigProvider>
```

嵌套 Provider 继承省略项，显式品牌色通过 brandColor 覆盖，null 恢复当前设计体系默认品牌。Apple 是自主 Web 适配，不承诺复刻特定 macOS 版本。

文档站和工作台默认同样使用 MD3 Expressive。外观菜单分别保存设计体系和明暗偏好；历史设计偏好仅在存储入口迁移，切换不清空正在编辑的组件状态。更多规则见[设计体系](/guides/design-styles)与[尺寸密度](/guides/component-sizing)。

## 连接状态与表单

值控件使用 value/defaultValue/onValueChange，布尔控件使用 checked/defaultChecked/onCheckedChange。原生 onChange 保留 DOM 事件语义。Form 的值控件采用默认适配，Checkbox/Switch 等采用 adapter="checked"；详见[公共 API](/guides/public-api)。

## 在仓库中开发

使用 Node.js ≥ 22 和根 packageManager 指定的 Yarn 4 PnP，通过 Corepack 安装后运行根 yarn docs:dev。Wake Docs 使用项目内 theme_css 加载公共主题 CSS，开发服务器同步组件正文、示例、教学内容与生成页面。

从[组件库体系](/guides/library-architecture)理解产品职责，从[贡献维护](/guides/contributing)查找生成来源、验证与发布要求。已有代码先阅读[迁移指南](/guides/migration)。
