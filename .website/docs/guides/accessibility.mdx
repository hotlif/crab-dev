# 无障碍使用指南

组件内置的角色和键盘行为只是基础。业务代码仍需提供与当前上下文匹配的名称、说明和状态文案。

## 为控件提供名称

优先使用可见文字。图标按钮或没有可见标签的控件必须提供 `aria-label`；表单控件应使用
`useId` 生成稳定 ID，通过 `htmlFor` 与 `<label>` 关联。

```tsx
import { useId } from "react";

export default function SearchField() {
    const inputId = useId();

    return (
        <>
            <label htmlFor={inputId}>搜索项目</label>
            <input id={inputId} type="search" />
        </>
    );
}
```

占位符会在输入后消失，不能替代标签。装饰图标应从无障碍树中隐藏，避免重复朗读。

## 关联说明和错误

帮助文本与错误信息使用 `aria-describedby` 关联；错误状态同时提供文字或图标，不能只改变颜色。
异步操作超过约 400 ms 时，为作用区域设置 `aria-busy`，并提供可感知的加载反馈。

## 保留完整键盘路径

- Tab 顺序应与 DOM 和视觉顺序一致，不使用正数 `tabIndex`。
- 所有操作都应能通过键盘完成；不要把关键操作只放在 hover 或右键菜单中。
- 不移除 `:focus-visible` 轮廓。自定义焦点环时必须提供清晰、对比度足够的等价样式。
- 浮层打开后应管理初始焦点，关闭后将焦点还给触发器；Escape 应提供可预期的关闭路径。

## 表达状态和约束

选中、展开、错误、禁用和加载状态应使用相应的原生属性或 ARIA。暂时不可用的操作应禁用并解释原因；
删除、覆盖等不可逆操作使用 Dialog 二次确认或提供撤销。

## 验收清单

1. 仅使用键盘完成主流程，并检查焦点始终可见。
2. 使用辅助技术确认每个控件都有唯一、准确的名称，状态变化会被感知。
3. 在 320 px 宽度、200% 缩放、`forced-colors` 和 `prefers-reduced-motion` 下检查界面。
4. 为关键名称、角色、状态和键盘行为补充自动化测试。
