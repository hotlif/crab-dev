# 尺寸与密度

尺寸描述控件的视觉档位，密度描述内容间距与行的疏密。两者独立，也不隐式改变设计体系、明暗或品牌。

```tsx
<ConfigProvider designSystem="md3" colorMode="light" size="medium" density="standard">
    <Form />
</ConfigProvider>
```

## 四个独立轴

| 配置 | 取值 | 选择依据 |
| --- | --- | --- |
| designSystem | md3 / apple / shadcn | 组件形态、角色与反馈规则 |
| colorMode | light / dark | 解析后的明暗模式 |
| size | small / medium / large | 控件的组件专属尺寸档位 |
| density | compact / standard / comfortable | 间距、内容区与数据行节奏 |

默认 MD3 Expressive、light、medium、standard，语言 zh-CN、方向 ltr。局部 Provider 只覆盖显式传入的轴，其余继承；切换尺寸或密度不应重建组件、清空草稿或改变值。

## 交互对照

先改变控件尺寸，再改变内容密度，观察字段、操作和表格的不同职责。显式尺寸的单个组件保持自身档位。

## 组件专属规格

`small / medium / large` 是统一选择入口，不能据此推断所有控件使用同一高度。字段需要保留标签和说明空间，复选框/单选框的视觉大小与交互命中区分别定义，多行文本和内容卡片随内容扩展。

Button 显式 `size` 使用 `xs / s / m / l / xl`，是组件自己的 Expressive 尺寸变体；Provider 的通用档位由组件映射到其默认规格。画布坐标、PDF 页面、图表数据和正文排版不随控件尺寸等比缩放。

TextEdit 的 `rows` / `autoSize` 管内容高度，`size` 管输入边界的最小高度和间距，不缩放正文。Apple 的三档为本库 Web 几何；shadcn/ui 的 medium 采用固定 New York V4 的 64px 最小高度、上下 8px、左右 12px，small/large 是显式扩展。具体数值及全部外观见 [TextEdit 尺寸契约](/components/rc-text-edit)。

TextEdit 在 MD3 下将三档映射到同一标准字段几何（最小 56px、常规内边距 16px、正文 16px/24px），是保留浮动标签、正文与轮廓空间的例外，不是官方三档规格。该映射兼容已有 size 调用和内部清除动作分档，适用于带边界字段；无边框模式由宿主提供几何。实际 CSS 回归覆盖三档、标签、Filled、行数及 autoSize。只有引入有依据的新变体并同步迁移和复验后才退出此例外。

密度可以调整布局间距和数据行节奏，但不能减少必要的标签空间、焦点可见性和触控命中区域。不可用更小字号掩盖宽度不足；窄屏改为合适布局，长内容保持阅读和操作顺序。

Table/TablePro 的虚拟行几何使用独立 density；size 只影响内部控件。显式 getRowHeight 或 row.height 优先，切换密度时仍需核对滚动窗口和焦点位置。

Tree 的节点高度优先采用 node.height，其次采用显式 defaultNodeHeight，未提供时使用自动默认几何。Table/Tree 的粗指针最低高度只用于自动默认值，不覆盖显式行高或节点高度；显式较小高度保持传入值，由应用按实际输入方式选择尺寸。

## 验证

在实际使用的设计体系、明暗、尺寸和密度组合下检查可读性、标签、错误说明、键盘焦点、触控与 200% 缩放。所有具体数值以公共令牌和对应组件规格为准，不能把某个按钮的数值推广到全库。
