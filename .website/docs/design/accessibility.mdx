# 无障碍与键盘

> **验收目标：遵循 WCAG 2.2 的相关要求，并采用明确标注的 Crab 更严格约定。** 以下清单不能单独构成“全站符合 WCAG”的声明；真实辅助技术、设备与完整任务仍需验收。

> **本轮实现范围**：当前基础批次补齐了 Button、Checkbox、Radio、Switch 的焦点、强制颜色与粗指针命中区。样板层的兜底样式不能代替公共组件自身实现。运行中的自动测量、真实键盘观察、辅助技术测试与 React 单元测试各自记录结果；任何阻塞都不能通过更改文案改成已通过。

## 可感知的信息

普通文字以至少 4.5:1 为设计门槛，必要控件轮廓和状态图形至少 3:1。装饰线与控件边界要分开评审；占位提示和帮助文字如果承担阅读任务，也需要可读对比度。

状态不能只靠颜色。错误包含文字，当前页包含 current 语义，选中控件包含相应选择语义。图标旁已有完整文字时，避免重复朗读。标准的适用范围参阅 [文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

## 名称、标签和关联

每个输入必须有持久可见的标签。帮助和错误说明通过 aria-describedby 等方式与输入关联；无效字段使用相应 invalid 语义。ID 由 useId 等稳定机制生成，不能依赖随机值或页面内硬编码重复 ID。

按钮名称应包含动作，必要时包含对象。可见文字是“保存修改”时，可访问名称不应变成完全不同的术语。必填不能只用红色星号说明，应有文字或明确的表单约定。

## 键盘操作基线

| 场景 | 预期行为 | 验收重点 |
| --- | --- | --- |
| 页面与表单 | Tab 前进，Shift+Tab 后退 | 顺序符合 DOM 与阅读顺序，无正数 tabIndex |
| 按钮与链接 | 使用相应原生激活方式 | 不用不可聚焦容器模拟按钮 |
| 菜单、单选组和选择器 | 遵循组件既有方向键、确认与关闭行为 | 不另造一套与视觉方向相反的规则 |
| 弹层 | 焦点进入当前任务层，关闭后恢复 | 背景模态限制与视觉遮罩一致 |
| 可滚动表格与代码 | 提供可达的局部滚动路径 | 不只能拖动很细的滚动条 |
| 拖拽功能 | 提供等价的非拖拽操作 | 排序不能仅依赖精细指针动作 |

组合控件不要求内部每个项都成为独立 Tab 停靠点；应复用组件已有的标准键盘模式。添加键盘快捷键时，要避免与浏览器、输入法和辅助技术冲突，并提供可见操作入口。

## 焦点显示与恢复

Crab 采用清楚的实线焦点轮廓，必要时增加偏移以区别边界；不能只保留低对比度的柔和阴影。目标是容易辨认的 2px 级轮廓和至少 3:1 的必要对比。这里的项目约定不等于声称 WCAG AA 统一要求“2px 焦点环”；[Focus Appearance 的面积要求属于 AAA 条款](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html)。

打开编辑抽屉后，焦点进入抽屉；校验失败聚焦首个需要修复的字段；取消确认后回到编辑上下文；关闭后回到触发按钮。触发按钮已不存在时，应选择仍存在的逻辑后继位置，而不是丢失焦点。

## 触控与放大

Crab 对触控目标采用至少 44px 的约定。WCAG 2.2 AA 的 Target Size Minimum 基线是 24×24 CSS px，并包含特定例外；两者不能混为一谈。详见 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

在 320px 视口与 200% 文字缩放下，主要任务仍应可完成。表格等二维内容可以局部滚动，表单和普通说明应重排。固定页头、吸底操作区和弹层不能遮住当前焦点。

## 媒体偏好与强制颜色

减少动态效果模式下移除非必要动画，同时保留最终状态和加载文字。强制颜色模式下使用系统颜色保留边界、焦点和选择线索，不能假设 box-shadow 或背景色一定存在。

仅在 CSS 中写入媒体查询不等于完成验收。需要在支持相应模式的浏览器或真实设备中确认可读、可操作；当前样板的自动截图环境不能模拟的项目必须标记为待验收。

## 反馈的播报

轻量成功信息使用适当的状态区域，避免每次键入都打断阅读。重要错误要能被感知，但同一个字段错误不应同时在字段、全局提示和弹窗中反复播报。

加载内容标记 busy 时，用户仍应知道在处理哪个任务。列表更新后，如果焦点没有移动，应通过合理的结果计数或状态提示告知变化。

## 交付检查表

- 只用键盘完成搜索、选择、编辑、提交和关闭。
- 检查标签、帮助、错误关联和焦点恢复。
- 检查暗黑、缩放、长文本、强制颜色与减少动态效果。
- 检查当前页、展开项、加载与错误具有正确语义。
- 记录实际浏览器、辅助技术和设备范围，不用单元测试替代布局或屏幕阅读器测试。

## 标准等级与 Crab 约定对照

本表作为评审索引，标准中的完整条件和例外以所链接官方说明为准。规范要求和实测结果分别记录；页面含有 ARIA 属性不等于已完成辅助技术验收。

| 项目 | 标准要求与适用边界 | Crab 的使用方式 |
| --- | --- | --- |
| 文字对比度 | 1.4.3，AA；普通文字 4.5:1，大字 3:1，非活动控件等存在例外 | 阅读正文和帮助信息以 4.5:1 为基线；不因字号变大随意降低 |
| 非文本对比度 | 1.4.11，AA；识别控件、状态及必要图形的信息通常为 3:1 | 分清必要边界与纯装饰分隔，检查最终合成色 |
| 触控目标 | 2.5.8，AA；24×24 CSS px，包含间距等例外 | 触控交互采用至少 44px 的项目约定，独立检查实际命中区 |
| 焦点外观 | 2.4.13，AAA；含面积和颜色变化对比要求 | 使用明显实线轮廓作为目标，不把“2px”冒称为全部 AA 要求 |

来源：[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[焦点外观](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html)。

失活控件的标准例外不表示可以把禁用原因一起淡化；只读内容也不应一概视为失活信息。测量文字时使用实际前景和背景，透明度需合成；不要通过四舍五入让低于阈值的结果“通过”。

### 文字缩放、重排与焦点遮挡

200% 文字缩放与 320 CSS px 重排分别验收。前者关注文字增大后没有内容或功能损失；后者关注纵向内容在等效 320px 宽度下重排，必要二维内容有例外，例外不扩展到整页。1280px 视口以 400% 缩放可用于检查等效宽度。见 [1.4.4 Resize Text，AA](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) 与 [1.4.10 Reflow，AA](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

焦点不能被作者创建的内容完全遮住，这是 [2.4.11 Focus Not Obscured，AA](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) 的基线。Crab 进一步要求常见操作中能同时辨认焦点目标与必要上下文，尤其是固定页头、吸底操作、错误定位和软键盘出现时。

## 名称、角色、值与描述

| 信息 | 应回答的问题 | 成员编辑示例 |
| --- | --- | --- |
| 名称 | 这是什么操作或字段 | “工作邮箱”“关闭成员编辑” |
| 角色 | 怎样操作这个对象 | 输入、按钮、对话框等实际语义 |
| 值与状态 | 当前内容和是否可操作 | 已填邮箱、无效、展开、忙碌 |
| 描述 | 有什么限制、如何修正 | 格式示例与保存规范化说明 |

名称不应堆入所有帮助文字，描述也不能代替名称。已有可见标签优先建立程序化关联；标签、错误和帮助使用稳定 ID。错误更新后关联仍有效，不因重新渲染出现重复 ID。多处同名操作要能结合对象区分，不能让整个列表只有一串“编辑”。

## 组合控件的键盘模式

下面是选型与验收目标，不是本次新增的组件能力。每种控件必须保持自身公开键盘模式，不能给所有容器统一套方向键。

| 控件 | 键盘目标 | 重要边界 |
| --- | --- | --- |
| 普通按钮与链接 | 保留原生激活与 Tab 路径 | 链接不能因 Space 行为不同被改成伪按钮 |
| Tabs | 方向键定位标签，激活模式一致 | 当前 Crab 水平标签处理左右、Home、End，并激活目标 |
| 选择器 | 定位候选、确认、关闭 | 焦点候选与最终选值区分；输入法期间不误确认 |
| 导航分组 | 独立展开控制，内部链接可达 | 收起项退出键盘路径，当前页状态保留 |
| 表格与树 | 按实际语义与能力提供导航 | 不能仅写 role 就声称实现完整 grid/tree 键盘模型 |
| 模态任务 | 焦点进入、在当前层内循环、关闭后恢复 | 下层和背景不同时响应 |

自动激活标签适合内容即时可用的情形，加载有明显延迟时应评审手动激活或预加载策略；当前组件是否支持该策略须另行确认。模式来源：[APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)、[APG Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)。APG 提供实现指导，不是独立的 WCAG 合规证明。

## 焦点恢复与非拖拽操作

模态打开时把焦点放在有意义的位置；长说明可从标题或内容起点开始，危险决策优先安全动作。关闭后恢复触发器，触发器已被删除时选择合理后继。嵌套确认取消后回到编辑层，不能直接落到背景页面。参见 [APG 模态对话框](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

可拖拽排序应提供单指针、不必拖拽的等价操作，例如“上移 / 下移”按钮或选择目标位置，并同时支持键盘。只有键盘快捷键不能自动满足“非拖拽单指针替代”。例外条件见 [2.5.7 Dragging Movements，AA](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)。现有拖拽组件是否全部提供替代入口需单独审计，本轮未迁移。

## 播报与人工验收记录

非焦点变化的结果、等待、进度和错误需要能被辅助技术识别，但不应同时从多个区域重复播报。使用何种状态角色取决于紧急程度；更新结果数通常无需抢焦点。见 [4.1.3 Status Messages，AA](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。

**正例**：错误就近显示并关联字段，提交失败定位首错，用户能读取限制、修正并再次提交。**反例**：红边框、全局消息和弹窗重复表达同一错误，却未关联字段。修正为一个主要错误说明路径，保留必要的摘要定位。

人工记录必须写明浏览器、系统、辅助技术、页面、初始状态、动作和结果。至少分别执行键盘完整流程、文字缩放、窄屏重排、强制颜色和减少动态效果；未具备的测试设备写为待验收。自动语义检查和对比度测试作为证据之一，不替代真实任务操作。
