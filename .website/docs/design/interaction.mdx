# 状态系统

> **落实状态：基础状态矩阵已提供可交互样板。** 本页的组合规则是组件验收依据；具体组件是否支持某个状态，需要以该组件的公开能力和真实任务为准。

## 状态是行为契约

用户看到状态后，应能判断：是否可以操作、操作会影响什么、系统是否已经接受请求、结果是否需要处理。视觉变化、文字、键盘行为和可访问语义必须指向同一个含义。

例如，“已选中”表示当前值已经成立，“已聚焦”仅表示键盘接下来作用于这里。“悬停”不能代替聚焦，“颜色变蓝”也不能代替真正的选择状态。

## 控件状态总表

| 状态 | 触发条件 | 视觉与文字要求 | 行为与语义 |
| --- | --- | --- | --- |
| 默认 | 可用且未交互 | 标签、边界和操作范围清楚 | 进入正常 Tab 顺序，使用匹配光标 |
| 悬停 | 指针进入可用目标 | 轻微背景或色阶变化 | 不改变值，不打开破坏性流程 |
| 按压 | 按钮处于有效按下过程 | 比悬停更明确的即时反馈 | 使用组件既有激活时机；不得重复提交 |
| 聚焦 | 键盘进入或程序定位 | 明显焦点环，不依赖阴影模糊区 | 焦点顺序与阅读顺序一致 |
| 选中 | 当前值、当前项或切换状态成立 | 文字、标记与容器反馈组合 | 使用适当的 checked、selected、pressed 或 current 语义 |
| 展开 | 触发器控制的补充内容可见 | 箭头方向与内容一致 | expanded 表示状态，controls 关联目标 |
| 只读 | 当前值可查看但不可编辑 | 保持阅读对比度，说明限制 | 文本值保留可达的阅读与复制路径 |
| 禁用 | 操作暂不可执行 | 使用禁用透明度，附近解释原因 | 不产生操作结果，取消 hover 和点击暗示 |
| 加载 | 请求已接受但尚无最终结果 | spinner / 骨架与“处理中”文字 | 标明 busy；限制重复操作，保留上下文 |
| 错误 | 当前值或操作结果不符合要求 | 文字说明、错误标记与可辨识边界 | 字段关联错误说明，保留可修复内容 |
| 空状态 | 集合无可展示内容 | 解释原因并提供相关下一步 | 与加载、失败和无权限明确区分 |

这些不是可随意切换的皮肤。文本输入不需要“按压后提交”状态，静态状态标签也不应伪装成 toggle。先确认控件角色，再覆盖适用状态。

## 状态如何组合

### 选中与悬停

鼠标进入已选中的行或按钮时，应保留选中标记和语义，再叠加轻微悬停反馈。移开鼠标后仍保持选中。不能让 hover 背景完全盖住选择状态，使用户误以为选择被取消。

### 错误与聚焦

错误边界说明当前值有问题，焦点环说明用户正在修复这个字段。两者应同时可见；错误说明与字段通过可编程关联连接。用户修改后，错误的清除时机必须与实际校验结果一致。

### 加载与禁用

提交已开始时，按钮呈现加载反馈，并阻止重复提交。仍显示原操作目标，例如“保存修改”变为“保存中”，而不是只剩一个无名称的转圈。焦点不要因按钮文字变化而被移到页面顶部。

### 只读与禁用

只读值仍可阅读、选择和复制，必要时仍能获得焦点；禁用操作则暂时不可执行。用户有查看权限但无编辑权限时，应保留值和限制说明，不应把整个区域淡到不可读。

## 状态转换顺序

| 场景 | 正常路径 | 异常路径与恢复 |
| --- | --- | --- |
| 按钮提交 | 可用 → 接受操作 → 加载 → 成功 | 加载 → 失败说明 → 允许重试 |
| 字段编辑 | 初始值 → 输入 → 校验通过 → 保存 | 输入 → 校验失败 → 就近修正 → 重新校验 |
| 数据查询 | 当前条件 → 加载 → 结果 | 加载 → 请求错误；成功但零项 → 空结果 |
| 编辑抽屉 | 摘要 → 编辑 → 保存 → 摘要更新 | 有未保存修改 → 关闭请求 → 继续编辑或确认放弃 |
| 选择列表 | 未选 → 当前页选择 → 批量操作 | 筛选或切页改变范围时，按明确规则清空或保留选择 |

状态改变后，必须让用户知道结果在哪。保存成功更新摘要，筛选完成更新计数，关闭弹层恢复焦点。不要只改变内部状态而没有任何可感知反馈。

## 焦点与输入方式

键盘焦点使用 focus-visible 等符合组件实现的机制，不以鼠标悬停代替。焦点环应围绕当前交互目标，和背景至少达到 3:1 的必要对比；本项目采用明显的实线轮廓作为验收目标，尺寸细则见 [无障碍](/design/accessibility)。

鼠标、触控和键盘应触发同一个业务动作，但不要求所有视觉反馈完全一样。触控没有持续悬停，任何依赖 hover 才能发现的关键按钮都需要常驻入口或等价替代。

## 错误、空数据与无权限

错误说明“本次操作没有按预期完成”，空结果说明“查询成功但没有匹配内容”，无权限说明“当前身份不能访问或执行”。三者必须使用不同文字和恢复动作。

搜索无结果应允许清除条件；首次无数据可以引导创建；请求失败可以重试；无权限应说明如何获取帮助。不要把这四种场景都写成“暂无数据”。

## 逐项验收

1. 使用 Tab、Shift+Tab 和组件支持的方向键访问全部可用控件。
2. 对选中控件悬停、移开，再聚焦，确认选择与焦点彼此独立。
3. 在错误字段上聚焦并修改，检查错误说明、边界和焦点同时有效。
4. 连续点击保存，确认只产生一次当前提交；失败后能明确重试。
5. 切换暗黑、紧凑与减少动态效果模式，确认状态含义不变。
6. 用长错误文字和窄屏检查控件位置不跳动，重要反馈不被裁剪。

## 状态组合矩阵

状态分为交互位置、业务值、可用性和数据结果四类。一个错误字段可以同时聚焦；一个已选对象可以暂时不可操作。不能用单个外观字符串覆盖所有维度。

| 组合 | 保留什么 | 限制什么 | 退出条件 |
| --- | --- | --- | --- |
| 选中＋悬停 | 选择标记、语义和范围 | hover 不覆盖选择 | 指针离开，只撤销 hover |
| 选中＋聚焦 | 选择与独立焦点轮廓 | 不把移动焦点当成选择所有项 | 焦点移动，值按控件模式决定 |
| 错误＋聚焦 | 错误说明与焦点 | 不因聚焦就假定已修复 | 实际校验通过再清错 |
| 只读＋聚焦 | 阅读、复制与位置 | 禁止编辑，不淡化全部正文 | 权限或任务状态改变 |
| 加载＋不可提交 | 操作名称、处理中反馈 | 重复提交及冲突操作 | 当前请求成功、失败或确认取消 |
| 选中＋不可操作 | 对象身份与选择范围 | 执行无权限动作 | 重新核对权限与选择有效性 |
| 展开＋子项加载 | 触发器、展开状态、区域反馈 | 不展示旧候选为新结果 | 数据返回或关闭 |
| 已有数据＋刷新失败 | 旧数据身份与失败说明 | 不伪装成最新成功结果 | 重试成功或用户改变条件 |

表中是设计契约；哪些组合能由组件直接表达，须核对公开能力。原生 disabled、只读和 aria-disabled 不是任意可替换的皮肤。aria-disabled 只说明语义，仍需实际阻止相关操作；原生禁用元素的焦点变化也需由任务流程处理。

## 事件接受、结果确认与重复操作

按钮反馈表示已经接收到输入，请求开始表示正在处理，业务成功必须有可靠结果。不要在请求发送时即显示“已保存”。网络超时后结果可能未知，不能无条件认定失败后直接重复产生不可逆操作。

| 阶段 | 页面应表达 | 示例 |
| --- | --- | --- |
| 输入已接受 | 即时按压或忙碌反馈 | “正在保存资料” |
| 处理未结束 | 当前任务、可继续做什么 | 保留草稿并限制重复提交 |
| 完成已确认 | 具体结果与最新内容 | 摘要展示保存后的资料 |
| 明确失败 | 失败范围、保留内容与恢复 | “资料仍保留，请重试” |
| 结果未知 | 需要核对状态 | “结果尚未确认，请先刷新状态” |

异步返回不能覆盖用户后来发起的查询或编辑。生产接入要定义过期结果和取消策略；当前本地样板未实现完整网络竞争机制。

## 状态与视觉反馈的边界

颜色职责见[色彩](/design/color)，尺寸见[布局](/design/layout)，焦点基线见[无障碍](/design/accessibility)。反馈可以增加内容高度，但不能通过改变边框宽度使原控件抖动；多行错误的自然重排是允许的。

鼠标悬停不应写入持久业务值；触控无需模拟持续 hover；键盘必须有独立位置线索。改变主题、密度或视口只改变表达，不应清空表单或更改已选范围。减少动画后仍保留全部最终状态。

**正例**：已选行出现刷新错误时保留选择信息，同时说明数据未更新并限制危险操作。**反例**：一失败就清空列表和选择，用户不知道哪些记录受到影响。修正需区分数据结果与用户选择，而非仅更换错误颜色。

## 状态验收记录

每个测试写出初始状态、触发动作、可见反馈、语义、焦点位置和最终业务值。至少验证一次连续操作、一次失败恢复以及一项组合状态。样板矩阵主要覆盖基础控件，结果未知、权限变化及复杂选择组合仍需后续业务接入验收。
