# 浮层与对话

> **规范状态：现有能力与设计要求并列。** Drawer / Dialog 当前基于原生模态 dialog；多层焦点、复杂草稿和业务取消策略仍需按场景验收。本页不新增浮层类型或属性。

浮层暂时提高一项信息或任务的优先级。使用前先判断：内容是否必须脱离原位置，用户是否需要保留背景上下文，以及关闭后应回到哪里。能在字段附近解释的问题，优先就近说明。

## 按任务选择浮层

| 形式 | 适用内容 | 与背景的关系 | 关闭与替代 |
| --- | --- | --- | --- |
| Tooltip 提示 | 简短补充解释，例如无文字图标的名称 | 不阻断背景，不承载必须操作的表单 | 悬停和键盘聚焦都可获得解释；重要信息常驻 |
| 菜单或下拉面板 | 选择命令、候选值或轻量条件 | 关联具体触发器，位置靠近触发器 | 选择完成或取消后回到明确位置 |
| Drawer 抽屉 | 查看详情、编辑对象，同时保留列表上下文 | 较大的补充任务区域；模态行为由具体组件决定 | 关闭回到原对象或触发器；脏数据需要处理 |
| Dialog 对话框 | 必须立即作出的决定、不可逆操作确认 | 暂停背景交互，聚焦一个决策 | 明确继续与取消的结果，避免含糊“是／否” |

不使用对话框报告每一次保存成功；不把多步复杂业务塞入一连串嵌套对话框。内容需要长期引用、浏览器历史或独立访问时，应考虑普通页面。

## 结构与文案

浮层的基本顺序是标题、必要说明、主体内容、操作区。标题说明对象与任务，例如“编辑成员资料”，而不是泛化的“提示”。关闭按钮具备可访问名称，且不能只靠不易识别的图形说明用途。

确认框必须说明操作对象、结果和可恢复性。例如“放弃未保存的修改？”应解释本次填写将被丢弃；操作使用“放弃修改”和“继续编辑”，让用户在不回读全文时也能判断。

### 操作区

主要操作放在稳定位置，内容滚动后仍能找到。存在取消路径时保留可见入口；关闭图标、取消按钮和 Escape 是否等价，必须按任务规则统一。不可逆操作与安全取消在视觉上可区分，但不能通过极低对比度隐藏取消。

浮层内部若还包含删除等另一项高风险任务，应先减少任务层级。确有必要的第二层确认只用于一个短决策，不再嵌套第三层。

## 打开、焦点与关闭

| 阶段 | 规范 | 当前样板对应 |
| --- | --- | --- |
| 打开前 | 触发器名称说明任务，维护与目标的程序化关联 | “编辑成员资料”打开编辑抽屉 |
| 打开后 | 将焦点放到有意义的位置；长说明可先聚焦标题 | 使用现有 Drawer 的焦点管理能力 |
| 编辑中 | Tab 顺序与视觉顺序一致；模态层内约束焦点 | 基本信息、团队、保存与取消 |
| 关闭请求 | 检查未保存修改与进行中的操作 | 未修改可直接关闭；有修改弹出确认 |
| 取消关闭 | 保留草稿并恢复到编辑上下文 | “继续编辑”关闭确认层 |
| 完成关闭 | 将焦点恢复到原触发器；触发器已消失时选择合理替代 | 返回成员资料入口 |

不要在浮层出现后立即把焦点放到危险确认按钮。对话框遮罩后方的内容不应仍可被键盘操作；背景滚动锁定与焦点约束需要同时验证。

### 未保存修改

“关闭”“取消”“返回”是否丢弃草稿必须保持一致。确认框应默认支持继续编辑，放弃后恢复上次保存值。单纯打开后直接关闭不需要确认；已保存完成后也不再重复提示未保存。

提交期间避免重复提交。当前样板在保存期间暂时禁用关闭与编辑，并提供“正在保存”状态；生产接入应为长请求提供超时、失败恢复或明确的取消策略，不能无限期锁住用户。

## 表面、主题与密度

抽屉和对话框属于浮层表面，候选圆角为 12px。边界表达容器范围，阴影表达与背景的层级关系。暗色模式按浮层表面角色配置，不能简单把浅色卡片加深阴影。

通过 Portal 挂载的内容可能位于样板 DOM 之外，因此必须同步主题、密度和必要的语义变量作用域。测试不能只看页面主体变暗；必须打开下拉、抽屉与确认框，逐层检查文本、表面、控件边界和焦点。

## 尺寸、滚动与触控

**现有 Dialog 范围**：默认最小宽度 520px、`useConfirm` 目标 22rem，均收敛到视口两侧各留 16px；短视口限制内容高度。顶部关闭按钮默认 32px、粗指针 44px，底部操作可换行，具体参数与覆盖方式见[Dialog](/components/rc-dialog)。异步操作由发起按钮显示 loading 并保留焦点，其他关闭路径受 pending 限制；这些落实情况不代表其他浮层已通过相同验收。

- 宽度由任务内容决定，并受视口约束。320px 下不能出现超出屏幕的操作区。
- 主体长内容在浮层内滚动；标题、关闭入口和主操作需要容易找到。
- 软键盘出现后，当前输入与错误说明应仍可见，不被固定操作区遮挡。
- 小关闭图标使用至少 44px 的触控目标；扩大命中区域不能覆盖邻近操作。
- 遮罩点击可关闭时，也要提供键盘等价路径；涉及草稿时遵守同一确认流程。

## 动效与无障碍

打开与关闭使用语义动效令牌，不能等待动画结束才更新可交互状态。减少动态效果模式移除非必要位移、缩放和淡入淡出，同时保留立即可见的层级变化。

Dialog 的标题、描述与角色应建立关联。Tooltip 不承载必须点击的交互内容；菜单不模拟普通文本列表。强制颜色模式下确保边界、焦点和关闭图形仍可识别，不依赖阴影区分层级。

## 关闭方式决策矩阵

| 任务状态 | 关闭图标、取消、Escape | 点击遮罩 | 关闭后的结果 |
| --- | --- | --- | --- |
| 只读详情 | 允许关闭 | 按现有能力与产品约定 | 回到来源对象 |
| 编辑且未修改 | 允许关闭 | 若启用则等价关闭 | 草稿无需确认 |
| 有未保存修改 | 进入统一确认流程 | 不能绕过草稿保护 | 继续编辑或明确放弃 |
| 正在保存 | 按请求契约限制或取消 | 不隐式终止请求 | 明确完成、失败或取消结果 |
| 高风险确认 | 安全取消路径可达 | 不能因误触执行确认 | 原对象保持不变 |

是否允许遮罩关闭应在设计记录中明确，不能假定所有浮层默认一致。当前资料样板在 pending 期间限制关闭，默认模拟保存会结束；生产服务需补齐长期等待、结果未知和恢复路径。

## 焦点进入与恢复位置

标题应说明当前任务，并与模态层建立名称关系。简单编辑可将焦点放在首个合理字段；长说明先让用户理解上下文，必要时聚焦标题。初始焦点不能为了缩短点击路径直接落到危险确认。

| 退出路径 | 焦点目标 | 内容状态 |
| --- | --- | --- |
| 取消只读详情 | 原触发器 | 背景数据不变 |
| 取消未保存确认 | 编辑层内合理位置 | 草稿保留 |
| 确认放弃修改 | 原编辑入口 | 恢复已保存值 |
| 保存完成后关闭 | 结果位置或原入口，依任务决定 | 摘要更新 |
| 来源行已删除 | 下一条记录或列表入口 | 不聚焦不存在节点 |

只有当前最上层模态接收操作。嵌套确认关闭不能释放编辑层的背景限制；所有浮层结束后再恢复页面滚动。实际原生焦点行为需在浏览器中检查，单元测试环境不能证明焦点循环与布局正确。

## 下拉、提示和长任务的边界

Tooltip 只补充短说明，不承载必须点击的控件或唯一错误信息。内容必须可操作时，选择适当的下拉面板、Dialog、Drawer 或普通页面；不能只把 Tooltip 放大成表单。

下拉与触发器建立可编程关系，并根据可视空间定位；向上打开时，视觉方向、焦点与滚动范围应清楚。触发器移除、滚动离开或候选失效时，需关闭或重新定位，不能遗留来源不明的面板。相关处理是否由现有容器提供，需核对组件能力。

需要独立地址、长期保存、分享或复杂多步骤导航的任务应优先使用页面。Drawer 保留背景上下文不等于适合任何大表单；内容不断增加时先复核任务边界。

## 表面、层级与响应式验收

浮层颜色与前景按[色彩](/design/color)配对，圆角与阴影按[形状](/design/shape)选用，动效实际来源按[动效](/design/motion)核对。Portal 不保证继承触发器样式，需实际打开各层检查主题与密度，而非只切换页面底色。

320px 下长标题可以换行，关闭按钮不能被挤出；长正文允许滚动，操作和必要风险说明必须可达。软键盘出现后能看到当前字段及错误。需要局部横向比较的内容可以局部滚动，不能让整个模态层超出视口。

**正例**：编辑抽屉中打开放弃确认，取消后回到草稿，背景列表始终受模态限制。**反例**：确认关闭时同时释放全部滚动锁，用户在仍打开的编辑层后滚动并点击列表。修正需按层管理生命周期与焦点。

## 验收清单

分别使用鼠标与键盘验证：打开、Tab 顺序、Escape、遮罩关闭、显式取消、未保存确认、继续编辑、放弃修改、保存中及保存失败。检查两层浮层的焦点恢复，以及明暗主题切换后已打开浮层的颜色。
