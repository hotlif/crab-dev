# 操作按钮

> **规范状态：组件设计规则与现有能力映射。** 复用 Button；本页不新增公共 Props。视觉尺寸指设计样板的令牌覆盖，不等于整个组件库的默认尺寸。

> **本轮实现范围**：本轮 Button 已补充公共焦点、强制颜色边界、粗指针下至少 44×44 CSS px 的独立操作目标，并在 loading 时拦截激活和表单提交。默认加载保持前景与背景可读；旧透明度变量继续有效。源码修改不等于完整交互验收，包内 React 测试与生产复测结果需分别记录。

## 作用与结构

按钮执行动作，链接导航到目标。按钮结构由容器、文字、可选前置图标、可选后置图标和状态反馈组成。文字说明结果，图标辅助识别，容器表达强调程度与命中范围。

有明确目标地址的导航使用链接语义，保留复制链接、修饰键和浏览器前进后退能力。提交、展开确认和修改数据使用动作语义，不能仅因需要下划线就把动作伪装成链接。

## 变体与选择

| 设计层级 | 现有能力 | 适用场景 | 限制 |
| --- | --- | --- | --- |
| 主要操作 | primary | 当前任务的提交、保存、创建 | 同一操作组通常只有一个主要按钮 |
| 常规次要操作 | 默认外观 | 取消、返回、普通工具栏操作 | 不与主操作竞争 |
| 轻量次要操作 | subtle / text | 卡片内辅助动作、低风险快捷操作 | 仍需清楚的可点击线索 |
| 文本链接 | link 或带目标地址的链接能力 | 查看详情、跳转其他页面 | 文案必须说明目的地 |
| 危险操作 | danger | 删除、撤销不可恢复的结果 | 仍需确认范围或提供撤销 |
| 特定占位动作 | dashed | 有清楚场景含义的补充入口 | 不作为通用“次要”替代 |

这些是 Crab 现有变体与任务层级的映射，不应照搬其他设计系统的变体名称作为新的组件属性。使用主要填充按钮前，先确认它是否真的是用户当前最需要完成的动作。

## 尺寸与排列

标准视觉高度 36px，紧凑 28px，控件圆角 6px；触控目标至少 44px。相邻按钮采用统一高度、标签字号与图标尺寸。按钮宽度优先由内容和内边距决定，成组时再按场景决定是否等宽。

表单中的次要动作与主要动作应有稳定顺序。桌面可横向排列，窄屏可以换行或堆叠；不允许换行后把“删除”放到原来“保存”的位置造成误触。图标按钮的可访问名称和目标尺寸分别验收。

## 状态与提交

默认、悬停、按压和聚焦使用一致的反馈节奏。禁用时取消 hover 和操作结果，并解释无法继续的条件。表单内非提交按钮应明确使用非提交类型，避免“取消编辑”触发保存。

异步动作接受后显示加载状态并限制重复提交。按钮宽度应保持稳定，文字继续说明目标。加载失败后恢复明确的可用状态，保留用户内容并给出重试路径；成功后更新任务结果，不能只有一条很快消失的消息。

## 危险操作

删除前明确对象、数量和影响。例如“删除 3 个项目”比“确定操作吗”更可评估。不可逆操作复用确认框或提供可靠撤销；确认按钮名称重复具体动作，不使用含糊的“是”。

不要默认聚焦高风险确认按钮以求操作更快。风险信息、取消入口和受影响范围必须可读，确认框关闭后回到原操作上下文。危险按钮不应用于普通错误提示或常规取消操作。

## 键盘与可访问性

保留按钮和链接的原生激活方式。焦点环独立于 hover，禁用与加载不能制造键盘陷阱。图标按钮提供可访问名称；与展开内容关联的触发器应准确表达展开状态与目标关系。

如果业务必须保留不可用动作的可发现性，需要明确实现“可感知但不可执行”的行为，而不是只添加 aria-disabled 后仍让点击执行。优先使用组件已有禁用能力，特殊工具栏行为单独验收。

## 使用禁例与验收

- 同一组出现多个颜色和权重相同的“主要”按钮，无法判断下一步。
- 按钮标签写“查看”，实际立即提交或删除数据。
- 加载时只剩无名称的 spinner，或仍允许连续提交。
- 只有鼠标悬停后才出现某个关键操作。
- 为了窄屏容纳更多操作，把触控目标缩小到图标本身。

## 从任务选择操作形态

| 决策问题 | 选择 | 需要记录 |
| --- | --- | --- |
| 是否到达一个可访问地址 | 使用 Button 的链接能力或真实链接 | 目标、当前页或新窗口、返回上下文 |
| 是否改变当前值或提交任务 | 使用动作按钮 | 影响对象、处理结果、失败恢复 |
| 是否是当前任务唯一主要结果 | primary | 为什么优先，其他操作如何降低强调 |
| 是否不可逆或影响范围较大 | danger，并确认或提供可靠撤销 | 对象数量、后果和安全返回路径 |
| 是否只是补充操作 | 默认、subtle 或 text 等既有能力 | 入口仍可发现，不能只在 hover 可见 |

一个页面可以包含多个独立任务区，但同一操作组应有明确主次。“保存修改”与“删除成员”不应以同等填充并排争夺注意力；删除可以移到对象管理区或次要操作区，仍保持可发现和明确后果。

默认外观对应未指定 appearance，不能把文档中的“默认”反推成一个新的字符串属性。具体值以现有 Button 类型为准。大小和圆角的设计来源见[布局](/design/layout)与[形状](/design/shape)，不新增通用 density API。

## 按钮组与响应式结构

单个按钮依次包含前置图标、标签、可选后置图标或状态。只在图标增加识别价值时使用；加载占位应保持相近空间，避免同组按钮整体左右跳动。

操作顺序在同一业务产品内保持一致，按任务和平台约定确定后，不因窄屏而交换 DOM 顺序。当前成员样板为“保存修改、取消编辑”；若未来业务采用其他顺序，应全流程一致并单独评审，而不是用 CSS 视觉反转。

| 场景 | 排列目标 | 窄屏处理 |
| --- | --- | --- |
| 表单页脚 | 紧随受影响字段，主次清楚 | 整组换行或堆叠，保留完整文案 |
| 列表工具栏 | 查询、全局动作、批量动作范围清楚 | 分行并保留选择摘要 |
| 表格行内 | 靠近对应记录 | 收纳次要动作时仍提供可达入口 |
| 对话框 | 决策和安全取消都可见 | 不裁切风险说明和取消操作 |

图标按钮的视觉图形和实际命中区域分别验收，详见[图标](/design/icons)。不能通过扩大透明区域覆盖邻近删除动作。

## 提交与危险操作契约

| 阶段 | 操作表现 | 内容与焦点要求 |
| --- | --- | --- |
| 可提交 | 标签说明动作 | 输入与约束已可读 |
| 提交已接受 | 立即显示加载或处理反馈 | 保留上下文，限制重复提交 |
| 成功 | 更新实际对象内容 | 结果可复核，按任务决定是否关闭 |
| 明确失败 | 恢复可重试状态 | 保留输入，定位错误或区域说明 |
| 结果未知 | 引导核对状态 | 不诱导连续重复不可逆操作 |

Button 的 loading 用于表达处理状态，不替代业务层防重与结果确认。确认框也不负责校验权限或保证服务端幂等。异步操作是否能取消由真实请求契约决定，不因界面有一个“取消”按钮就声称已经取消服务端任务。

删除确认应包含对象身份、数量、范围和可恢复性。“删除 3 个项目”必须对应实际选择，不允许进入确认后偷偷扩大为全部筛选结果。权限或对象状态变化时，重新说明可执行范围；不能沿用旧确认文本处理新对象。

## 键盘与不可用原因

表单内辅助动作明确非提交语义。原生按钮按其原生激活方式工作，链接保留浏览器导航能力；不要统一拦截 Space 模拟所有链接。展开动作有 expanded 和 controls 关系，切换动作使用适合其值的语义，普通保存按钮不伪装为可切换按钮。

禁用原因置于可读的相邻位置。若业务需要不可执行动作仍可聚焦，应确认组件能表达该模式并实际拦截操作；不能只加 aria-disabled。当前组件未提供的焦点策略列入差距，不由文档发明新属性。

**正例**：“保存修改”接受后显示“正在保存”，失败保留字段，成功回写摘要。**反例**：点击后仅图标旋转，按钮仍重复发请求，最后显示三条成功消息。修正为统一处理状态和业务防重，保留操作名称。

专项验收：鼠标、Enter、Space 按对应语义激活；连续提交只接受当前有效任务；加载前后组内布局稳定；长标签在 320px 可读；取消和危险确认范围一致；深色、强制颜色和减少动画下状态仍成立。

交互状态可在 [状态样板](/design/interaction) 体验，组件完整 API 位于 [Button 文档](/components/rc-button)。本章只定义视觉语言与使用规则。
