# 色彩与主题

> **落实状态：公共基元与主题映射已实现；全组件视觉复测进行中。** 紫色来自公共 L1 `purple`，明暗配对由 L2 `themeColorContract` 定义，文档站、工作台与公共主题消费同一来源。基础值测试通过不代表所有业务组合已经验收。

## 颜色首先表达用途

先确定“这是什么角色”，再选择具体色阶。主要操作、链接、焦点、选中和成功虽然都可能需要强调，但不能共用一个没有语义的“高亮色”。基准紫色用于行动引导；选中容器使用低强调紫灰色，成功、警告、错误和信息各自承担独立反馈语义。

参考来源为 [Material Web v0.192 基准色板](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-ref-palette.scss)和[色彩角色映射](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-sys-color.scss)。这是固定色板，不根据壁纸、图片或设备动态取色。

背景与文字必须成对选择。仅标注“Primary 40”还不够，必须同时说明其上的文字、悬停、按压和暗黑模式。下表用 sRGB 十六进制值方便设计工具核对；样板色卡直接读取源码中的 OKLCh 令牌。

## 品牌与选中配对

| 角色 | 浅色主题 | 暗黑主题 | 使用场景 |
| --- | --- | --- | --- |
| 主要操作背景 | Primary 40 · #6750A4 | Primary 80 · #D0BCFF | 提交、保存、创建等主要按钮 |
| 主要操作悬停 | Purple 30 · #4F378B | Purple 90 · #EADDFF | 鼠标进入可用按钮 |
| 主要操作按压 | Purple 20 · #381E72 | Purple 100 · #FFFFFF | 按下期间的即时反馈 |
| 品牌背景上的文字 | #FFFFFF | #381E72 | 与默认、悬停、按压三种背景配对 |
| 选中容器 | Purple 90 · #EADDFF | Purple 30 · #4F378B | 导航当前项、选中行或选择区域 |
| 选中容器上的文字 | Purple 10 · #21005D | Purple 90 · #EADDFF | 保持选中内容可读 |
| 主色容器 / 其上文字 | #EADDFF / #21005D | #4F378B / #EADDFF | 需要品牌归属的低强调内容块 |
| 焦点指示 | #6750A4 | #D0BCFF | 清楚的实线轮廓，不能仅靠浅色阴影 |

主要按钮可以有强填充；普通内容卡片不应为了“体现品牌”全部铺满紫色。选中容器与主按钮也不能互换：前者说明当前状态，后者提示可执行动作。

品牌悬停与按压采用明确的色阶映射，中性操作使用公共 hover-subtle / active-subtle 表面。链接通过颜色和下划线等已有意符反馈；焦点轮廓独立存在。旧站点的 8% / 12% 混色值保留为参考参数，已不作为当前主题的状态生成规则。不得把参考系统的混色公式套用到所有组件。

## 文本、表面与边界

| 角色 | 浅色主题 | 暗黑主题 | 使用说明 |
| --- | --- | --- | --- |
| 画布 / sunken | Zinc 50 | Black | 页面最底层、顶部与正文背景 |
| 内容表面 / surface | White | Zinc 950 | 卡片、列表、代码容器和表单分组 |
| 浮层表面 / elevated | White | Zinc 900 | 搜索、抽屉、对话框和下拉 |
| 主要文字 | Zinc 950 | Zinc 50 | 标题、字段值、核心数据 |
| 次要文字 | Zinc 700 | Zinc 300 | 帮助、元信息和时间 |
| 辅助文字 | Zinc 600 | Zinc 400 | 小字仍需足够对比度 |
| 必要控件边界 | Zinc 600 | Zinc 500 | 输入等控件的可识别轮廓 |
| 装饰分隔 | Zinc 200 | Zinc 800 | 已能通过布局识别的内容间隔 |
| 中性悬停 / 按压 | Zinc 100 / 200 | Zinc 900 / 800 | 可操作对象的即时反馈 |

本表使用公共基元名称，精确 OKLCh 值见[全局令牌](/components/rc-token-global#颜色)。浅色内容与浮层可以同为白色，依靠位置、必要边界和阴影表达层次；不为区分每一层而增加紫色底板。深色表面逐层抬升明度。不要简单反相背景，也不要用白字搭配深色主题的淡紫按钮。

## 功能反馈的语义

| 状态 | 必须同时提供的线索 | 不适合的表达 |
| --- | --- | --- |
| 成功 | 已完成的文字或确认图形，并指明完成对象 | 仅把原文字变绿 |
| 警告 | 风险、影响范围，以及可继续或取消的动作 | 用警告色装饰普通提示 |
| 错误 | 失败原因或可执行的修复步骤 | 只显示红色边框或内部错误码 |
| 信息 | 当前事实、限制或补充条件 | 与错误同等强烈的中断提示 |

错误使用公共 Red 反馈配对：浅色文字 Red 800、背景 Red 50；深色文字 Red 300，背景为 Red 500 与 Zinc 950 的 18% Oklab 混合。实心危险按钮以 Red 600 / White 配对，悬停和按压分别为 Red 700 / 800。全部反馈角色由 L2 契约维护，组件不能只取背景而丢失其前景。

成功、警告和信息继续使用现有 Green、Amber、Blue 功能色，分别提供背景、文字、图标、边界、实心按钮及其前景配对。这些是 Crab 的功能色扩展，不能声称属于 Material 基准色板。

反馈色必须使用相应的背景、文字、图标角色组合。状态标签应同时包含文字，例如“进行中”“待启动”“已完成”；图标只是补充，不替代文案。

## 叠加状态与对比度

文字至少满足 4.5:1，必要图形、控件边界和焦点至少满足 3:1。本项目正文统一使用 4.5:1 作为设计门槛；不能因字号较大就自动降低所有标题的可读性要求。关于标准中的例外与适用范围，参见 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

对比度检查必须覆盖最终组合：选中行上的文字、按压按钮上的文字、浮层中的说明，以及半透明颜色与实际背景混合后的结果。单独检查一对色板色值，不能证明所有叠加场景合格。

禁用态与正常态分别验收。使用禁用透明度后，不应再叠加一层灰度滤镜反复淡化；用户仍需要在附近读到禁用原因。

## 主题切换与浮层

顶部主题与样板主题使用同一个站点状态。切换主题不能清空输入、改变选中含义或让已打开的浮层保持旧主题。下拉、抽屉和确认框必须消费当前主题和密度，而不是依赖根节点偶然继承。

在脱离站点上下文展示样板时，样板使用本地主题状态。正常页面仍由站点负责“浅色、深色、系统”偏好及刷新记忆。首次访问默认跟随系统；已手动选择的主题不会因本轮配色调整而被清空。选择“系统”后，系统明暗变化应同步到已打开页面与浮层。

## 推荐、禁例与验收

- 推荐：一个工作区只有明确的主要操作；其余操作使用较低强调变体。
- 推荐：用真实长文本、选中行和浮层检查明暗配对。
- 避免：把品牌色同时当作成功色、警告色和所有图表序列色。
- 避免：用装饰分隔色作为输入框唯一的可识别边界。
- 验收：两种主题、三种按钮状态、三层表面与强制颜色模式均有检查记录。

## 角色选择的执行顺序

1. 确定对象是内容、操作还是反馈。静态项目状态首先是信息，不因采用紫色就获得按钮行为。
2. 确定所在表面：画布、内容、浮层。先选背景，再选对应前景，最后检查边界与图标。
3. 确定基础状态和组合状态。选择、聚焦与错误可以同时存在，颜色不能互相抹除各自含义。
4. 将配对映射到已有语义角色。没有适合的角色时登记候选，不能在业务页中挑一个“差不多”的色值。
5. 检查明暗两套最终组合；透明度、遮罩及状态层必须参与计算。

| 视觉对象 | 角色选择 | 必须保留的非颜色线索 |
| --- | --- | --- |
| 保存、创建等主要动作 | 品牌背景与 on-brand 前景 | 动词标签、按钮轮廓与可操作状态 |
| 当前导航、已选数据行 | selection 背景与前景 | 当前项语义、选择标记或位置指示 |
| 输入框 | 内容表面、正文、必要边界 | 常驻标签、可辨识输入范围 |
| 字段错误 | error 文字与相应边界 | 错误原因、修正方式和字段关联 |
| 保存结果 | success 的背景、文字、图形配对 | 对象名称与完成结果 |
| 次要说明 | secondary / tertiary 文字 | 稳定位置；不能仅凭灰色表示“不重要” |

装饰边界只服务已经可以通过结构理解的分组。若移除边界就无法知道哪里可输入，该边界属于必要控件轮廓，不能使用装饰分隔的低强调角色。

## 颜色在状态组合中的职责

| 组合 | 前景与背景处理 | 验收条件 |
| --- | --- | --- |
| 已选中后悬停 | 保留选择底色和标记，只增加适度反馈 | 移开指针仍能识别选中 |
| 错误字段聚焦 | 保留错误文字和边界，另呈现焦点轮廓 | 能同时识别问题与当前输入位置 |
| 加载中的主按钮 | 保留主操作归属，显示文字及加载图形 | 不因淡化而无法判断正在处理什么 |
| 禁用 | 采用禁用透明度，不重复叠加灰度 | 原因说明位于正常可读的相邻区域 |
| 只读 | 保留正常阅读前景，降低编辑暗示 | 值仍可读；需要复制时有可达路径 |
| 选中行包含错误 | 选择底色与错误文字各司其职 | 不把整行涂红而掩盖当前选择 |

状态组合不以统一百分比代替设计决定。错误、选中、禁用与遮罩分别使用自己的语义角色；L3 如需混色必须说明参与颜色和所在表面。具体可执行性和转换规则以[状态系统](/design/interaction)为准。

## 图表与数据颜色

分类颜色用于区分不同对象，顺序颜色用于表达有序量级，发散颜色用于表达相对于明确基准的两侧。三种编码必须在图例或文字中解释；品牌色只适合单序列强调或突出一个重点，不是多系列的全部答案。

同一业务对象跨图表保持相同含义，排序变化不应让“工程研发”从紫色变成绿色。新增类别无法获得可区分颜色时，优先增加标签、线型或分图，不无限添加相近色。这里规定使用方式，尚未新增公共图表分类色板。

“上升”是否有利由指标决定：成本上升不能仅因为正数就自动显示成功绿。需要同时说明指标名、比较周期、数值与趋势。必要的数据图形及直接标签按照无障碍章检查；图表还应提供关键结论或数据阅读替代，不能要求用户只凭色块估值。

## 参数来源与核对边界

- 原始色板来自 `rc-token-global/token.toml`，Purple 七档保留 Material Web 基准值的 sRGB 等价性；中性与反馈继续消费现有 Zinc / Red / Green / Amber / Blue。
- `rc-token-semantic/src/theme.ts` 是明暗配对的公共来源；`rc-theme` 负责输出 CSS 覆盖。站点 `palette.ts` 只提供展示别名，`paletteStyles.ts` 仅绑定站点专用阅读变量。
- 原始色、主题角色、混合后的状态色应分别记录。功能反馈沿用全局 Green / Amber / Blue 扩展，不能标注成 Material 固定基准色。
- 透明图标叠在选中底色上时，检查实际合成结果；不能用原始图标色和白色背景的结果代替。

## 场景对照与专项验收

**正例**：成员编辑的错误信息在字段下常驻，聚焦时仍保留错误说明；暗色模式按钮同时替换背景和文字角色。**反例**：只把页面背景变黑，保留白色主按钮文字，导致淡紫按钮无法阅读。修正时按配对更换前景，而非单独提高饱和度。

依次检查正文、辅助说明、选中行、主按钮默认/悬停/按压、错误字段、打开的浮层。每个记录包括主题、状态、最终前景、背景和测量结果。关闭颜色显示或用强制颜色模式复核后，关键状态仍应可由文字、形状和语义识别。对比度的标准等级、例外及测量条件统一见[无障碍与键盘](/design/accessibility)。
