# 界面文案与信息

> **规范状态：Crab 中文界面写作规则。** 本页用于设计和评审；不会自动改写现有组件中的所有文字。

## 语气与基本原则

文字应直接说明事实、动作和结果。用户在处理工作，不需要被责备、被教育或被模糊的系统术语打断。短句优先，但不能为追求简短省略对象、范围或后果。

同一个概念使用同一个名称。“项目”“任务”“记录”如果是不同对象，就不能在按钮、标题和错误提示里交替使用。业务术语首次出现时给出解释；面向用户的文案不暴露实现细节、内部异常栈或组件属性名。

## 操作标签

| 场景 | 推荐写法 | 避免写法 | 原因 |
| --- | --- | --- | --- |
| 保存当前编辑 | 保存修改 | 确定 | 明确结果是保存当前草稿 |
| 创建对象 | 创建项目 | 新增 | 指明将创建什么 |
| 破坏性操作 | 删除 3 个项目 | 是 / 好的 | 说明动作与范围 |
| 恢复查询 | 清除筛选 | 重置全部 | 避免误以为清空业务数据 |
| 继续编辑 | 继续编辑 | 否 | 回答用户接下来会做什么 |
| 重试失败操作 | 重试加载 | 再来一次 | 明确重复的任务 |

按钮以动词开头，导航以地点或对象命名。不要把“查看详情”写在实际会立即修改数据的按钮上，也不要用“返回”表达放弃草稿。

## 字段标签与帮助

标签说明填写内容，例如“工作邮箱”；帮助文字解释格式、用途或限制，例如“用于接收项目通知”。占位提示只给示例，不代替标签。必填字段使用清楚的必填约定，选填项同样保持一致表达。

帮助信息应出现在输入之前或附近，避免等用户提交失败后才告诉他长度限制。字数统计应说明单位；范围、时区和金额单位不能藏在工具提示里。

## 错误信息的结构

好的错误信息包含可以理解的原因和下一步。字段错误通常不需要标题，直接写“请输入有效邮箱，例如 lin@example.com”。全局请求错误可以分为“加载失败”和“请检查网络后重试”，并保留重试入口。

服务端不能确定具体原因时，不编造诊断。可以说明“暂时无法保存，修改内容已保留，请稍后重试”。不要写“操作有误”“非法输入”来暗示用户做错了什么，也不要只显示错误编号。

## 状态、计数与结果

状态文字使用稳定名称，例如“待启动”“进行中”“已完成”。列表计数说明范围：“共 12 项 · 已选 5 项”与“当前页 5 项”不是同一个口径。跨页选择必须明确写出“全部筛选结果”，不能只让勾选框看起来全选。

金额、日期、百分比和单位遵循统一格式。未知值不等于 0，尚未计算不等于失败；分别使用“未设置”“计算中”“计算失败”等清楚文字。

## 空页面与权限说明

首次无数据可以写“尚无项目”，并提供“创建项目”；筛选无结果写“没有匹配的项目”，并提供“清除筛选”；请求失败使用错误说明；无权限解释访问限制与求助方式。

不要把所有空白都描述为“暂无数据”，也不要在用户没有创建权限时给出无法完成的创建引导。空页面中的插图和幽默文案不能妨碍理解下一步。

## 长度、本地化与验收

常用按钮应保持简短，但不设置会改变业务含义的硬性字数目标。设计需要容纳较长对象名称、翻译文案和文字放大；错误说明允许多行，导航名称不能只为对齐而改成难懂缩写。

评审时把标签读成完整句子：“点击这个按钮后，会……”。如果句子说不清结果，先改文案，再调整图标。检查禁用原因、确认框、成功反馈是否沿用同一个对象名与操作范围。

## 信息结构与用词职责

界面文案分为名称、动作、约束、状态和恢复五类。先确定文字承担的职责，再决定长度与位置。同一个任务从入口到成功必须沿用相同对象名，“成员”不能在确认框突然变成“用户账号”。

| 位置 | 必须包含 | 通常不包含 |
| --- | --- | --- |
| 页面或区块标题 | 对象、任务或范围 | 泛化的“欢迎使用”、实现细节 |
| 操作按钮 | 明确动作，必要时带对象 | 模糊的“确定”“处理一下” |
| 字段标签 | 稳定的数据名称 | 大段用途说明、只有示例的文字 |
| 帮助文字 | 格式、单位、限制或用途 | 尚未发生的错误指责 |
| 错误说明 | 已知问题与下一步 | 编造原因、内部堆栈 |
| 完成结果 | 对象、动作和实际结果 | 尚未确认的最终成功 |

“保存”保留修改，“提交”把任务交给后续处理，“发布”使内容进入更广可见范围，“删除”改变对象存在性。这些词不能只按按钮宽度替换。涉及不可逆后果时，入口、确认按钮和结果文案重复同一动作及范围。

## 任务生命周期文案表

| 阶段 | 推荐表达 | 不推荐表达及原因 |
| --- | --- | --- |
| 编辑入口 | 编辑成员资料 | 修改：缺少对象 |
| 保存中 | 正在保存资料，请稍候 | 操作成功：尚无结果 |
| 保存成功 | 已保存林晓的资料 | 完成：无法确认完成什么 |
| 明确失败 | 保存未完成，资料仍保留，请重试 | 非法操作：指责用户且无法恢复 |
| 结果未知 | 保存结果尚未确认，请先检查最新状态 | 保存失败，请再点一次：可能重复写入 |
| 脏数据关闭 | 放弃未保存的修改？ | 确定关闭吗：未说明数据后果 |
| 确认选择 | 放弃修改 / 继续编辑 | 是 / 否：离开问题无法理解 |
| 批量结果 | 已处理 8 项，2 项未完成 | 全部成功：掩盖部分失败 |

样板保存为本地模拟，说明必须保留“仅本页”范围；真实产品的发送通知、修改权限等后果不能从样板文案中推导。后台任务“已提交”只表示接收，不表示所有记录已处理。

## 约束、字数和输入帮助

必填与选填采用一致约定，格式限制在输入前可见。长度需要说明计数单位；当前姓名样板使用 JavaScript 字符串 length 与原生 maxLength，emoji 等可能按多个 UTF-16 代码单元计数，因此“30 字”不是所有 Unicode 字符都按一个可见字形计数的保证。生产接入应明确产品计数规则，并让界面与服务端一致；本轮不修改样板计数逻辑。

帮助说明宜按“为什么需要 / 怎么填写”组织。错误应指出当前可修复的问题，不每次输入一个字符就展示最终格式错误。错误替换帮助文字时，必需的单位和约束仍要能获取，不让用户为修错失去格式依据。

## 数量、范围与数据语义

| 表达对象 | 应写清的信息 | 示例 |
| --- | --- | --- |
| 搜索 | 匹配字段与当前范围 | 搜索项目名称、编号或负责人 |
| 选择 | 当前页或所有筛选结果 | 当前页已选 3 项 |
| 统计 | 周期、数据范围和单位 | 本月预算 / 元 |
| 刷新 | 当前数据是否最新 | 更新失败，仍显示上次结果 |
| 未知值 | 未设置、未计算或无法读取 | 未填写，不以 0 代替 |
| 权限 | 哪项能力不可用及求助路径 | 当前账号无编辑权限，请联系管理员 |

金额、日期、百分比的展示格式以[字体与排版](/design/typography)为准。文案只陈述已知事实：没有权限不等于数据不存在，筛选无结果不等于系统为空，网络异常也不一定能定位为用户断网。

## 空状态与权限的完整句式

首次无数据：“尚无项目”，说明这里将展示什么，并在有权限时提供“创建项目”。筛选无结果：“没有匹配的项目”，说明可调整条件，提供“清除筛选”。权限不足：“无法查看成员资料”，说明申请路径，不展示无法执行的创建引导。

删除后对象不存在时，提供返回有效位置的入口；不要让重试成为永远不会成功的唯一动作。暂时禁用的操作应把原因放在可读位置，不能只藏在禁用按钮的 Tooltip 内。

## 文案对照与验收

**正例**：“删除当前页已选的 3 个项目”，确认正文说明不可恢复，取消入口为“保留项目”。**反例**：“清空全部”实际只清除筛选，用户担心数据被删除。修正名称为“清除筛选”，并保持重置后对象数据不变。

逐条把按钮读成“点击后将……”，把状态读成“当前……，接下来可以……”。若无法完成句子，说明对象或后果缺失。长名称、翻译长度翻倍、多行错误与文字放大后仍要表达完整范围；不能通过截掉“全部”“未保存”“不可恢复”等关键限定词保持整齐。

文案是设计要求，具体规范化、权限和持久化由业务契约确定；错误模板不可替代真实错误分类。术语和对象名由同一任务维护，跨章引用不另造同义词。
