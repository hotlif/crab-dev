# 反馈与等待

> **规范状态：反馈选型与生产流程要求。** 本地样板用于观察基本状态，网络超时、结果未知、通知追溯等不代表已实现能力。

反馈回答三个问题：系统是否收到操作、现在处于什么阶段、用户接下来可以做什么。反馈应贴近作用对象；只有需要用户立即作出决定时，才打断当前任务。

## 选择合适的反馈强度

| 方式 | 适用信息 | 持续与打断程度 | 使用要求 |
| --- | --- | --- | --- |
| 字段帮助或错误 | 单个输入的格式、范围、必填问题 | 常驻字段附近，不打断 | 与字段关联，指出如何修正 |
| Alert 区域提示 | 当前区域的异常、限制或重要成功结果 | 随上下文保留 | 标题说明情况，正文说明影响和下一步 |
| Message 轻提示 | 操作已完成等简短结果 | 短暂出现，不抢焦点 | 关键结果还应在对象本身反映，不能只依赖瞬时消息 |
| Notification 通知 | 与当前区域关联较弱、值得稍后查看的事件 | 可关闭或进入详情 | 控制数量，提供可追溯入口 |
| Spin / Skeleton | 已收到请求，内容尚未就绪 | 在等待区域出现 | 说明正在做什么；骨架尽量对应真实布局 |
| Empty 空状态 | 当前数据区域没有内容 | 保留到条件变化 | 区分初次使用与无匹配结果 |
| Dialog 对话框 | 必须由用户决定才能继续 | 阻断当前任务 | 用于决策，不作为常规成功反馈 |

这里是设计选型规则。各反馈组件的具体支持能力以现有公开 API 为准；未在样板演示的组合需在后续迁移时单独验证。

## 等待的时间与范围

按钮按下后应立即显示接收反馈，不等待网络响应才改变外观。预计超过约 400ms 的操作提供可见等待信息与忙碌语义；这是本项目的体验约定，不是要求所有操作延迟 400ms 再显示反馈。

| 场景 | 建议反馈 | 允许继续的操作 |
| --- | --- | --- |
| 保存单个表单 | 提交按钮加载状态，表单附近说明正在保存 | 不重复提交；是否允许取消由请求语义决定 |
| 首次读取列表 | 表格区域的加载状态或骨架 | 保留可识别的页面标题与查询上下文 |
| 更新已有数据 | 原数据可保留，并明确标注正在刷新 | 防止用户将旧数据当作更新结果执行危险操作 |
| 长任务 | 有实际依据的进度与阶段说明 | 支持离开后查看或取消时，清楚告知后果 |

没有真实进度时使用不定进度，不能虚构百分比。加载图形不替代“正在读取项目”等文字。对于极短请求，避免闪烁的全屏遮罩；不能为展示动画而人为阻塞任务。

## 成功反馈

成功必须建立在操作实际完成之后。显示具体对象与结果，例如“已保存林晓的资料”；只在本地演示的数据应说明作用范围，不能暗示已经同步到服务器。

轻量成功不抢焦点，也不自动打开对话框。对象内容应同步更新，让用户关闭提示后仍能确认结果。涉及异步后台任务时，“已提交”与“已完成”必须区分。

## 错误、警告与恢复

### 错误的三段信息

1. 发生了什么：用用户理解的对象描述失败。
2. 影响是什么：哪些内容没有保存、哪些数据仍然可用。
3. 如何继续：修改字段、重试、调整条件或联系相关人员。

例如“保存未完成，资料仍保留在表单中，请重试”比“未知错误”更有帮助。错误码可作为可复制的补充信息，不作为主文案。不能泄露内部堆栈、凭证或与用户无关的系统细节。

### 就近处理与保留上下文

字段错误放在字段附近，首次提交失败后定位首个错误。区域读取失败在区域内说明并提供重试；不要清空用户已经输入的草稿。重复失败时保留已有条件，避免用户再次完成全部前置步骤。

警告用于仍可继续但需要了解的限制，错误用于当前操作无法完成。两者不能只用黄与红区分，还要通过标题、图形和文案说明严重程度。

## 空状态分类

| 状态 | 解释重点 | 下一步 |
| --- | --- | --- |
| 首次使用，没有记录 | 此处将呈现什么内容，如何开始 | 有权限时提供创建入口 |
| 搜索或筛选无匹配 | 当前条件没有命中，不代表系统没有数据 | 修改关键词、移除筛选或重置 |
| 没有访问权限 | 当前账户无法查看该内容 | 说明获取权限的可行路径 |
| 读取失败 | 数据是否存在尚不确定 | 重试；必要时提供帮助入口 |
| 内容已删除或不可用 | 原对象无法继续访问 | 返回有效列表或其他可用位置 |

权限不足与读取失败不能伪装成普通“暂无数据”。空状态插图只是辅助，标题、说明与必要操作必须独立成立；不为简单表格空结果增加大面积装饰。

## 状态播报与动态效果

非紧急的保存进度、结果数与成功信息使用适度的状态播报；需要立即修正的错误可采用警报语义。不能同时在多处重复播报同一句话，也不能每次输入字符都强制打断读屏。

动态反馈不移动用户焦点，除非任务流程需要定位错误或进入模态对话。减少动态效果模式可以停止旋转与脉冲，但“正在处理”的文字与忙碌状态仍需存在。强制颜色模式用系统可见的文字、边界和图形保留含义。

## 使用禁例与验收

避免加载时只有无法辨认的灰块、保存失败清空草稿、成功提示自动抢焦点、错误只有颜色，以及“重试”按钮重复触发并行请求。

验收覆盖快速完成、持续等待、成功、失败重试、重复操作、无匹配结果、键盘操作和读屏播报。对生产异步任务还需检查断网、超时与取消；当前样板使用固定本地场景，不代表这些网络行为已经实现。

## 反馈结构与位置选择

反馈包含状态名称、影响范围、必要说明和可执行下一步。短成功可以省略标题，但不能省略实际结果；复杂错误可以增加详情入口，但主说明仍要可理解。

| 判断顺序 | 选择依据 | 示例 |
| --- | --- | --- |
| 能否定位到单字段 | 就近字段说明 | 邮箱格式不正确 |
| 是否影响一个区域 | 区域 Alert 或状态区 | 项目列表读取失败 |
| 是否已完成且可从对象复核 | 简短 Message 或局部成功 | 成员摘要已更新 |
| 是否需要稍后查看 | Notification 与可追溯入口 | 后台任务已处理完成 |
| 是否必须由用户决策 | Dialog | 放弃未保存修改 |

不要同时用字段错误、全局 Message 和 Dialog 重复同一失败。选择一个主要说明位置，确需摘要时负责定位和计数，而不是重复抢占播报。

## 等待与内容保留矩阵

| 情形 | 显示策略 | 操作限制与恢复 |
| --- | --- | --- |
| 首次加载，无可信旧数据 | 保留标题与区域结构，局部加载或骨架 | 查询上下文可见，失败提供重试 |
| 已有结果刷新 | 保留旧结果并标明更新中 | 限制依赖新结果的危险操作 |
| 保存草稿 | 按钮与表单附近显示处理状态 | 不重复提交，失败保留输入 |
| 长任务进度已知 | 展示可信阶段或百分比 | 取消和离开后的行为有说明 |
| 长任务进度未知 | 不定进度与任务文字 | 提供状态核对或可行恢复路径 |

400ms 是预计较长操作应提供反馈的项目约定，不是规定等待到第 400ms 才响应。消息停留时间以内容长度、重要性和现有组件能力决定，本章不发明统一“3 秒自动消失”标准。需要用户处理的重要信息应持续可达，不能依赖短暂消息。

## 成功、部分成功与结果未知

成功由实际结果确认。批量操作有部分失败时，应显示成功数量、失败数量与失败项处理入口；重试范围只包含明确需处理的对象。不能将“已接收任务”表达为“全部处理完成”。

请求超时可能代表未完成，也可能是结果尚未收到。对不可重复的操作，使用“结果尚未确认，请核对最新状态”，由业务判断是否安全重试；不能盲目给出“再试一次”。当前样板只有本地模拟结果，不具备该网络判断。

自动消失的成功提示应由对象更新提供持续证据。撤销若被作为唯一风险补救，需要可发现、可操作且覆盖真实影响；只提供一个短暂按钮不等于已经有可靠撤销能力。

## 错误恢复与权限变化

| 失败类别 | 用户需要知道 | 合理下一步 |
| --- | --- | --- |
| 字段可修复 | 哪项不符合、如何填写 | 聚焦并修正字段 |
| 读取暂时失败 | 当前区域没有最新数据 | 保留条件并重试 |
| 写入明确失败 | 哪些修改未保存 | 保留草稿，修正或重试 |
| 权限改变 | 哪项能力已不可用 | 返回可访问位置或申请权限 |
| 对象已删除 | 当前目标已不存在 | 回到有效列表 |
| 结果不确定 | 不能确认是否完成 | 查询状态，避免重复操作 |

恢复动作应与原因匹配。没有权限和对象不存在通常不能靠无限重试解决；网络诊断不确定时不编造具体原因。错误编号可复制用于求助，但不替代主文案。

## 播报、动效与排布

加载区的 busy 语义说明哪个任务在处理，文本说明正在做什么。完成后按需更新状态区，不移动焦点到普通成功消息。重要错误播报避免与字段重复；详细原则见[无障碍](/design/accessibility)。

多个通知出现时，控制可见数量和空间，不覆盖主要任务和焦点；超过容量的通知应有可追溯路径。实现是否具备通知中心、去重或暂停计时需核对现有能力，本轮未新增。

**正例**：列表失败保留筛选条件，在列表区域解释“暂时无法加载”，重试后更新结果数。**反例**：失败直接展示“暂无数据”和“创建项目”，让用户误建重复对象。修正应区分失败与成功但零项。

专项验收覆盖快速完成、长等待、部分失败、结果未知、重复重试、权限变化和对象删除；默认样板不能触发的情形标为设计用例。深色、减少动画、强制颜色和窄屏下，结果文字与恢复操作均可阅读、可访问。
