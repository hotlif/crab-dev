# 表面、层级与形状

> **落实状态：样板采用三级表面，并在指定容器消费 6 / 8 / 12px 圆角刻度。** 下表表达设计角色；具体覆盖范围见本页选型说明，不能推导为全库迁移完成。嵌套容器、遮罩与复杂浮层仍需逐项验收。

## 三类表面的职责

| 表面 | 表达的关系 | 常见对象 | 与其他表面的区别 |
| --- | --- | --- | --- |
| 画布 | 当前页面的总体背景 | 页面底色、工作区域空白 | 不承担每个内容块的边框 |
| 内容 | 持续存在的任务与信息 | 卡片、列表、表单、详情区域 | 主要依靠留白和细边界组织 |
| 浮层 | 暂时出现且高于原任务的内容 | 菜单、提示层、抽屉、确认框 | 需要明确来源、退出方式和焦点管理 |

表面层级必须对应交互关系。静态卡片不因为重要就自动成为“浮层”；浮层也不应仅靠更深的阴影暗示模态行为。是否阻断背景操作由任务决定，不能由视觉效果替代。

## 圆角规格与语义

| 对象 | 圆角 | 选择理由 |
| --- | --- | --- |
| 常规控件 | 6px | 保持精确轮廓，适合密集排列 |
| 内容卡片 | 8px | 表示信息分组，不制造过度装饰 |
| 临时浮层 | 12px | 与背景任务形成清晰区别 |
| 标签与状态 | 胶囊形 | 表达短小、独立的属性或状态 |
| 数据网格内部 | 由外容器统一处理 | 避免每个单元格都像独立按钮 |

圆角不是点击提示。不可点击的标签可以是胶囊形，可点击按钮也不需要因此变成胶囊。组件的可操作性仍由标签、边界、状态和光标共同表达。

嵌套圆角应服从同心关系与内边距：内层边缘不能顶到外层弧线。优先减少无意义的嵌套卡片，不用机械递减公式为每一层增加新的圆角令牌。

## 边界与分隔线

必要控件边界帮助用户识别可输入区域、选择框或当前焦点，必须满足对应对比度要求。装饰分隔线只辅助已有分组，不应承担识别控件的唯一线索。

边框宽度在默认、悬停、按压和错误状态之间应保持稳定。通过颜色、轮廓或不占布局的阴影提供反馈，避免按钮宽度或字段位置因状态变化而跳动。需要强调错误时，应同时显示说明文字。

## 阴影与遮罩

普通内容默认不依靠阴影抬升。浮层使用已有浮层阴影角色；连续叠加多层阴影会降低表格和文字的清晰度。暗黑模式中，较亮表面与边界通常比纯黑阴影更有效。

遮罩说明背景暂时不可直接操作，而不是把背景信息完全抹去。打开详情抽屉时，用户仍应能理解抽屉来自哪一行；出现确认框时，原编辑内容应保持稳定，不在遮罩后悄悄清空。

## 内容容器的结构

一个典型内容容器包含标题区、内容区和可选操作区。标题区说明对象，操作区只包含影响该对象的动作。容器若同时承载多种任务，应以内部区块区分，避免把所有按钮堆在卡片右上角。

整卡可点击时，卡内独立按钮不能产生两次触发；只允许标题链接跳转时，不应让整个卡片显示手形光标。边界所暗示的命中范围必须与实际可点击范围一致。

## 主题、窄屏与验收

检查白色内容表面与白色浮层能否通过边界、位置和遮罩区分；检查暗黑表面层级是否仍清楚。窄屏抽屉可以占据更大空间，但关闭与返回路径不能因此消失。

禁止把所有内容块做成高阴影卡片、把表格每一行做成圆角按钮，或用超大圆角挤压字段标签。评审时应能回答：每一层为什么存在，用户如何进入，又如何退出。

## 容器的结构与选型规则

容器由外边界、内边距、标题、主体和可选页脚组成。外边界表达归属，内边距保护内容，标题建立对象身份；任何一项都不应只作为填满空间的装饰。

| 场景 | 优先结构 | 不需要额外增加 |
| --- | --- | --- |
| 一组同类说明 | 标题、正文和留白 | 每段独立边框 |
| 单个项目摘要 | 一层 Card，内部按信息关系分组 | 卡片内再套相同外观卡片 |
| 数据网格 | 外容器与必要行列分隔 | 每个单元格单独圆角和阴影 |
| 局部编辑或详情 | 来源明确的 Drawer 或页面区块 | 为体现重要性额外嵌套模态层 |
| 短决策 | Dialog 标题、后果和操作 | 与决定无关的大段装饰内容 |

圆角表表达 Crab 设计目标。当前样板显式覆盖 Card 的 middle 圆角、Dialog 和 DropdownContainer 根圆角，其他元素仍需核对各自令牌。表内“标签胶囊形”是选型规范，不应解释为所有 Tag 变体已迁移；Drawer 也不能因为同属浮层而被假定与 Dialog 使用相同根令牌。

## 边界、分隔、阴影的选择顺序

先用对齐与空间分组；仍需明确物理范围时加边界；确实暂时浮于背景之上时再使用浮层层次。边界与阴影可以共存，但必须各有职责，不能用多层阴影补救不清楚的信息结构。

| 手段 | 表达什么 | 状态变化时的限制 |
| --- | --- | --- |
| 内外留白 | 内容归属与阅读节奏 | 不随 hover 无故改变 |
| 装饰分隔 | 已知分组之间的辅助界线 | 不替代输入控件的必要边界 |
| 必要边界 | 控件或任务容器范围 | 宽度稳定，错误时叠加说明 |
| 焦点轮廓 | 当前键盘操作位置 | 独立于容器阴影，不能被裁切 |
| 浮层阴影 | 临时内容高于原页面 | 强制颜色下仍有边界和名称 |
| 遮罩 | 背景暂时受交互限制 | 与真实模态行为一致，不逐层无限加黑 |

阴影参数继续引用 shadow.float 等既有角色；本章不新增阴影数值或 z-index 常量。原生 dialog 的顶层行为不能靠任意增大 z-index 等价替代，具体交互关系见[浮层与对话](/design/overlays)。

## 嵌套与裁切

外容器圆角与内部底色相邻时，应避免背景越过弧线；但不能给整张卡片简单设置裁切，导致菜单、焦点环或长说明被切掉。裁切对象应仅限需要遵守圆角的背景或媒体区域。

一张卡片内有完整子任务时，先考虑标题和分隔，确实需要独立选择、加载或操作边界时才加子容器。取消一层容器后信息仍清楚，通常表示这一层可以移除。嵌套圆角无需每层发明新值，以现有语义刻度和实际内边距核对视觉关系。

## 表面与可操作范围

整卡导航应有单一可理解目标；卡内又有编辑、选择等动作时，需要明确独立区域，不能产生嵌套链接或一次点击触发两项操作。悬停抬升或手形光标只能出现在真实可操作范围。静态指标卡保持阅读表面，不以相同动作暗示吸引点击。

空状态、错误状态和加载状态不应改变容器所代表的对象。项目列表加载失败后，仍能从标题辨认失败的是该列表；不能把原卡片替换成来源不明的全屏红色面板。

## 对照与可观察验收

**正例**：成员摘要使用一层边界，编辑动作在摘要内部，抽屉出现后保留背景对象关系。**反例**：卡片、字段组、字段各带阴影，错误再加粗边框，用户难以辨认操作层级。修正先合并重复容器，再让错误和焦点各用独立线索。

- 明暗主题中，能指出画布、内容、浮层各自范围，且不是仅凭阴影判断模态。
- Tab 走过卡片内所有动作时，焦点轮廓完整；长菜单和错误说明没有被外圆角裁切。
- 悬停、选中、错误和加载前后，容器外尺寸不会因边框宽度变化而抖动。
- 320px 下关闭入口、主要动作和内容可达；圆角不挤占可读内容和触控命中区。
- 强制颜色模式下，即使阴影消失，任务边界和交互目标仍能识别。
