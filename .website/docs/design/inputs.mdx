# 输入与选择

**补充实现边界**：NumberEdit 在步进前读取有效编辑草稿，例如原值 3、键入 20 后按 ↑ 得到 21；Select 清除后恢复到选择器，供键盘用户继续选择。两项分别见[NumberEdit](/components/rc-number-edit)和[Select](/components/rc-select)。这不代表它们的全部触控、搜索和复合状态已完成验收。

> **规范状态：复用现有输入与表单组件。** 组合规则作为设计与实现验收依据，不新增统一包装组件或公共属性。

> **本轮实现范围**：Checkbox、Radio 和 Switch 已补充可见焦点及强制颜色表达，粗指针下由标签容器扩展至少 44×44 CSS px 命中区。LineEdit / TextEdit 已补充输入焦点轮廓、错误语义、清除后焦点恢复及粗指针操作目标；内部动作复用 Button。该范围不能推广为 Select、日期控件和所有组合都已完成迁移，源码实现与生产验收仍分别记录。

## 按数据选择控件

| 数据或任务 | 优先组件 | 判断依据 |
| --- | --- | --- |
| 单行名称、编号、邮箱 | LineEdit | 输入内容应保持单行阅读 |
| 多行描述 | TextEdit | 内容需要自然换行和较长编辑空间 |
| 数值与范围 | NumberEdit | 需要数值约束、步进或格式处理 |
| 有限集合中选择一项 | Select / Radio | 项数、解释长度与可用空间决定展示方式 |
| 多项独立选择 | Checkbox | 每一项可以独立成立 |
| 立即生效的开关 | Switch | 结果是明确的开 / 关，切换即生效 |
| 日期或时间 | DatePicker 等专用组件 | 避免自行拼接复杂解析与键盘行为 |
| 多字段校验和提交 | Form | 管理关联、错误和提交上下文 |

Radio 适合让选项同时可见，Select 适合需要节省空间或搜索的集合。多个状态并非独立开关时，不应使用一排 Switch 代替单选。选择器不能在没有说明的情况下同时承担导航和提交。

## 字段结构

一个字段包括标签、输入区域、可选前后缀、帮助文字和反馈区域。标签位于固定、可发现的位置；前缀说明单位或上下文，后缀只提供与当前输入直接相关的动作。

帮助文字解释格式、用途和限制。错误出现在同一字段附近，并与输入关联。控件高度不应把帮助与错误一起包成不可伸缩的固定盒子；多行反馈出现时，布局可以增加高度但不能相互覆盖。

## 默认、必填与初始值

只有确有可靠业务默认值时才预填。占位示例不是实际值，不应被当成提交内容。必填信息应在填写前可见；无法预先知道的限制，在发现时提供具体解释。

选择器的“请选择”代表尚未选择，不等于业务选项。清空后应回到明确的空值状态；如果不允许空值，应说明原因并避免提供无效清除动作。

## 校验与纠错时机

输入层约束明显无效的长度或数值范围，同时避免打断输入法组合输入。格式校验应在用户完成一段输入或尝试提交后给出，不在每输入一个字符时连续报错。

提交失败时保留全部已填内容，定位第一个需要修复的字段。用户修正后，按实际校验结果清除错误。客户端校验帮助减少错误，不代表服务器可以省略最终校验。

当前资料样板会清理姓名与邮箱的首尾空白，并把示例邮箱转为小写；真实产品仍应依据数据契约定义规范化规则，不能擅自改变所有用户标识符。

## 选择器与搜索

选项标签应可区分，必要时附简短辅助信息。搜索只缩小候选范围，不自动提交当前输入。无匹配结果、选项加载失败与尚未输入关键词需要不同提示。

打开下拉后，支持组件已有的键盘选择、确认和关闭方式。下拉定位受可视区域限制，窄屏不能越出页面；弹层与触发器的主题和密度保持一致。关闭后焦点回到触发器或继续留在合理的输入位置。

## 禁用、只读与依赖

字段依赖其他选择时，在附近说明“请先选择团队”等条件。已有值只需查看时使用只读表达，避免淡化到不可读。权限不足与未完成前置条件是不同原因，应分别说明。

当上游选择改变导致下游值失效时，明确清理并提示，而不是继续提交不一致的数据。不要静默替用户选择另一个可能改变业务含义的值。

## 清除、取消与恢复

清除只影响当前字段；重置恢复表单初始值；取消结束当前编辑；放弃修改丢弃未保存草稿。四种动作不能共用一个模糊按钮。清除按钮应有名称并同步受控值，不能只清空 DOM 中的文字。

LineEdit / TextEdit 当前在调用 `onClear` 前将焦点回到输入区，避免动作卸载后焦点丢失。禁用密码字段的显示按钮同步禁用；只读密码允许切换可见性，值仍不可修改。错误状态默认提供 `aria-invalid`，显式 ARIA 优先，调用方继续负责可见错误文字和 `aria-describedby` 关联。完整尺寸与适用边界以各包文档为准，不把单行最小高度和多行 rows 混作同一密度参数。

## 验收与禁例

用中文输入法、粘贴、长文本、空白、错误格式和键盘操作验证字段。检查必填、帮助、错误、字数与单位不会互相冲突；检查加载中是否保留值，暗黑与窄屏下下拉是否可读。

避免只用 placeholder 作标签、用红色星号作唯一必填说明、把所有字段一起禁用而不解释，或关闭抽屉时无提示丢弃修改。

## 选择控件的进一步判断

| 任务条件 | 推荐判断 | 常见误用 |
| --- | --- | --- |
| 用户需要比较所有选项含义 | 优先可见的 Radio 或 Checkbox | 用窄下拉隐藏每项长说明 |
| 候选较多、已知名称可查找 | 评估 Select 的搜索及加载能力 | 让用户在长列表反复滚动找值 |
| 开关立即生效 | Switch 并提供处理、失败回退 | 看似立即生效，实际还需隐藏的保存 |
| 选择只是表单草稿 | 明确统一保存的说明，必要时用 Checkbox | 切换后既保存一次，提交又保存一次 |
| 数字参与算术或范围运算 | NumberEdit，明确上下限与步进 | 把电话、证件编号当普通数值 |
| 日期具有时间或时区含义 | 专用日期时间能力和持久说明 | 只显示日期却按未知时区保存 |

选项数量不是唯一判断标准；解释长度、搜索需求、选择频率和误选代价同样重要。不为 Radio 与 Select 制定未经验证的“超过几项必须切换”数字。

## 字段解剖与反馈位置

每个字段按照标签、控件、帮助/错误的阅读顺序组织。单位通常放在标签或稳定前后缀中；清除按钮只影响该字段；密码可见性等特殊动作必须说明状态与作用，不复用含义不明的图标。

| 部分 | 必须保留的信息 | 内容变化时 |
| --- | --- | --- |
| 标签 | 字段名、必填或选填约定 | 长标签换行，不被输入覆盖 |
| 输入值 | 用户正在编辑的真实内容 | 中文组合输入不被提前规范化打断 |
| 前后缀 | 单位、上下文或局部动作 | 不占用主值的全部宽度 |
| 帮助 | 格式、限制和用途 | 错误出现后关键限制仍可获取 |
| 错误 | 可修复问题与字段关联 | 允许多行，真实通过后再清除 |

普通控件的标准/紧凑规格来自[布局与密度](/design/layout)。TextEdit 的多行高度、日期面板宽度和候选列表高度按内容与组件能力决定，不直接套用单行控件高度。

## 清除、只读和依赖字段

当前 LineEdit 在 disabled 或 readOnly 时不会展示清除按钮。这里的实现不能推导为所有选择器都有同名 readOnly 属性；没有适当只读能力时，使用清楚的文本值与限制说明，具体方案在业务中评审。

清除后空值的含义必须明确：空字符串、未设置和有效空选项不是同一个数据值。不得仅清空可见文字而保留旧提交值。焦点应保留在合理的编辑位置，用户能继续输入；清除不可逆业务内容与清除尚未提交字段也需要不同风险判断。

上游字段改变后，判断下游值是否仍有效。仍有效则保留；失效则清除或标为待重新选择，并说明原因。加载新候选失败时保留已知值与错误说明，不能悄悄改成第一项。旧请求返回不能覆盖更新的上游条件。

## 搜索、输入法与日期边界

| 情形 | 设计要求 | 恢复路径 |
| --- | --- | --- |
| 输入法组合中 | 保留组合输入，不提前确认候选 | 组合结束后按明确规则查询或校验 |
| 粘贴长内容 | 按字段契约处理长度和格式 | 说明被限制的原因，不无声改写关键标识符 |
| 候选加载 | busy 与范围说明，保留触发器 | 失败可重试，关闭后仍能编辑 |
| 候选无匹配 | 说明当前关键词无结果 | 修改词、清除条件或合法创建路径 |
| 日期越界 | 输入前说明范围，禁用非法日期 | 能回到有效日期，不仅提交时报错 |
| 起止日期相关 | 开始与结束按同一时区比较 | 指明哪一端需调整，不静默交换 |

这些是生产组合规则，当前样板只展示基本搜索和本地资料校验。是否支持远程候选、创建选项或特定日期解析以对应组件文档为准，不在本章承诺通用能力。

## 正反例与可复核验收

**正例**：选择团队后只保留该团队合法角色，清空失效角色并提示“团队已改变，请重新选择角色”。**反例**：下拉显示新团队，提交仍携带旧团队角色，保存后才报错。修正应让依赖关系、草稿和提交值一致。

验收顺序为初始值、输入法、粘贴、空白、长度边界、非法范围、清除、只读、禁用、候选失败、错误修复与提交。逐项确认可见值等于当前草稿，字段关系有效，暗色浮层和窄屏可读，键盘能选择并退出，错误与标签可被辅助技术获取。
