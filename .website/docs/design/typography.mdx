# 字体与排版

> **落实状态：标尺已用于样板。** 页面标题行高、正文行高为候选语义参数；文档站外壳与公共组件的默认字体仍有各自职责。

## 阅读层级的目标

字号、字重和行距应让用户在不逐字阅读时区分页面主题、区块、字段值与补充信息。层级来自语义，不来自某段文字“想更醒目”。页面里最重要的数字也必须伴随名称、单位和统计范围。

中文采用自然字距，不使用字间距扩大来模拟英文品牌标题。正文默认左对齐；金额和可比较数值按列对齐，避免在同一段落内混合多个阅读方向。

## 字体族与回退

正文优先使用 Inter，中文依次回退到 PingFang SC、Microsoft YaHei UI、Microsoft YaHei 等系统字体。字体尚未下载时仍应完整显示内容；布局不能依赖某台开发机的单一字体宽度。

代码使用 Geist Mono 对应的全局等宽字体令牌。数字对齐使用等宽数字特性，业务正文不应为了数字对齐整段切换为代码字体。字形缺失、金额符号和中英文标点应在实际系统上检查。

## 字体标尺

| 角色 | 字号 / 行高 | 字重建议 | 主要用途 |
| --- | --- | --- | --- |
| 页面标题 | 28 / 36px | 半粗 | 单页任务或对象名称 |
| 区块标题 | 20 / 28px | 半粗 | 数据分区、表单分组 |
| 正文 | 14 / 22px | 常规 | 描述、字段值、表格正文 |
| 辅助说明 | 12 / 18px | 常规 | 帮助文字、时间、统计口径 |
| 代码与标识符 | 复用辅助字号 | 常规等宽 | 令牌名、项目编号、代码片段 |

尺寸应按语义成套使用。不要只缩小字号而保留原行高与间距，也不要在每个卡片里重新创建一套 13、15、17px 标尺。密度主要改变控件和数据行高度，不应把正文压到 12px 以下。

## 中文与混合内容

### 名称与句子

页面标题使用名词或任务短语，例如“项目台账”“编辑成员资料”。说明文字使用完整、直接的句子。中文与英文缩写之间保留清楚的间隔，不通过大量英文大写制造层级。

同类字段的标点和后缀保持一致。“预算 / 元”适合作为列标题，“¥ 86,000.00”适合作为具体值；不要在每个单元格里重复不同形式的币种名称。

### 数据与缺失值

金额使用一致的小数位和千分位规则。日期必须说明业务时区或统计日期口径；列表展示短日期时，应能在详情中获得完整时间。空值显示“未填写”“未设置”等有意义的占位，不能用 0 代替未知。

增长率的正负号必须与文案一致。仅用上升箭头和绿色不能说明增长是否有利，应写出指标名和比较区间。

## 长文本、换行与截断

标题和帮助文字优先自然换行。编号、邮箱和长链接需要允许断行或提供局部横向滚动，不能撑宽整个页面。按钮标签过长时，优先改进文案或换行布局，不缩小文字。

表格在列宽受限时可以截断名称，但必须提供键盘与触控都可获得的完整内容入口，例如详情视图。工具提示只能作为辅助，不能是读取关键值的唯一方法。

错误文字不应固定为单行。系统语言变化、200% 文字缩放或内容多一倍时，字段下面的反馈仍要完整显示，且不能覆盖下一行操作。

## 验收与使用禁例

- 检查标题、区块、正文和说明能否仅凭字重与空间清楚区分。
- 检查中文、英文、金额、负值、长邮箱与缺失数据的真实样本。
- 检查文字缩放后仍可阅读、输入和提交；固定高度容器不能裁掉正文。
- 避免把灰度过低的文字当作“高级感”，尤其是帮助文字和占位提示。
- 避免用文字加粗替代标题语义，也不要只为视觉大小跳过标题层级。

## 业务界面与文档阅读的两种尺度

本页 14/22px 正文来自设计样板 `design.body`，适用于密集业务信息。站点外壳通过语义 subhead 字号提供 16px 阅读基准；导航、API、代码和真实组件可有各自语义字号。两者用途不同，不应为统一数字而压缩整站文章，或把样板控件一律放大。

| 场景 | 选择依据 | 实现状态 |
| --- | --- | --- |
| 样板页面标题 | 28/36px，600 字重，强调任务身份 | 样板参数与标题样式已使用 |
| 样板区块标题 | 20/28px，600 字重，区分主要信息组 | 字号引用全局 xl，行高由样板定义 |
| 样板正文 | 14/22px，常规字重 | 样板局部阅读基准 |
| 样板辅助信息 | 12/18px，保持可读前景 | 用于简短元信息，不承载长篇规则 |
| 站点文章 | 16px 阅读基准，按文章标题建立层次 | 站点样式；不代表公共组件默认字号 |
| 图标旁短标签 | 跟随所在控件的正文尺度 | 使用对应组件能力，不能独立缩小 |

字号与行高分别记录 px；字重使用实际数值或已有令牌。字体名称表示回退优先级，不代表页面已经下载该字体。新增中间字号或行高必须登记候选用途，不能仅为让某一行恰好不换行而新增规格。

## 标题、段落与信息组合

页面应有清楚的主标题，章节使用连续的语义层级。标题视觉大小可以由样式决定，但不能把普通文字加粗当作标题结构。相邻章节之间的距离应大于标题与其正文之间的距离，数值选择见[布局与密度](/design/layout)。

字段名称、字段值、帮助文字依次说明“是什么、内容是什么、如何理解”。它们不必全部使用不同字号：优先借助字重、换行和间距建立关系。数据卡的大数字必须紧邻名称和统计范围，辅助说明不能远到看起来属于下一张卡片。

长文容器优先控制阅读行长，表格优先保留列间比较。不得给所有页面设同一个固定正文宽度；样板介绍的 60ch 上限只是局部英文字符度量，不能解释成“每行 60 个中文字”。

## 数字与文本格式决策表

| 内容 | 规范 | 边界处理 |
| --- | --- | --- |
| 金额 | 同列币种、单位、小数位一致；数值右对齐 | 超长金额提供完整值，不能只剩省略号 |
| 百分比 | 说明比例分母或比较基准 | 分母为零、未计算与 0% 分别表达 |
| 时间 | 明确业务时区；同类列表采用一致精度 | 相对时间提供完整时间的可达入口 |
| 编号 | 作为标识符展示，不自动加千分位 | 保留前导零和原始大小写 |
| 电话等非算术数字 | 采用适合该数据的格式 | 不能因全是数字就丢弃符号与前导零 |
| 空值 | “未填写”“未设置”等明确语义 | 0、未知、无权限、加载中不能互换 |
| 代码 | 等宽字体，保留缩进和语法字符 | 允许局部横向滚动，复制内容不被展示截断 |

复制行为应与被复制对象的契约一致：金额的格式化展示可以带单位，标识符复制应保留完整原值。不能在用户不知情时复制省略后的字符串。

## 内容增长时的处理顺序

1. 先确认文案能否精简而不损失对象、范围和后果。
2. 允许文本自然换行，并让容器高度随内容增长。
3. 调整列布局或移走次要操作，保持 DOM 顺序。
4. 只有明确的摘要场景才截断，并提供可达的完整内容入口。
5. 只有代码、长标识符或二维数据等确有需求时局部滚动，不把整篇文章变成横向阅读。

按钮标签优先保持单行；空间不足时先换行按钮组或纵向排列。不得通过裁掉“删除全部项目”中的“全部”来缩短按钮，亦不能把风险说明限制为固定行数。

## 对照样例与排版验收

**正例**：预算列标题为“预算 / 元”，每行采用统一格式，未填写显示文字；详情提供完整金额。**反例**：同列同时出现“8.6万”“86,000.00元”和“-”，又没有解释缺失含义。修正先统一数据表达，再处理视觉对齐。

验收样本至少包含中文长项目名、中英文混合团队名、长邮箱、带前导零编号、负数、零值、大金额及三行错误。分别检查默认和 200% 文字缩放：无文字重叠，标题层级可识别，提示不被固定高度截断。字体回退后仍能完成阅读和操作；深色模式不以更细字重补偿亮度。当前样板未统一所有组件的排版细节，这部分按组件迁移记录验收。
