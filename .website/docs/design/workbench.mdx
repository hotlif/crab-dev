# 数据工作台

> **落实状态：已有本地数据样板。** 本页分别标注可直接操作的演示路径与未来生产接入要求，不新增排序、批量或网络功能。

工作台面向反复查找、比较与处理记录的任务。用户应先判断整体情况，再缩小范围、核对具体对象、完成操作。页面中的指标、查询条件和选择范围必须各有明确含义。

## 模式目标与适用场景

适用于项目台账、成员管理、订单查询和类似的结构化记录任务。这里验证的是一种通用业务布局与交互关系，不定义某一行业的真实数据口径。

当前样板使用 12 条固定项目数据，仅在本页内进行查询、选择与场景模拟。不会向服务器提交数据，也不提供真实删除、导出、权限管理或后台任务。

## 页面分区

| 区域 | 内容 | 设计目的 |
| --- | --- | --- |
| 概览 | 全部项目、正在进行、已交付 | 用少量关键数值建立整体判断 |
| 数据标题 | 项目台账及演示范围 | 明确下方查询和数据的作用对象 |
| 查询区 | 项目搜索、状态筛选 | 让用户逐步缩小范围，保留可见标签 |
| 场景控制 | 正常、加载、错误、空数据 | 用于规范验证；真实业务按请求状态呈现 |
| 数据区 | 名称、负责人、状态、预算、更新日期 | 支持识别对象与跨行比较 |
| 结果区 | 查询结果数、当前页选择数、分页 | 清楚说明当前范围及后续操作 |

概览始终统计全部模拟项目，结果区统计当前查询结果。不要在筛选后把全局指标误标为当前结果；实际业务若需要联动指标，应明确采用同一筛选口径。

### 字段呈现

项目名称与负责人左对齐；预算右对齐，以元为单位并使用千位分隔和等宽数字；日期保持一致格式。状态使用文字与图形共同表达：待启动、进行中、已完成。颜色只是辅助。

标准模式行高 44px，紧凑模式行高 36px；触控环境保证至少 44px 的交互目标。宽表格在容器内部横向滚动，查询控件在窄屏按原顺序换行。

## 搜索与筛选规则

搜索匹配项目名称、编号或负责人，忽略两端空白与大小写。状态包含“全部状态、待启动、进行中、已完成”，并与搜索条件取交集。

查询变化后回到第一页并清空当前选择，防止选择范围变成不可见记录。清空搜索只清除关键词；空状态中的“重置筛选”同时恢复全部状态、第一页与正常场景。

### 结果数与分页

每页展示 5 条记录。第一页没有可用的上一页，最后一页没有可用的下一页；查询后页数减少时从第一页重新计算。页码变化应只更新数据区域，避免页面跳到顶部。

当前样板的选择只作用于当前页，翻页和筛选会清空选择。批量操作、跨页全选和排序尚未加入该样板；未来接入时遵守[数据展示](/design/data-display)中的范围与反馈规则。

## 状态与恢复路径

| 场景 | 显示内容 | 用户可以如何继续 |
| --- | --- | --- |
| 正常 | 数据行、结果数、选择与分页 | 查询、筛选、选择记录或翻页 |
| 加载 | “正在读取项目，请稍候”与加载图形 | 通过演示控件切换场景；数据区标记忙碌 |
| 错误 | 区域错误说明与“重新加载” | 重试回到正常展示，保留查询条件 |
| 空数据 | 无匹配说明与“重置筛选” | 清除条件恢复正常列表 |
| 正常但查询无匹配 | 同样明确是当前条件无命中 | 修改搜索词或重置筛选 |

展示场景是验证入口，不是真实网络状态。切换到加载、错误或空数据时清空选择并禁用数据分页，避免对不可见数据执行操作。

## 可交互样板

使用样板顶部的主题与密度控制检查同一规则的视觉变化。主题与站点顶部同步，密度只作用于当前样板。切换章节会重新创建本地演示状态。

## 按步骤验收

1. 初始应显示 12 条项目记录的统计与第一页数据；每页最多 5 条。
2. 搜索“PRJ-001”应定位海蓝设计系统；清空后恢复全部结果。
3. 搜索负责人后再选择状态，结果应同时满足两个条件。
4. 选择当前页记录，检查选择数；翻页后选择数应回到零。
5. 输入不存在的关键词，检查空结果说明；重置后恢复第一页。
6. 切换加载与错误场景，检查忙碌提示、分页限制与重试恢复。
7. 在明暗主题及两种密度下核对状态图形、文字、必要边界和选中反馈。
8. 在 320px 下操作查询与分页，横向滚动仅发生在表格区域；使用键盘完成主要流程。

## 后续接入真实业务

先定义统计口径、筛选协议、稳定记录标识和分页模型，再接入数据源。需要处理请求竞争、失败重试、权限、过期记录与选择失效，不能仅把本地数组替换为网络结果。

新增批量删除或覆盖操作前，应明确对象总数与不可逆后果，复用确认机制。这里的模拟成功和重试不代表生产服务的可靠性保证。

## 页面结构与范围口径

工作台由页面身份、指标摘要、查询工具栏、数据区域、选择摘要及分页组成。每一部分都需要说明范围，尤其要区分不随筛选变化的总览与当前查询结果数。

| 区域 | 当前样板 | 生产设计要求 |
| --- | --- | --- |
| 指标 | 全部项目、正在进行、已交付 | 写明数据范围、统计时点和刷新方式 |
| 搜索 | 名称、编号、负责人，本地匹配 | 告知字段与查询提交方式 |
| 状态筛选 | 与搜索条件取交集 | 组合条件和清除规则一致 |
| 列表 | 本地 12 个项目，每页最多 5 项 | 明确稳定标识、分页与排序模型 |
| 选择 | 仅当前页，筛选/翻页清空 | 如需跨页，必须另有明确范围设计 |
| 展示场景 | 正常、加载、错误、空数据 | 演示控件不是生产用户操作 |

主题、密度和窗口变化不改变数据含义。标准/紧凑的行高来源见[布局与密度](/design/layout)，颜色与图形表达见[色彩](/design/color)；本章不重复维护数值标尺。

## 从进入到完成的完整流程

| 步骤 | 用户或系统动作 | 可见结果 | 失败或边界处理 |
| --- | --- | --- | --- |
| 进入 | 确定身份、权限与默认范围 | 页面标题、查询区、初次加载 | 无权限与加载失败分别呈现 |
| 查询 | 输入关键词、选择状态 | 当前条件明确，结果与计数同步 | 成功但零项显示无匹配 |
| 排序 | 指定字段和方向 | 结果按正确类型与范围排序 | 不将当前页排序冒充全结果排序 |
| 分页 | 选择下一段结果 | 页码、行与总数一致 | 总数缩减后回到有效页 |
| 选择 | 选择明确记录范围 | 数量、范围和可执行操作可见 | 失效或无权限项解释原因 |
| 执行 | 确认对象与风险 | 处理中反馈，限制重复执行 | 部分成功按对象分开反馈 |
| 完成 | 获取可靠结果 | 数据、统计与有效选择更新 | 结果未知时先核对状态 |
| 返回 | 关闭详情或编辑 | 回到来源对象或后继 | 对象不存在时回有效列表 |

以上为生产模式设计。样板没有排序、批量执行、后端权限和真实刷新；不要把这些流程写成现有演示的操作步骤。

## 请求竞争与旧结果

新查询发起后，旧响应不得覆盖当前条件对应的结果。加载时可以保留旧数据，但必须让用户知道那是上次结果；危险动作不能依赖尚未确认的最新范围。刷新失败保留条件与合理上下文，重试不自动清空搜索。

筛选与分页的先后关系需要稳定：先建立查询范围，再取有效页；排序作用于完整结果集。后端分页的总数未知时，不制造一个确定总数。结果集变化可能导致当前页失效，应更新页码并解释变化，避免出现“有总数但当前页永久空白”。

这些为真实服务接入要求，尚无网络 API 或请求协议变更。实现团队需以业务服务契约落实，不直接照抄本地数组处理方式。

## 批量操作的范围与恢复

当前页选择必须在执行前让用户看到对象数量；跨页全选需要额外入口，明确“全部筛选结果”，并能撤销选择。确认期间条件变化时不能自动扩大对象集合，应重新确认或保留已明确的对象快照。

部分成功时分别显示完成、失败和不可执行的数量。失败项可保留用于再次处理；已成功项不能被无差别再次执行。高风险操作采用确认或可靠撤销，规则见[操作按钮](/design/actions)。当前样板尚无此流程。

## 验收场景与预期结果

| 场景 | 预期 | 样板可直接验证 |
| --- | --- | --- |
| 查找已知编号 | 匹配正确项目，计数准确 | 是 |
| 搜索与状态组合 | 结果满足两个条件 | 是 |
| 选中后翻页 | 选择清空，页码同步 | 是 |
| 查询无命中后清除 | 恢复有效结果与第一页 | 是 |
| 错误场景重试 | 恢复数据，保留查询条件 | 是，本地模拟 |
| 快速连续查询乱序响应 | 最后有效条件对应正确结果 | 否，真实接入后验证 |
| 跨页选择及部分失败 | 范围明确且失败可恢复 | 否，后续设计实现 |
| 权限改变、对象被删除 | 不执行失效操作，返回路径可用 | 否，后续业务接入 |

**正例**：顶部指标标明全量概览，表格页脚标明筛选结果数，清除条件后回第一页。**反例**：搜索后表格只剩 1 条，顶部仍显示 12 条却没有范围说明，批量按钮又写“全部”。修正应分别命名统计、查询和选择范围。

阅读与操作验收还包括：320px 工具栏重排、表格局部横滚、两种密度的可读性、明暗主题、键盘选择与翻页、长名称和大金额。评价目标是完成查询与处理任务，不是仅让默认截图看起来整齐。
