# 布局、间距与密度

> **落实状态：4px 基准与两种样板密度已实现。** 本页的任务分区与列布局属于迁移建议；业务应根据真实内容验证，不能把文档站断点直接当作所有产品的统一断点。

> **本轮实现范围**：公共 Button 在粗指针下以最小尺寸提供 44×44 CSS px 独立目标；Checkbox、Radio、Switch 通过可点击标签容器扩展命中区，内部视觉尺寸仍使用原 size。这里没有建立全局 density API；表格行内等紧凑组合需检查扩展后的目标与邻项是否重叠，不能把最小目标盲目套到所有子元素。

> **输入控件补充**：LineEdit 的 size 使用最小高度，文字或内部动作可以使容器自然增高；TextEdit 高度由 rows / autoSize 决定。两者在粗指针下为输入区提供至少 44px 高度、内部动作提供至少 44×44px 目标；外层边框和内边距使总高度可能更大。TextEdit 常驻预留清除操作宽度，避免清除入口出现时文本重排。参阅 [LineEdit](/components/rc-line-edit) 与 [TextEdit](/components/rc-text-edit) 的当前尺寸表。

## 从任务建立布局

先排列信息的阅读顺序：页面身份、主要结果、筛选与操作、内容、补充信息。控件应靠近其作用对象；表格的批量操作不能与另一个列表共用一组没有范围说明的按钮。

顶部承担栏目切换，左侧承担栏目内导航，正文承担任务，右侧目录承担长文定位。布局改变时，这些语义保持一致。手机上可以把侧栏放入抽屉，但不能把原来的“筛选”按钮变成“导航”。

## 间距刻度与归属

| 刻度 | 推荐用途 | 不应承担的职责 |
| --- | --- | --- |
| 4px | 图标与短标签、紧密关联的小元素 | 分隔独立任务 |
| 8px | 同组按钮、标签之间的间隔 | 页面外边距 |
| 12px | 说明与内容、紧凑字段间距 | 区分两个大工作区 |
| 16px | 卡片内容、字段组内部的基本节奏 | 代替所有层级的留白 |
| 24px | 表单分组、区块之间的分隔 | 为拥挤内容强行压缩出来的装饰空白 |
| 32 / 48px | 页面区块和大任务之间的留白 | 单个图标周围的常规内边距 |

这些数值是空间刻度，不要求每个页面全部用到。通过距离表达归属后，通常不再需要额外边框把每个字段圈起来。重复卡片应保持一致内边距和标题基线。

## 密度规格

| 项目 | 标准 | 紧凑 | 触控优先 |
| --- | --- | --- | --- |
| 控件视觉高度 | 36px | 28px | 交互目标至少 44px |
| 单行数据行高 | 44px | 36px | 可操作目标不能随密度缩水 |
| 正文字号 | 14px | 14px | 保持可读，不以缩字号换空间 |
| 适用场景 | 常规管理任务、混合阅读与编辑 | 鼠标键盘下的高频数据操作 | 手机、触屏和粗指针环境 |

密度应在一个任务区域内一致。表格行、工具栏输入框和操作按钮一起调整；标题、语义、分页逻辑和选中范围保持不变。多行文本或错误说明可以增加实际行高，不能强行裁剪进单行规格。

当前样板的密度只影响所在章节，进入另一个章节默认恢复标准。触控媒体条件会优先放大交互目标，用户选择紧凑模式也不应覆盖这一要求。

## 响应式重排

### 宽屏

让主要数据区获得连续的宽度。次要说明可以移到右侧，但不能改变 DOM 阅读顺序。只有信息之间需要横向比较时才使用并排布局；三个互不相关的表单不应只因为屏幕宽就并列。

### 中等宽度

先移走非必要的辅助栏，再减少正文列数。筛选工具栏允许换行，每个标签继续贴近自己的输入。不要依赖固定宽度让表格和侧栏一起把页面撑出视口。

### 窄屏

页面使用单列，主导航与章节目录保持可发现。表单字段纵向排列，主操作保持完整标签。表格允许在自己的滚动区域横向滚动，并保留清楚的范围边界；页面整体不应产生横向滚动。

文档站在 768px 以下使用手机导航，在 1280px 以下收起右侧目录。这是当前站点的实现选择；业务布局应以内容是否仍可读、控件是否可操作为调整依据。

## 固定区域与滚动

固定页头、吸底按钮和粘性表头必须留出正文空间。锚点跳转与校验聚焦后，目标不能被这些区域遮住。长抽屉只滚动内容区时，标题、关闭按钮和操作区仍应可达。

每个滚动区必须有明确用途。普通说明段落不要再套一个小滚动框；必须滚动的表格或代码区需要可聚焦或其他键盘滚动路径，并在窄屏上保持最大宽度约束。

## 推荐与禁例

- 推荐：用 4px 刻度建立节奏，再依据真实文本验证分组距离。
- 推荐：在 1440、768、320px 和文字缩放场景检查所有任务。
- 避免：为了放下更多列而把按钮、字号和点击范围一起缩小。
- 避免：通过视觉重排改变 Tab 顺序，或让重要操作只能悬停出现。
- 避免：固定卡片高度导致中文说明、错误反馈或翻译文字被截断。

## 验收步骤

先检查整体是否溢出，再检查局部滚动是否可操作；切换两种密度，确认数据含义不变；使用键盘从顶部走到末尾，确认焦点未被遮挡；最后检查粗指针下的目标尺寸。

## 布局结构与空间职责

| 层级 | 包含内容 | 空间决策 |
| --- | --- | --- |
| 应用外壳 | 全局身份、栏目、导航 | 固定结构不能压缩主任务到不可读 |
| 页面身份区 | 标题、范围、主要动作 | 与正文对齐，避免标题和操作各自漂浮 |
| 任务区 | 查询、结果、编辑或详情 | 每个动作应能明确归属到一个任务 |
| 分组区 | 相同目的的字段或指标 | 组间距离大于组内距离 |
| 控件内部 | 图标、标签、值、前后缀 | 使用组件公开尺寸，不靠负边距凑对齐 |
| 反馈区 | 帮助、错误、完成结果 | 就近出现，可扩展高度，不能覆盖下一组 |

上述间距表是选取全局空间刻度的设计规则，不是强制为每一层新增 L2 令牌。当前样板的相邻项目、字段和区块分别消费 component-gap、section-gap、group-gap 等语义值；选用时同时核对具体映射，不能假设名字中的“section”在所有产品都代表同一页面结构。

## 容器宽度的选择

单列编辑应以标签和输入能连续阅读为目标；多列表格以保留有效比较为目标；说明文档以稳定行长为目标。需要独立宽度的对象分别约束，不把整个站点的最大宽度复制给一张编辑卡片。

当前站点通用外壳最大宽度为 96rem，设计语言外壳使用全局空间刻度组合出 1536px；这些属于站点实现，不是所有业务页面的标准。样板工具栏搜索项以 220px、筛选项以 130px 作为 flex 基础宽度并允许换行，表格演示框为 290px 高；这些为演示结构参数，不应成为生产表格固定高度要求。

新页面没有适用规格时，先记录候选容器宽度和内容样本，并在目标宽度验证后推广。禁止把演示窗口大小当成数据容量上限。

## 响应式决策矩阵

| 区域 | 空间充足 | 开始拥挤 | 320px 验收目标 |
| --- | --- | --- | --- |
| 导航 | 保留常用定位入口 | 次要目录折叠 | 入口常驻，抽屉内可定位当前章节 |
| 查询工具栏 | 字段与操作顺序排列 | 按完整字段单元换行 | 标签与输入单列，操作不挤压输入 |
| 编辑表单 | 有明确关系时可并列字段 | 先恢复单列 | 帮助和错误完整显示，提交可达 |
| 指标摘要 | 同类指标并列 | 减少列数 | 卡片纵向排列，数字与单位不分离 |
| 数据表格 | 连续显示比较列 | 收纳次要列或局部滚动 | 页面无整体横滚，表格有可达滚动路径 |
| 操作组 | 主次动作稳定排列 | 整组换行或堆叠 | 保留完整标签与触控目标 |

不要因为用户窗口变窄就改变筛选语义、删除已选记录或自动提交表单。布局重排应保留输入、展开状态和任务上下文。固定列若占满窄屏，应在业务设计中减少固定列，而不是让可滚动列完全不可见。

## 密度切换的边界

标准与紧凑改变可见容量，不改变数据和控件的业务含义。同组按钮、输入和选择器采用一致视觉高度；多行输入、错误说明和详情内容按实际内容伸展，不能硬塞进 28px。

当前样板通过局部 L3 高度覆盖调整常用控件，并通过 Table 的行高能力调整数据行；这并不证明每个组件都有通用 density 属性。触控优先规则见[无障碍](/design/accessibility)，粗指针下不能仅扩大背景而保留小点击区域。新增密度需要同时检查视觉高度、内边距、图标位置和命中区，不能只改一个高度值。

## 滚动、定位与反馈出现

页面、浮层和数据区分别拥有自己的滚动职责。一个普通表单不应同时套三层纵向滚动。固定表头应跟随它所解释的数据区域，固定操作区应预留内容空间；最末一行错误和最后一个按钮必须能滚入可见范围。

错误出现可以让下方内容自然下移，禁止的是重叠、裁切及状态边框引起的非必要跳动。焦点定位首个错误后，需要同时看到字段标签、输入和修正说明。若用户正在阅读别处，后台数据刷新不应强行把整页滚回顶部。

**正例**：手机筛选字段整组竖排，表格自身横向滚动，分页紧随其后。**反例**：给表格设置大固定宽度，导致导航与全文一起横滚；修正时约束容器并为二维内容建立独立滚动区。

专项验收记录包括：各宽度的外壳、最长字段、最长操作组、两个密度、已打开浮层、文本缩放和焦点定位。通过条件是信息归属清楚、任务可完成、没有全页横向溢出，且视觉顺序、阅读顺序和 Tab 顺序一致。
