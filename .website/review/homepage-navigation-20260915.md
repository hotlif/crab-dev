# 首页与全站顶栏优化验收

日期：2026-09-15。首页：`http://127.0.0.1:4173/`。

## 重新评估与实施

| 原问题 | 实施结果 |
| --- | --- |
| 首屏只有笼统介绍，设计、开发读者缺少清楚的起点 | 明确企业应用与 React 19 定位，前置设计规范、组件目录和接入指南三个任务入口 |
| 大型交互陈列在组件目录之前，占据多屏阅读空间 | 调整为任务入口 → 组件分类 → 交互体验 → 业务实战 |
| 分类区网格线与组件名称小框太密 | 使用标题、对齐与留白分组；分类标题整行可点击，组件名称采用文字链接 |
| 搜索外框、快捷键框和三段主题控件争抢视觉注意力 | 搜索入口与快捷键去掉常态描边，主题改为单个图标入口 |
| 320 px 顶栏分为三行，高约 160 px | 品牌、搜索、主题和导航保持一行，高 64 px；主导航入口移入 Drawer |
| 示例卡片底色与边框偏重 | 保留真实组件行为，减轻示例卡片表面与边界；由示例源刷新可复制代码 |

## 实现与维护入口

- 首页正文与顺序：`.website/docs/site/learningHome.tsx`。
- 首页静态样式：`.website/docs/site/homeStyles.ts`。
- 全站顶栏及移动导航：`.website/docs/site/ui.tsx`、`siteStyles.ts`。
- 站点专用主题菜单：`.website/docs/site/themeSwitch.tsx`。
- 交互陈列：`.website/docs/examples/home/profile.tsx`；对应的 `.website/docs/_generated_tutorials/home.ts` 由 `generate:docs` 刷新。
- 工作约定同步至 `.website/README.md`；交互回归断言维护于 `.website/docs/site/__tests__/ui.test.tsx`。

主题菜单复用公共 DropdownContainer 与 Button。它提供 menu / menuitemradio 语义、当前设置名称、选中勾号、方向键、Home / End、Escape 和 Tab 离开。浮层以站点布局锚点对齐触发器右边缘，避免在右上角翻转到品牌区域。主题偏好仍由 Wake 保存；没有修改公共令牌、主题实现、组件 API 或依赖。

## 检查中修正

1. 初次类型检查发现不存在的标题行高令牌，以及其他站点区域仍需使用 Segmented；已使用现有正文行高并保留必要导入，复验通过。
2. 初版主题入口尝试复用 Select。实际检查发现其虚拟列表固定按 32 px 计算，加高为 44 px 后第三项被裁切。最终使用三项普通按钮菜单；公共 Select 的行高与 API 保持原状。
3. 窄屏下默认浮层翻转到触发器左侧并遮挡品牌。最终菜单通过专用布局锚点向下展开，三个选项均为 44 px，内容区高 140 px；320 px 下右边缘与触发器相差约 1 px。
4. 菜单的 ref 回调在退出过程中重新聚焦选项，会让关闭后的焦点落到 body。已改为 Button 挂载时的 autoFocus，只在打开时聚焦当前项；关闭与 Tab 的最终复验结果在下文记录。
