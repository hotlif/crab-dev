# 候选验收模板

复制到 `runs/<日期或候选 ID>/acceptance.md` 后填入真实结果。四层分别判断，不以其中一层代替其他层。

- 日期、负责人、范围：待填。
- 源码：提交 SHA；存在未提交改动时同时记录 `sourceRevision()` 的 `source.kind=worktree` 和 SHA-256。证据目录不参与该指纹，防止自引用。
- 产物：实际服务目录、`productionRevision()` SHA-256、构建命令；独立包或夹具应分别记录产物指纹。
- 条件：工具/浏览器/系统版本、视口、输入方式、配置与异常替身。

| 层次 | 状态 | 范围与证据 | 结果 | 未验证或失败 |
| --- | --- | --- | --- | --- |
| 规范已起草 | 待审 / 已通过 | 架构、来源、设计变体、API 与迁移文档 | 待填 | 不能据此声称实现完成 |
| API 已迁移 | 待验 / 部分 / 已通过 | 公共类型、运行行为、示例、导出与原生事件 | 待填 | 不能据此声称工程或视觉通过 |
| 工程已通过 | 待验 / 部分 / 已通过 | 逐项命令、日志与对应源码指纹 | 待填 | 全库汇总须覆盖全部受影响包 |
| 视觉交互已核对 | 待验 / 部分 / 已通过 | 对应产物、配置矩阵、截图与行为断言 | 待填 | L2 一致性不等于组件逐状态验收 |

每个设计体系分别记录 `matrixScope` 的六个轴：`colorModes`、`sizes`、`densities`、`directions`、`locales`、`states`。另记录视口、触控/键鼠、Portal/iframe、强制颜色与减少动画的适用范围。未覆盖组合明确列出，不能将抽样推广为完整矩阵。

若产品清单将设计覆盖提升为 `verified`，必须满足 `scripts/design-verification.mjs` 的实际结构：精确的 `source={kind,ref}`、SHA-256 `artifactFingerprint`、六轴非空 `matrixScope` 和仓库内存在的 `evidencePaths`。记录本身不会自动更改覆盖状态。

失败、重试和修复必须保留。源码或产物变化后，旧通过项是否仍适用需要重新判断；需要重新构建或复验时标为待验。本地候选通过不代替同一提交的 CI，也不表示已发布。
