# Crab / Material 3 对照评审协议

状态：协议已准备，参考方案、招募、观察数据和结果均待落实。没有真实参与者结果，不得宣称 Crab 优于 Material。

## 冻结条件

正式测试前锁定同一 Crab 候选版本与独立 Material 3 参考版本，记录源码版本、生产资源摘要、设备、浏览器、字体、视口和主题。两者使用相同中文内容、记录数量、功能、权限、加载延迟与失败注入。参考方案遵循官方 Material 3 组件语义，不通过放大间距、删减功能或设置不合理默认来降低其表现；不引入 Crab 生产依赖。

先让不参与正式数据的试测者检查任务是否可完成，修复方案缺陷后重新冻结。正式测试期间任何影响任务的改动均产生新候选，不混合两个版本的数据。桌面任务主测试条件为同一台设备、1440 CSS px、同一主题；320 / 768 px 及辅助技术另作工程验收。不能让某方案独占更熟悉的设备或输入方式。

## 四个相同任务

| 编号 | 给参与者的目标 | 成功终点 | 失败与错误记录 |
| --- | --- | --- | --- |
| A · 组件查找 | 为立即生效的通知设置找到适用组件，并打开基础示例 | 找到 Switch，打开可运行示例，并正确解释开启含义 | 打开错误组件记错误；只看到目录卡片不算完成 |
| B · 数据筛选 | 找出工程研发团队待启动的项目，按更新时间查看最新记录，选中指定两个项目 | 筛选与排序正确，选中范围仅为指定两项；未误选全部结果 | 记录误选、错误排序、重置后丢失范围及恢复动作 |
| C · 成员编辑 | 将指定成员的团队改为运营支持并保存，返回成员列表 | 修改持久化，返回正确上下文，其他成员数据不变 | 保存前误离开、重复提交、对象误认分别记录 |
| D · 错误恢复 | 保存资料时遇到一次服务端失败，修正给定字段并再次保存 | 看懂失败原因，输入保留，只发起一次有效重试，成功返回 | 丢失输入、重复创建、关闭后无法返回均为错误 |

每项最多 180 秒，从完整任务提示可见开始，到成功终点或主动放弃停止。超时、放弃、主持人提供操作提示均记未独立完成；不能从统计中删除。系统故障单独记为技术中止，保留原始记录与理由，并在冻结版本恢复后重测该对。错误指一次偏离目标的可观察操作；先定义后记录，不因方案不同改变判断尺度。

同一参与者两次任务使用难度等价的对象集合，避免记住上次对象位置。两套对象在条件间交换，数据规模、名称长度和目标位置保持等价。任务期间使用观察记录，结束后回顾；不强制边操作边思考，以免测量口述速度。

## 至少 12 名目标用户与顺序平衡

参与者应有中文企业后台的日常使用经验，记录角色、使用频率、两个系统的熟悉程度以及辅助技术使用情况。设计和开发团队自评可用于试测，不能代替目标用户。仅使用匿名编号，录屏与个人信息处理遵循参与者知情同意。

下表是招募位置，**不代表已经有 12 名参与者**。C 为 Crab，M 为 Material；每人体验两个方案。方案顺序各 6 人，任务起始位置各 3 人。

| 预留位置 | 方案顺序 | 每个方案的任务顺序 |
| --- | --- | --- |
| P01 / P02 / P03 | C→M / M→C / C→M | A B C D |
| P04 / P05 / P06 | M→C / C→M / M→C | B C D A |
| P07 / P08 / P09 | C→M / M→C / C→M | C D A B |
| P10 / P11 / P12 | M→C / C→M / M→C | D A B C |

两方案间安排相同休息时间，主持人只复述目标，不指点界面入口。参与者完成后分别评价清晰度、舒适度、专业感，并给出整体偏好：Crab / Material / 无明显偏好。不能把三个维度当作三名用户，也不能排除“无偏好”以抬高比例。

## 预先约定的指标

1. **独立完成率**：Crab 成功次数 / 全部有效任务尝试次数，目标至少 90%。同时逐任务报告结果，超时和求助计失败。
2. **完成时间**：以同一参与者、同一任务的双方成功记录配对，分别求 Crab 与 Material 时间中位数。改善率 = 1 − Crab 中位数 / Material 中位数，目标至少 15%。同时报告全部成功任务的中位数、配对样本数和各任务分布，避免只显示一个汇总数掩盖弱项。
3. **错误率**：发生至少一次错误的尝试数 / 全部有效尝试数；Crab 不高于 Material。同时报告总错误次数与严重错误，避免多次误操作被单个比例掩盖。
4. **整体偏好**：选择 Crab 的有效参与者数 / 全部完成两方案的参与者数，目标至少 70%；12 人时至少需要 9 人。三个分项偏好分别展示，不取其中最高项代替整体。

这些是项目目标值，不是 Material 或 WCAG 规定。12 人是本轮最低参与规模，不能仅凭达标比例作普遍统计推断。保留个体差异和失败案例；可报告区间估计，但不把小样本的点估计表述成所有中文后台用户的结论。

## 原始记录字段

每个尝试记录：匿名参与者、方案、候选版本、对象集合、设备条件、方案顺序、任务顺序、开始和结束时间、成功与否、错误次数、是否求助、是否技术中止、中止原因、观察证据路径。每人应有 8 条尝试及 1 条偏好记录。

原始数据与计算结果分文件保留。数据缺失时标明原因，不能填入推测时间、模拟用户或模型评分。报告包含两方案截图、任务脚本、版本、样本说明、指标、失败个案和改进决定。

## 完成判定

至少 12 名合格参与者完成顺序平衡测试；数据可追溯；独立完成率、配对时间、错误率、整体偏好同时达到目标；两轮完整工程和生产复审使用同一候选，确认的问题清零。未满足任一项时分别报告结果，不能简写为“已超过 Material”。
